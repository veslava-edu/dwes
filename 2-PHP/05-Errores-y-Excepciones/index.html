    Gestión de Errores y Excepciones en PHP

    La gestión de errores es un pilar fundamental en la construcción de aplicaciones PHP robustas. PHP tradicionalmente ha manejado los Errores (fallos del sistema) y las Excepciones (fallos de la lógica de la aplicación) de diferentes maneras. La gestión moderna se centra en el bloque try-catch y en la jerarquía de excepciones.

    1. Fundamentos de la Gestión de Errores Tradicional

    Antes del manejo moderno de excepciones, PHP confiaba en niveles de error para clasificar y reportar problemas de tiempo de ejecución y sintaxis.

    Niveles de Error Tradicionales

    Se definen mediante constantes de PHP para indicar la severidad del fallo.

    Constante Descripción Impacto
    E_ERROR Errores fatales de tiempo de ejecución. Detiene la ejecución del script inmediatamente.
    E_WARNING Advertencias. Errores no fatales. El script continúa su ejecución, pero algo está mal.
    E_NOTICE Avisos. Sugieren problemas, como usar una variable no definida. El script continúa, útil para depuración.
    E_PARSE Errores sintácticos de compilación (ej: falta un ;). Detiene la ejecución del script.
    E_ALL Todos los errores y advertencias (valor recomendado en desarrollo). -

    Directivas de Configuración Clave

    Estas directivas, establecidas en el archivo php.ini o mediante funciones, controlan cómo se reportan y muestran los errores:

    • error_reporting(nivel): Define qué tipos de errores deben ser reportados (ej: error_reporting(E_ALL);).
    • display_errors: Controla si los errores se muestran en la salida HTTP.
      • Off en producción (obligatorio por seguridad).
      • On solo en desarrollo.
    • log_errors y error_log: Determinan si los errores se guardan en un archivo de registro (log) y la ruta de ese archivo.

    2. Manejo Moderno: Excepciones (try-catch)

    El manejo de excepciones es el método preferido para gestionar errores previsibles o controlables dentro de la lógica del código, permitiendo una recuperación elegante o una terminación controlada del programa.

    El Bloque try-catch-finally

    Palabra Clave Función
    try Contiene el código que potencialmente puede lanzar una excepción.
    throw Se usa para crear y lanzar un objeto Exception cuando se detecta un error.
    catch Captura la excepción lanzada y ejecuta el código de manejo de errores.
    finally (Opcional) Contiene código que se ejecuta siempre, sin importar si se lanzó o capturó una excepción. 
    function dividir(int $a, int $b): float
{
    if ($b === 0) {
        // Al detectar el error, se lanza el objeto Exception
        throw new Exception("Error: El divisor no puede ser cero.");
    }
    return $a / $b;
}

try {
    echo "Intentando dividir 10 entre 0...\n";
    $resultado = dividir(10, 0);
    echo "Resultado: " . $resultado . "\n";
} catch (Exception $e) {
    // Se captura la excepción (como objeto $e) y se maneja el error
    echo "¡Excepción capturada!\n";
    echo "Mensaje de error: " . $e->getMessage() . "\n";
} finally {
    // Se ejecuta siempre al terminar el bloque try o catch
    echo "Proceso de división finalizado.\n";
}

    3. El Objeto Base: Exception

    El objeto Exception (que implementa la interfaz Throwable en PHP 7+) es la clase base para la mayoría de los errores lógicos controlables.

    Constructor

    Al crear una excepción, se recomienda proporcionar la mayor cantidad de información posible:

    __construct(
    string $message = "", 
    int $code = 0, 
    Throwable $previous = null
)

    Propiedades (Solo lectura)

    Los valores internos de una excepción no pueden modificarse una vez creados, y se acceden mediante métodos getter:

    1. $message: El mensaje de error (definido por el desarrollador).
    2. $code: Un código de error numérico (definido por el desarrollador para clasificación interna).
    3. $file: El archivo donde se lanzó la excepción.
    4. $line: La línea exacta dentro de ese archivo.
    5. $trace: La pila de llamadas (stack trace).

    Métodos Getters

    Estos son los métodos utilizados para obtener información detallada sobre el fallo, como se ve en el catch del ejemplo anterior ($e->getMessage()):

    Método Retorno Descripción
    getMessage() string Devuelve el mensaje de error de la excepción.
    getCode() int Devuelve el código de error numérico.
    getFile() string Devuelve el nombre del archivo donde ocurrió.
    getLine() int Devuelve el número de línea donde ocurrió.
    getTraceAsString() string Devuelve la pila de llamadas (stack trace) como una cadena formateada legible.
    getPrevious() Throwable Devuelve la excepción anterior (si se usa encadenamiento).

    4. Jerarquía y Excepciones Predefinidas

    Es una buena práctica lanzar una excepción específica en lugar de la genérica Exception, lo que permite a los bloques catch ser más precisos.

    Excepciones de la Librería Estándar (SPL)

    La Standard PHP Library (SPL) proporciona una jerarquía base para la aplicación:

    Clase Base Tipo de Error Ejemplos Comunes
    LogicException Fallos en la lógica de la aplicación (errores de programación que deberían evitarse). InvalidArgumentException, BadMethodCallException, DomainException.
    RuntimeException Fallos que ocurren en el tiempo de ejecución (a menudo debido a factores externos o inesperados). OutOfBoundsException, OverflowException, UnexpectedValueException.

    Excepciones Específicas de Extensiones

    Muchas extensiones de PHP tienen sus propias excepciones que descienden de Exception:

    Clase Descripción Uso
    PDOException Excepción de la extensión PDO (para Base de Datos). Fallos de conexión, errores de sintaxis en consultas SQL, violaciones de clave única.
    JsonException Excepción para errores al codificar o decodificar JSON. Permite manejar un JSON inválido de manera controlada.

    Ejemplo de Captura Selectiva

    Al usar excepciones específicas, se pueden crear manejadores de error que reaccionen de manera diferente al tipo de fallo:

    try {
    // 1. Podría fallar debido a un mal argumento.
    procesar_datos_usuario('abc'); 

    // 2. Podría fallar al interactuar con la DB.
    $db->query("SELECT * FROM tabla_inexistente"); 

} 
catch (InvalidArgumentException $e) {
    // Manejar específicamente un mal dato de entrada
    http_response_code(400); // Bad Request
    echo "Error de validación: Por favor, revise sus datos.";
} 
catch (PDOException $e) {
    // Manejar específicamente un fallo de base de datos
    http_response_code(500); // Internal Server Error
    error_log("Fallo de DB: " . $e->getMessage());
    echo "Error interno: El servicio de base de datos no está disponible.";
} 
catch (Exception $e) {
    // Capturar cualquier otra excepción genérica o no prevista
    http_response_code(500); 
    echo "Ha ocurrido un error inesperado.";
}

    5. Ejercicio Práctico: Calculadora Segura

    El ejercicio se centra en el uso del bloque try-catch y InvalidArgumentException para validar la entrada del usuario.

    Código del Ejercicio

    <?php

/**
 * Realiza una división validando que el divisor no sea cero.
 * 
 * @param float $dividendo El número a dividir.
 * @param float $divisor El número por el que se divide.
 * @return float El resultado de la división.
 * @throws InvalidArgumentException Si el divisor es cero.
 */
function dividirNumeros(float $dividendo, float $divisor): float
{
    // Usamos una excepción específica para indicar un argumento inválido
    if ($divisor === 0.0) {
        throw new InvalidArgumentException("El divisor (el segundo argumento) no puede ser cero.");
    }

    return $dividendo / $divisor;
}

echo "--- CASO 1: Ejecución correcta ---\n";
try {
    $resultado = dividirNumeros(10, 2);
    echo "Resultado de 10/2: " . $resultado . "\n";
} catch (InvalidArgumentException $e) {
    echo "Error: " . $e->getMessage() . "\n";
}

echo "\n--- CASO 2: Error controlado (División por Cero) ---\n";
try {
    $resultado_fallo = dividirNumeros(10, 0);
    echo "Resultado de 10/0: " . $resultado_fallo . "\n";
} catch (InvalidArgumentException $e) {
    // Se captura la excepción específica y se ofrece un manejo de error amigable.
    echo "ERROR CONTROLADO: " . $e->getMessage() . "\n";
    echo "El error ocurrió en el archivo " . $e->getFile() . " en la línea " . $e->getLine() . "\n";
} finally {
    echo "-> La operación de división ha concluido.\n";
}

?>
