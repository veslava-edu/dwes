    UML a PHP - Conversión

    Asociación, composición y agregación

    La asociación es una relación entre dos clases separadas que se establece a través de sus Objetos. La asociación puede ser de uno a uno, de uno a muchos, de muchos a uno, de muchos a muchos. En la programación orientada a objetos, un objeto se comunica con otro objeto para usar la funcionalidad y los servicios proporcionados por ese objeto. La composición y la agregación son las dos formas de asociación.

    La diferencia entre la composición y la agregación es que la primera representa una relación tipo es parte de mientras que la segunda tiene una relación tiene un.

    Por ejemplo, la relación entre Humano y Corazon es una composición porque el Corazon no puede existir sin el Humano. Sin embargo, la relación entre Motor y Coche es agregación porque el Motor sigue existiendo independientemente del Coche.

    La composición es una Asociación fuerte mientras que la agregación es débil.

    Relaciones 1:1

    En el caso de las relaciones unívocas, crearemos una propiedad en la clase principal que almacene una referencia (un objeto) de la clase secundaria.

    Por ejemplo:

    erDiagram
    PLANETA ||..|| ORBITA : orbita

    En este caso, la entidad principal es PLANETA, ya que ORBITA depende de que el planeta exista. Para modelar esto en PHP, crearemos dos clases.

    La clase Orbita es una entidad simple. Usando promoción de propiedades de constructor de PHP 8, podemos definirla de forma muy concisa:

    <?php
// Orbita.php

class Orbita
{
    // PHP 8+ constructor property promotion
    public function __construct(
        private string $nombre,
        private int $radio
    ) {}

    // Getters para acceder a las propiedades privadas
    public function getNombre(): string
    {
        return $this->nombre;
    }

    public function getRadio(): int
    {
        return $this->radio;
    }
}

    La clase Planeta contendrá una propiedad que debe ser un objeto de tipo Orbita. Usamos type-hinting para garantizarlo.

    <?php
// Planeta.php

class Planeta
{
    private string $nombre;
    // La propiedad $orbita debe ser un objeto de la clase Orbita
    private Orbita $orbita;

    public function __construct(string $nombre, Orbita $orbita)
    {
        $this->nombre = $nombre;
        $this->orbita = $orbita;
    }

    // Getters y Setters
    public function getNombre(): string
    {
        return $this->nombre;
    }

    public function getOrbita(): Orbita
    {
        return $this->orbita;
    }
}

    Relaciones 1:N

    En este caso, la clase en el lado "1" de la relación tendrá una colección (un array) de objetos del lado "N". La clase en el lado "N" tendrá una única referencia a un objeto del lado "1".

    Por ejemplo:

    erDiagram
    EDITORIAL ||..|{ LIBRO : edita

    La clase Libro (lado "N") tiene una única Editorial. La clase Editorial (lado "1") tiene muchos Libro.

    Primero, definimos la clase Libro. Esta contendrá una referencia a su Editorial.

    <?php
// Libro.php

class Libro
{
    public function __construct(
        private string $titulo,
        // Cada libro pertenece a UNA editorial
        private Editorial $editorial
    ) {}

    public function getTitulo(): string
    {
        return $this->titulo;
    }

    public function getEditorial(): Editorial
    {
        return $this->editorial;
    }
}

    Ahora, la clase Editorial. Contendrá un array para almacenar todos sus libros.

    <?php
// Editorial.php

class Editorial
{
    /** 
     * @var Libro[] 
     * La anotación @var ayuda a los IDEs y herramientas de análisis
     * a entender que este array contiene objetos de tipo Libro.
     */
    private array $libros = []; // Inicializamos como array vacío

    public function __construct(private string $nombre)
    {
        // El array de libros se inicializa vacío por defecto
    }

    public function getNombre(): string
    {
        return $this->nombre;
    }

    /**
     * Añade un libro al catálogo de la editorial.
     * El type-hint 'Libro' asegura que solo objetos Libro puedan ser añadidos.
     */
    public function addLibro(Libro $libro): void
    {
        $this->libros[] = $libro;
    }

    /**
     * Devuelve la lista completa de libros de la editorial.
     * El tipo de retorno 'array' indica que devolverá una colección.
     * @return Libro[]
     */
    public function getLibros(): array
    {
        return $this->libros;
    }
}

    Es fundamental inicializar la propiedad $libros como un array vacío (= []). Si no lo hacemos, al intentar añadir el primer libro con $this->libros[] = $libro, PHP generaría un error porque se intentaría operar sobre una propiedad no inicializada.

    Relaciones N:M sin atributos

    Para una relación "muchos a muchos", cada clase contendrá una propiedad que es un array de objetos de la otra clase.

    erDiagram
    LIBRO |{..|{ AUTOR : escribe
    Un Libro puede tener varios Autor, y un Autor puede tener varios Libro. Ambas clases necesitarán un array para gestionar la relación.

    <?php
// Autor.php

class Autor 
{
    /** @var Libro[] */
    private array $libros = [];

    public function __construct(private string $nombre) {}

    public function getNombre(): string
    {
        return $this->nombre;
    }

    public function addLibro(Libro $libro): void
    {
        $this->libros[] = $libro;
    }

    /** @return Libro[] */
    public function getLibros(): array
    {
        return $this->libros;
    }
}

    <?php
// Libro.php

class Libro 
{
    /** @var Autor[] */
    private array $autores = [];

    public function __construct(private string $titulo) {}

    public function getTitulo(): string
    {
        return $this->titulo;
    }

    public function addAutor(Autor $autor): void
    {
        $this->autores[] = $autor;
    }

    /** @return Autor[] */
    public function getAutores(): array
    {
        return $this->autores;
    }
}

    Relaciones N:M con atributos

    Cuando la propia relación tiene atributos (por ejemplo, la fecha de publicación de un libro por un autor), es necesario crear una tercera clase que modele esta relación. Esta clase se conoce como "clase de asociación" o "entidad pivote".

    erDiagram
    LIBRO ||--o{ PUBLICACION : es-publicado-en
    AUTOR ||--o{ PUBLICACION : publica-en
    PUBLICACION {
        DateTime fecha
    }

    Aquí, la clase PUBLICACION conecta LIBRO y AUTOR y contiene la fecha.

    Primero, la clase de asociación Publicacion:

    <?php
// Publicacion.php

use \DateTimeImmutable;

class Publicacion
{
    // Esta clase une un Autor con un Libro en una fecha específica
    public function __construct(
        private Autor $autor,
        private Libro $libro,
        private DateTimeImmutable $fecha
    ) {}

    public function getAutor(): Autor 
    {
        return $this->autor;
    }

    public function getLibro(): Libro
    {
        return $this->libro;
    }

    public function getFecha(): DateTimeImmutable
    {
        return $this->fecha;
    }
}

    Ahora, las clases Libro y Autor no se referenciarán directamente, sino a través de la clase Publicacion. Cada una tendrá un array de objetos Publicacion.

    <?php
// Libro.php

class Libro
{
    /** @var Publicacion[] */
    private array $publicaciones = [];

    public function __construct(private string $titulo) {}

    public function addPublicacion(Publicacion $publicacion): void
    {
        $this->publicaciones[] = $publicacion;
    }

    /** @return Publicacion[] */
    public function getPublicaciones(): array
    {
        return $this->publicaciones;
    }
}


    <?php
// Autor.php

class Autor
{
    /** @var Publicacion[] */
    private array $publicaciones = [];

    public function __construct(private string $nombre) {}

    public function addPublicacion(Publicacion $publicacion): void
    {
        $this->publicaciones[] = $publicacion;
    }

    /** @return Publicacion[] */
    public function getPublicaciones(): array
    {
        return $this->publicaciones;
    }
}
    Este diseño es mucho más potente, ya que desde un objeto Autor, podemos recorrer sus publicaciones para saber no solo qué libros ha escrito, sino también cuándo se publicó cada uno.
