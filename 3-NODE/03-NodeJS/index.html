    Node.js

    Node.js Environment

    Browser vs Node.js

    Aunque el lenguaje base es el mismo, el ecosistema es opuesto. En el navegador (Cliente), tu código vive en una "pecera" (sandbox) por seguridad. En Node.js (Servidor), tu código tiene llaves maestras del sistema. En el Navegador, tu preocupación principal es la interfaz de usuario, el DOM y la compatibilidad visual. En Node.js, tu prioridad es el sistema operativo, la red y el acceso a datos.

    Explicación Técnica

    En el navegador, interactúas con window y el DOM. En Node, no existen. A cambio, Node te da acceso a global y módulos nativos para manipular el Sistema Operativo (OS). Además, en el navegador dependes de la versión que el usuario tenga instalada (Chrome, Firefox, Safari); en Node.js, tú decides la versión exacta del motor (ej. Node 22 LTS), lo que garantiza estabilidad.

    Tablas Comparativas

    Característica Navegador (Browser) Node.js (Servidor)
    Acceso al Sistema Restringido (Sandbox). No puede leer tus archivos locales por seguridad. Total. Puede leer, escribir y borrar archivos del SO (fs).
    Objeto Global window / document global / process. No existe el DOM.
    Fragmentación Debes soportar Chrome, Firefox, Safari (Babel/Polyfills). Tú controlas la versión exacta de Node.js donde corre tu código.
    Módulos ES Modules (reciente) o Bundlers (Webpack/Vite). CommonJS (histórico) y ES Modules (moderno).
    Concepto Frontend (Cliente) Backend (Node.js)
    Prioridad Interactividad y renderizado Procesamiento de datos y I/O
    Motor V8, SpiderMonkey, JavaScriptCore V8 (principalmente)
    Event Loop Gestiona UI y clicks Gestiona I/O, Red y DB

    Ejemplos de Código

    Ejemplo 1: Intentar acceder al DOM en Node (Error) 

    // browser-check.ts
/* 
   ❌ Esto lanzará un error ReferenceError en Node.js 
   porque 'window' y 'document' no existen.
*/
try {
  console.log(window.location.href);
} catch (error: any) {
  console.error('Error: Estamos en el servidor, no hay ventana.');
}

    Ejemplo 2: Detectar el entorno de ejecución 

    // environment-detect.ts
// ✅ Verificamos dónde estamos corriendo
const isNode = typeof process !== 'undefined' && 
               process.versions != null && 
               process.versions.node != null;

if (isNode) {
  console.log(`Ejecutando en Node.js versión: ${process.version}`);
} else {
  console.log('Ejecutando en el navegador');
}

    Ejemplo 3: Uso de APIs exclusivas de Node 

    // server-capability.ts
import { freemem } from 'os';

// ✅ Acceso a hardware (imposible en browser puro)
const memory = freemem() / 1024 / 1024;
console.log(`Memoria libre en el servidor: ${memory.toFixed(2)} MB`);

    APIs Disponibles Navegador Node.js
    DOM (HTML) ✅ Sí ❌ No
    File System (fs) ❌ No ✅ Sí
    Fetch API ✅ Sí ✅ Sí (desde Node 18+)

    Consejo Profesional

    Nunca asumas que una librería de NPM funcionará en ambos lados. Si usa window, fallará en Node. Si usa fs, fallará en el navegador (a menos que uses empaquetadores complejos).

    Preguntas Reflexivas

    1. ¿Por qué es un riesgo de seguridad que el navegador tuviera las mismas capacidades de acceso al disco duro que Node.js?
    2. Si Node.js usa el mismo motor V8 que Chrome, ¿por qué el rendimiento puede variar entre ambos al ejecutar el mismo algoritmo matemático?
    3. ¿Qué implicaciones tiene para el desarrollador poder "fijar" la versión de Node.js en producción a diferencia del navegador del usuario?


    El REPL de Node.js (terminal interactiva)

    El REPL (Read-Eval-Print-Loop) es la consola de comandos de Node. Es ideal para probar lógica rápida sin crear archivos.

    Explicación Técnica

    Al escribir node en tu terminal sin argumentos, entras en este modo. Lee tu entrada, la evalúa en JavaScript, imprime el resultado y vuelve a esperar (Loop). Es muy útil para verificar sintaxis o comportamientos de librerías.

    Consejo Pro: REPL con TypeScript

    Node.js no entiende TS directamente en el REPL. Para probar código TypeScript interactivo, usa la herramienta ts-node. Ejecuta: npx ts-node.

    Tablas Comparativas

    Comando REPL Acción Equivalente en GUI
    .break Salir de expresión multilínea Escapar / Cancelar
    .editor Entrar en modo edición Abrir un archivo temporal
    .exit Cerrar el REPL Cerrar ventana
    .save [file] Guardar sesión actual Guardar como...
    Característica Script de Archivo (node file.js) REPL (node)
    Persistencia Permanente Volátil (se pierde al cerrar)
    Uso principal Aplicaciones completas Pruebas, debug rápido, cálculos
    Variables Ámbito del módulo Ámbito "global" de la sesión

    Ejemplos de Código (Sesión simulada)

    Ejemplo 1: Operaciones básicas y variables 

    // En terminal: npx ts-node

    Ojo con TypeScript en REPL

    El comando node espera JavaScript. Si queréis probar código TypeScript directamente en la terminal (con tipos), debéis usar la herramienta ts-node (ejecutando npx ts-node).

    Tablas Comparativas

    Comando REPL Acción
    .help Muestra la lista de comandos disponibles.
    .editor Entra en modo editor para escribir funciones multilínea.
    .break Cancela la entrada actual.

    Objectos Globales

    En Node.js, window no existe. El objeto raíz es global.

    Explicación Técnica

    Los objetos globales están disponibles en todos los módulos sin necesidad de import. Incluyen temporizadores (setTimeout), consola (console) y acceso al proceso (process). Existe una distinción importante: variables "verdaderamente globales" (en global) y variables "pseudo-globales" que existen por módulo (como __dirname en CommonJS).

    Cuidado con 'this'

    En el nivel superior de un archivo Node.js (CommonJS), this es module.exports, no el objeto global. En el REPL, this sí es el objeto global. ¡Confuso al principio!

    Variables Globales y "Pseudo-Globales" Importantes

    Variable Tipo Descripción Disponibilidad
    global Objeto El equivalente a window. Contiene métodos como setTimeout, console. Verdaderamente Global
    process Objeto Información sobre el proceso actual (env vars, argumentos). Verdaderamente Global
    __dirname String Ruta absoluta al directorio del archivo actual. Solo en CommonJS
    __filename String Ruta absoluta al archivo actual (incluye nombre). Solo en CommonJS
    module Objeto Referencia al módulo actual (usado para exportar). Solo en CommonJS

    Tablas Comparativas

    Objeto Descripción Disponibilidad
    global El objeto raíz (como window). Universal
    process Info del proceso actual (PID, env). Universal
    console Salida estándar y debug. Universal
    __dirname Ruta al directorio actual. Solo CommonJS (No en ESM)
    Método Síncrono/Asíncrono Uso típico
    setTimeout Asíncrono Retrasar ejecución
    setImmediate Asíncrono Ejecutar al final del ciclo actual
    queueMicrotask Asíncrono Ejecutar antes del siguiente ciclo

    Nota sobre TypeScript y ES Modules: Si configuras tu proyecto TypeScript para usar ES Modules modernos (lo recomendado hoy día), __dirname y __filename dejan de existir. Debemos recrearlos.

    Ejemplo 1: El objeto Global y temporizadores

  var miConfiguracion: string;

global.miConfiguracion = "SECRETO_SERVER";
console.log(global.miConfiguracion);

    Ejemplo 4: El objeto process (Global) 

    /**
 * archivo: global-process.ts
 * Descripción: Acceso a variables de entorno y argumentos.
 */

interface Desarrollador {

    Módulos en Node.js

    Crear un módulo

    En el desarrollo profesional, dividir es vencer. No escribimos todo el código en un fichero index.ts de 5000 líneas. Usamos módulos. Un módulo en Node.js es simplemente un archivo JavaScript/TypeScript que encapsula una funcionalidad específica y expone solo lo que quiere que otros vean (Interfaz Pública).

    Es como una cocina de restaurante: - Tu módulo: La estación de postres. - Lo privado: Tus recetas secretas, ingredientes sucios. - Lo público (export): El pastel terminado.

    Tipos de Sistemas de Módulos

    1. CommonJS (CJS): El clásico de Node. Usa require y module.exports. Síncrono.
    2. ES Modules (ESM): El estándar oficial de JavaScript y TypeScript. Usa import y export. Asíncrono y estático.

    Nos enfocaremos en cómo TypeScript maneja esto, priorizando ESM pero entendiendo CJS.


    Exportar e importar (module.exports y require)

    Aunque TypeScript prefiere import/export, en el mundo laboral encontrarás mucho código legado (legacy) o configuraciones específicas que usan CommonJS.

    Importante

    Para que TypeScript compile a CommonJS (y use require por debajo), tu tsconfig.json debe tener "module": "commonjs".

    Tabla Comparativa: CJS vs ESM

    Característica CommonJS (Legacy Node) ES Modules (Moderno TS/JS)
    Sintaxis Export module.exports = ... export const ... / export default
    Sintaxis Import const x = require('./x') import x from './x'
    Carga Síncrona (bloqueante) Asíncrona
    Uso principal Scripts antiguos, herramientas de build. Frontend moderno, Node.js actual, Deno.

    Diagrama de Carga de Módulos

    graph LR
    A[main.ts] -- require('./utils') --> B(Busca utils.ts/.js)
    B -- Lee archivo --> C{¿Tiene caché?}
    C -- Sí --> D[Devuelve exports de caché]
    C -- No --> E[Ejecuta código del módulo]
    E --> F[Guarda en caché]
    F --> G[Devuelve module.exports]

    Ejemplos de Código (Estilo CommonJS en TS)

    Ejemplo 1: Exportando (math.ts) 

    // math.ts
const PI = 3.1416; // Privado

function sumar(a: number, b: number): number {
    return a + b;
}

function restar(a: number, b: number): number {
    return a - b;
}

// Sintaxis CommonJS clásica
module.exports = {
    sumar,
    restar
    // PI no se exporta, es privada
};

    Ejemplo 2: Importando con require (app.ts) 

    // app.ts
// TypeScript nos permite usar require si declaramos los tipos o usamos una sintaxis especial:
// import x = require('./x') es la forma "TypeScript-ish" de hacerlo para CJS.
import operaciones = require('./math');

const resultado = operaciones.sumar(5, 10);
console.log(`Resultado: ${resultado}`);


**Ejemplo 3: Módulo privado (encapsulamiento)**
```typescript
// secretaria.ts
const CLAVE_SECRETA = "123456"; // Variable privada, no se exporta

// Solo exportamos la función que usa la clave internamente
export function validar(pass: string): boolean {
    return pass === CLAVE_SECRETA;
}

    Ejemplo 4: Módulo de utilidades 

    // mates.ts
export function cuadrado(x: number): number {
    return x * x;
}

    Ejemplo 5: Consumiendo el módulo 

    // app.ts
import { cuadrado } from './mates.js'; // Nota la extensión .js en imports ESM

    Exportar e importar (module.exports y require)

    Este es el sistema clásico (CommonJS o CJS). Es vital conocerlo porque mucho código "legacy" y herramientas de configuración aún lo usan.

    Importante: CommonJS

    CommonJS es síncrono. Cuando haces require(), el programa se detiene hasta que el archivo se carga y lee.

    Explicación Técnica

    CommonJS es síncrono. Usa module.exports para exponer objetos o funciones y require() para cargarlos. TypeScript puede compilar a este formato si configuramos "module": "commonjs".

    Tablas Comparativas

    Acción CommonJS (CJS) ES Modules (ESM)
    Exportar module.exports = ... export ...
    Importar const x = require('./x') import x from './x'
    Carga Síncrona (bloqueante) Asíncrona

    Ejemplos de Código (Sintaxis CJS)

    Ejemplo 1: Exportando un objeto (CJS) 

    // calculadora.js (Legacy)
const PI = 3.14;

function area(radio) {
    return PI * radio * radio;
}

module.exports = {
    area,
    PI
};

    Ejemplo 2: Importando con require 

    // app.js (Legacy)
const mates = require('./calculadora');
console.log(mates.area(10));

    Ejemplo 3: TypeScript adaptándose a CJS 

    // legacy-adapter.ts
// TS permite usar sintaxis import para traer CJS
import mates = require('./calculadora'); // Sintaxis especial TS
// O la estándar si "esModuleInterop" es true
import mates from './calculadora';

    Exportar varios elementos

    En ESM tenemos dos formas de exportar: Nombrada (Named) y Por Defecto (Default). La recomendación profesional es usar Exportaciones Nombradas para mantener la consistencia y facilitar el refactoring.

    Buenas Prácticas

    Google Style Guide y la comunidad TS prefieren Named Exports. Hacen que el refactoring sea más fácil y el autocompletado del IDE más preciso. Evita export default si puedes.

    Explicación Técnica

    Existen Named Exports (exportaciones con nombre) y Default Exports.
    * Named: Obliga a usar el mismo nombre al importar. Es más seguro para refactorizar.
    * Default: Se puede renombrar al importar. Solo uno por archivo.

    Tablas Comparativas

    Tipo Sintaxis Export Sintaxis Import Recomendación
    Named export const X = 1 import { X } from ... Alta (Google Style)
    Default export default X import CualquierNombre from ... Baja (Confuso)

    Ejemplos de Código

    Ejemplo 1: Named Exports (Recomendado) 

    // usuarios.ts
export interface User { id: number; name: string; }
export const MAX_USERS = 100;
export function crearUsuario() { /* ... */ }

    Ejemplo 2: Default Export 

    // logger.ts
export default class Logger {
    log(msg: string) { console.log(msg); }
}

    Ejemplo 3: Importando ambos tipos 

    // main.ts
import Logger from './logger.js'; // Default (sin llaves)
import { MAX_USERS, type User } from './usuarios.js'; // Named (con llaves)

const log = new Logger();
log.log(`Límite: ${MAX_USERS}`);

    Sintaxis de desestructuración y require

    Volviendo un momento a CommonJS (o al interoperar con librerías antiguas). Cuando hacemos require('modulo'), obtenemos un objeto gigante. A menudo solo queremos una pieza. Aquí entra la Desestructuración (Destructuring) de JavaScript.

    Es como pedir una pizza entera pero solo poner en tu plato una porción de pepperoni.

    La desestructuración (Destructuring) permite extraer propiedades de un objeto y asignarlas a variables en una sola línea. Es fundamental para mantener el código limpio y importar solo lo necesario.

    Tablas Comparativas

    Método Código Clásico Código con Desestructuración
    Acceso const fs = require('fs'); fs.readFile(...) const { readFile } = require('fs');
    Ventaja Espacio de nombres claro Menos verbosidad, código más directo
    Riesgo Ninguno Posible colisión de nombres de variables

    Diagrama de Secuencia: Desestructuración

    sequenceDiagram
    participant Main as "Archivo Principal"
    participant Modulo as "Módulo 'fs'"

    Note over Main, Modulo: Sin Desestructuración
    Main->>Modulo: const fs = require('fs')
    Modulo-->>Main: Devuelve objeto { readFile, writeFile, ... }
    Main->>Main: Uso: fs.readFile()

    Note over Main, Modulo: Con Desestructuración
    Main->>Modulo: const { readFile } = require('fs')
    Modulo-->>Main: Devuelve objeto completo
    Main->>Main: Extrae SOLO 'readFile'
    Main->>Main: Uso: readFile()

    Ejemplos de Código

    Ejemplo 1: Desestructuración con require 

    // legacy.js
// Importamos TODO el objeto
const path = require('path');
// Extraemos solo lo que queremos
const { join, resolve } = require('path');

console.log(join('a', 'b')); // Uso directo

    // modern.ts

    El módulo console

    Mucho más que console.log. Es tu herramienta principal de depuración y salida estándar. Es una herramienta de depuración poderosa conectada a stdout (salida estándar) y stderr (salida de error).

    Explicación Técnica

    Escribe en stdout (salida estándar) y stderr (salida de error). Es bloqueante en algunos sistemas (Windows) y asíncrono en otros, pero para propósitos generales lo tratamos como síncrono.

    Métodos Avanzados

    Método Uso Ejemplo
    console.log Salida estándar (stdout). Info general.
    console.error Salida de error (stderr). Errores críticos.
    console.table Muestra arrays/objetos como tabla. Listados de datos.
    console.time / timeEnd Mide el tiempo de ejecución. Performance testing.
    console.trace Muestra la pila de llamadas (stack trace). ¿Quién llamó a esta función?

    Ejemplos de Código

    Ejemplo 1: Tablas para datos estructurados 

    const alumnos = [
    { id: 1, nombre: 'Luis', nota: 8 },
    { id: 2, nombre: 'Marta', nota: 9.5 }
];
// Muestra una tabla ASCII preciosa en la terminal
console.table(alumnos);

    Ejemplo 2: Benchmarking simple 

    console.time('Bucle');
for(let i=0; i<1000000; i++) { /* work */ }
console.timeEnd('Bucle'); 
// Output: Bucle: 2.453ms

    Ejemplo 3: Trace (Pila de llamadas) 

    function critica() {
    // Me dice quién llamó a esta función y toda la ruta
    console.trace('¿Quién me llamó?');
}
critica();

    Ejemplo 4: Niveles de Log 

    console.log("Info normal");         // stdout
console.error("Error crítico");     // stderr (útil para logs de errores)
console.warn("Advertencia");        // stderr
console.trace("¿Quién me llamó?");  // Imprime la pila de llamadas


    El módulo process

    process es el puente entre tu código y el proceso del sistema operativo que lo está ejecutando. Es fundamental para la configuración de entornos (Dev vs Prod).

    Funcionalidades Clave

    • Variables de Entorno (process.env): Para guardar contraseñas, claves API y puertos sin escribirlos en el código ("hardcode").
    • Argumentos (process.argv): Leer inputs desde la línea de comandos.
    • Salida (process.exit): Terminar el programa (0 = éxito, 1 = error).

    Explicación Técnica

    No necesita import. Provee acceso a las variables de entorno (.env), argumentos de línea de comandos (argv) y control del ciclo de vida (salir del programa).

    Tablas Comparativas

    Propiedad/Método Descripción Ejemplo de uso
    process.env Variables de entorno Leer contraseñas de BD, Puertos
    process.argv Argumentos de ejecución node app.js --modo=dev
    process.exit(code) Terminar programa exit(0) (ok), exit(1) (error)
    process.cwd() Directorio actual Saber desde dónde se lanzó el comando

    Ejemplos de Código

    Ejemplo 1: Variables de Entorno (Seguridad) 

    // config.ts
// Ejecutar como: PORT=3000 node dist/config.js
const puerto = process.env.PORT || 8080;
const dbUser = process.env.DB_USER;

if (!dbUser) {
    console.error('Fatal: DB_USER no definido');
    process.exit(1); // Salida con error
}
console.log(`Servidor en puerto ${puerto}`);

    Ejemplo 2: Argumentos CLI 

    // args.ts
// Ejecutar: node dist/args.js --borrar-todo
const args = process.argv; 
// argv[0] es el binario de node
// argv[1] es el archivo ejecutado
// argv[2...] son tus argumentos

if (args.includes('--borrar-todo')) {
    console.warn('⚠️  Borrando base de datos...');
}

    Ejemplo 3: Uso de memoria 

    const uso = process.memoryUsage();
console.log(`Uso de RAM: ${(uso.heapUsed / 1024 / 1024).toFixed(2)} MB`);


    El módulo os

    Te da información sobre el hardware y el sistema operativo. Muy útil si estás creando herramientas de monitoreo o balanceadores de carga.

    Explicación Técnica

    Útil para diagnósticos, balanceo de carga (saber cuántas CPUs tenemos para lanzar hilos) y obtener rutas específicas del usuario.

    Tablas Comparativas

    Método Retorno Utilidad
    os.cpus() Array de núcleos Clustering (aprovechar multicore)
    os.freemem() Bytes libres Monitorización de salud del server
    os.homedir() Ruta string Guardar configs en carpeta de usuario
    os.platform() 'win32', 'linux' Lógica específica por SO

    Ejemplos de Código

    Ejemplo 1: Información básica 

    import * as os from 'os';

    import { networkInterfaces } from 'os';

    El módulo path

    Manipulación de rutas de archivos segura y multiplataforma. En Windows las rutas usan backslash \ (ej: C:\Users\Pepe). En Linux/Mac usan slash / (ej: /home/pepe). Si escribes las rutas a mano ("carpeta/archivo.txt"), tu aplicación se romperá cuando cambies de sistema operativo.

    path resuelve esto normalizando las rutas automáticamente.

    Explicación Técnica

    Problema: Windows usa \ y Linux/Mac usan / para separar carpetas. Si escribes strings manuales ("carpeta/archivo"), fallará en Windows. Solución: path normaliza esto automáticamente.

    Regla de Oro

    Nunca concatenes rutas con + (ej: dir + '/' + file). Usa siempre path.join().

    Tablas Comparativas

    Método Descripción Ejemplo
    path.join() Une segmentos a/b (Linux), a\b (Win)
    path.resolve() Ruta absoluta /home/user/proyecto/a
    path.extname() Extensión .jpg
    path.parse() Desglosa ruta { root, dir, base, ext, name }

    Ejemplos de Código

    Ejemplo 1: Unir rutas (Cross-platform) 

    import path from 'path';

// Nunca hagas esto: const ruta = 'uploads' + '/' + 'foto.jpg';
// Haz esto:
const rutaSegura = path.join('uploads', '2024', 'foto.jpg');
console.log(rutaSegura); 
// Win: uploads\2024\foto.jpg
// Linux: uploads/2024/foto.jpg

    Ejemplo 2: Obtener rutas absolutas 

    import path from 'path';

// Resuelve desde la raíz del disco
const absoluta = path.resolve('dist', 'index.js');
console.log(absoluta);
// /Users/usuario/proyectos/mi-api/dist/index.js

    Ejemplo 3: Analizar nombres de archivo 

    import path from 'path';

const archivo = '/var/www/index.html';
console.log(path.extname(archivo)); // .html
console.log(path.basename(archivo)); // index.html
console.log(path.basename(archivo, '.html')); // index

    Ejemplo 4: Extrayendo información de un archivo 

    import { parse, format } from 'path';

const ruta = '/home/usuario/documentos/reporte.pdf';

const info = parse(ruta);

console.table(info);

│   ext    │           '.pdf'            │
│   name   │          'reporte'          │
