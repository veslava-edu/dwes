    Introducción a Node.js

    🚀 Introducción: El Camarero Ninja

    Imagina un restaurante tradicional muy concurrido. En el modelo clásico (como Apache/PHP antiguo), cada vez que entra un cliente, el restaurante contrata a un camarero exclusivo para esa mesa. El camarero toma la nota, va a la cocina y se queda esperando de pie mirando al cocinero hasta que el plato está listo. Si el cocinero tarda 20 minutos, ese camarero está 20 minutos inactivo. Si llegan 500 clientes, necesitas 500 camareros. El restaurante colapsa por falta de espacio (memoria RAM).

    Node.js cambia las reglas del juego. Es un restaurante con un solo camarero. ¿Cómo? Porque es un Camarero Ninja. Toma la nota de la Mesa 1, la deja en cocina, y mientras se cocina, corre a atender a la Mesa 2, luego a la Mesa 3... No espera a nadie. Cuando la cocina (Base de Datos o Sistema de Archivos) termina un plato, toca un timbre (Evento), y el Camarero Ninja vuelve, recoge el plato y lo sirve.

    Resultado: Un solo camarero gestiona miles de clientes simultáneamente, siempre que los pedidos sean rápidos de anotar. Esto es Node.js: eficiencia máxima basada en eventos.

    🧠 Conceptos Fundamentales

    Antes de picar código, definamos el vocabulario que usarás en las entrevistas de trabajo.

    Definición: Runtime (Entorno de Ejecución)

    Node.js NO es un lenguaje de programación ni un framework. Es un entorno de ejecución (Runtime Environment) que permite correr código JavaScript fuera del navegador (servidores, robots, IoT).

    Definición: V8 Engine

    Es el motor de JavaScript de código abierto creado por Google para Chrome. Node.js lo usa para traducir tu código JS/TS a código máquina a velocidad de vértigo.

    Definición: Non-blocking I/O (E/S No Bloqueante)

    Es la capacidad de solicitar una operación lenta (leer disco, petición a API) y continuar ejecutando el resto del código sin esperar a que la primera termine.


    1. ¿Qué es Node.js?

    Node.js nació en 2009 cuando Ryan Dahl presentó una idea revolucionaria: sacar JavaScript del navegador. Su obsesión era crear servidores que pudieran manejar miles de conexiones concurrentes sin bloquearse, algo que en aquella época era una pesadilla con los servidores tradicionales.

    Hoy, Node.js es el estándar de facto para el desarrollo web moderno, permitiendo el Isomorphic JavaScript: usar el mismo lenguaje en el cliente (Frontend) y en el servidor (Backend).

    Características Principales

    1. Single-threaded (Monohilo): Ejecuta el código JavaScript en un solo hilo principal. No crea un hilo por cada usuario.
    2. Event Driven (Basado en Eventos): Todo es una reacción. "Si pasa X, ejecuta la función Y".
    3. Asíncrono y No Bloqueante: La filosofía central. Nunca detengas el hilo principal.
    4. Motor V8: Desarrollado por Google, compila JS a código máquina nativo a una velocidad vertiginosa. Es de arquitectura ligera. Ideal para operaciones intensivas de I/O (Red/Disco).
    5. Full Stack JS: Permite usar el mismo lenguaje en cliente y servidor, unificando tipos de datos y lógica.

    ¿Por qué usarlo en el desarrollo moderno?

    Característica Servidor Clásico (Ej. Apache/PHP antiguo) Node.js
    Concurrencia Crea un hilo (thread) por cada petición. Consume mucha RAM. Un solo hilo gestiona miles de conexiones concurrentes.
    Bloqueo Si la DB tarda, el hilo se duerme y espera. Si la DB tarda, Node atiende a otro cliente mientras espera.
    Lenguaje PHP/Java/Python en back, JS en front. (Context Switching). TypeScript/JS en todo el stack. (Full Stack real).

    Casos de uso Reales

    Gigantes como Netflix (redujo el tiempo de inicio en un 70%), Uber (gestión masiva de datos en tiempo real), LinkedIn y NASA utilizan Node.js para sistemas críticos.

    2. Arquitectura interna de Node.js

    Muchos desarrolladores usan Node sin saber qué hay bajo el capó. Vosotros no seréis de esos. Entender la arquitectura es lo que separa a un Junior de un Senior.

    Los Motores

    1. V8 (Google): Compila JS a código máquina.
    2. Libuv (C++): Es la biblioteca mágica. Proporciona el Event Loop y el Thread Pool. Es la que permite que Node sea asíncrono y cross-platform (funciona igual en Windows y Linux).

    El Event Loop (El Corazón)

    El Event Loop es un bucle infinito que orquesta todo. Cuando tu código JS termina, el Event Loop comprueba si hay tareas pendientes.

    Fases del Event Loop: 1. Timers: Ejecuta callbacks de setTimeout y setInterval. 2. Pending Callbacks: Errores de sistema I/O. 3. Poll: Recupera nuevos eventos I/O; ejecuta I/O callbacks. Aquí pasa la mayor parte del tiempo. 4. Check: Ejecuta setImmediate. 5. Close Callbacks: Cierre de conexiones (socket.on('close')).

    Call Stack vs Queues (La clave de la entrevista)

    • Call Stack (Pila de llamadas): Donde se ejecuta el código síncrono. LIFO (Last In, First Out).
    • Callback Queue (Macrotasks): setTimeout, I/O. Esperan a que el Call Stack esté vacío.
    • Microtask Queue: Promise.then, process.nextTick. Tienen prioridad VIP. El Event Loop vaciará TODA la cola de microtareas antes de pasar a la siguiente macrotarea.

    Peligro: Bloquear el Event Loop

    Si ejecutas un while(true) o un cálculo matemático de 10 segundos en el hilo principal, NADIE podrá acceder a tu servidor durante ese tiempo. Node.js se detendrá por completo.

    Ejemplos Prácticos (TypeScript)

    Ejemplo 1: Prioridad de Ejecución (Reto Mental)

    console.log('1. Inicio del script');

// Macrotask (Cola normal)
setTimeout(() => {
  console.log('5. Timeout 0ms');
}, 0);

// Microtask (Cola VIP - Promesas)
Promise.resolve().then(() => {
  console.log('3. Promesa resuelta');
});

// Microtask (Cola VIP ++ - Exclusivo Node)
process.nextTick(() => {
  console.log('2. Next Tick');
});

console.log('4. Fin del script');

/**
 * ORDEN REAL DE SALIDA:
 * 1. Inicio del script
 * 4. Fin del script
 * 2. Next Tick (Prioridad máxima tras el stack)
 * 3. Promesa resuelta (Microtask)
 * 5. Timeout 0ms (Macrotask - Event Loop nueva vuelta)
 */

    Ejemplo 2: Uso del Thread Pool (Criptografía) Node delega esto a Libuv, que usa hilos del sistema (generalmente 4 por defecto).

    import { pbkdf2 } from 'crypto';

const start = Date.now();

// Simulamos 4 llamadas pesadas de encriptación
for (let i = 0; i < 4; i++) {
  pbkdf2('password', 'salt', 100000, 512, 'sha512', () => {
    console.log(`Hash ${i + 1} terminado en:`, Date.now() - start, 'ms');
  });
}

// Verás que los 4 terminan casi al mismo tiempo.
// Si Node fuera 100% single-thread puro, tardarían la suma de los tiempos.
// ¡Gracias Libuv!

    3. Instalación y configuración inicial

    Configuración Inicial


    Olvídate de ir a la web de Node.js y descargar el instalador .msi o .pkg. Eso está bien para probar un día, pero profesionalmente es un error. ¿Por qué? Porque los proyectos cambian de versión. Hoy trabajas en Node 18, mañana te asignan un proyecto legacy en Node 14.

    La Solución Profesional: NVM (Node Version Manager)

    Permite tener múltiples versiones instaladas y cambiar entre ellas con un comando.

    • Linux/Mac: nvm
    • Windows: nvm-windows (coreybutler)

    Inicializando un Proyecto

    Todo proyecto Node.js comienza con un package.json. Es el DNI de tu aplicación.

    • Script: Escribir código en un archivo index.js y ejecutar node index.js.

    3.2 Otras utilidades recomendadas (Tooling)

    Para programar como un profesional, necesitas un entorno que te corrija y te ayude.

    ESLint es una herramienta de linting de código para JavaScript. Su objetivo principal es detectar y reportar patrones de código problemáticos o sospechosos en tu código fuente. Te ayuda a mantener un código limpio, legible y consistente en tus proyectos.

    Algunas de las características y beneficios de ESLint son:

    • Detección de errores y problemas: ESLint analiza tu código en busca de errores comunes, como variables no utilizadas, variables no declaradas, uso incorrecto de funciones, entre otros.

    • Consistencia de código: ESLint te permite definir y aplicar reglas de estilo de código personalizadas o utilizar conjuntos de reglas predefinidas (como las de Airbnb, Google, Standard, etc.) para mantener la consistencia en tu código.

    • Integración con herramientas de desarrollo: ESLint se puede integrar con tu editor de código favorito o con tu flujo de trabajo de desarrollo, lo que te permite recibir retroalimentación instantánea sobre problemas de código mientras escribes.

    A continuación, te explico cómo instalar y configurar ESLint en tu proyecto:

    1. Instalación: Puedes instalar ESLint localmente en tu proyecto ejecutando el siguiente comando en la terminal, dentro de la carpeta raíz de tu proyecto: 

      npm install eslint --save-dev

    2. Configuración: Después de la instalación, necesitarás configurar ESLint. Puedes generar un archivo de configuración inicial ejecutando el siguiente comando: 

      npx eslint --init
      Esto abrirá un asistente interactivo que te guiará a través de la configuración. Puedes seleccionar un conjunto de reglas predefinidas o personalizar tus propias reglas.

    3. Uso: Una vez que hayas configurado ESLint, puedes ejecutarlo en tu proyecto utilizando el siguiente comando: 

      npx eslint your-file.js
      Reemplaza your-file.js con la ruta al archivo o carpeta que deseas analizar. ESLint mostrará los problemas encontrados en tu código y te sugerirá cómo solucionarlos.

    4. Integración con editores de código: Para obtener una experiencia de desarrollo más fluida, puedes integrar ESLint con tu editor de código. La mayoría de los editores populares tienen extensiones o complementos disponibles para ESLint. Estas extensiones pueden mostrar los problemas de ESLint directamente en tu editor y proporcionar sugerencias mientras escribes.

    5. Personalización: Puedes personalizar las reglas de ESLint según tus preferencias o necesidades. Puedes editar el archivo de configuración .eslintrc.js o .eslintrc.json generado en el paso 2 para agregar, modificar o desactivar reglas específicas.

    Recuerda que la configuración de ESLint puede variar según tus necesidades y el tipo de proyecto en el que estés trabajando. Puedes consultar la documentación oficial de ESLint para obtener más información sobre las opciones de configuración y las reglas disponibles.

    module.exports = {

    En este ejemplo:

    • La propiedad env establece el entorno en el que se ejecutará el código (navegador, ES2021 y Node.js).
    • La propiedad extends especifica las configuraciones predefinidas que se utilizarán. En este caso, se utiliza eslint:recommended que incluye las reglas recomendadas por ESLint y plugin:prettier/recommended que integra ESLint con Prettier para formatear el código automáticamente.
    • La propiedad parserOptions especifica las opciones del analizador de código. Aquí se establece la versión de ECMAScript (ES2021) y el tipo de módulo (module).
    • La propiedad rules define las reglas personalizadas. En este ejemplo, se establecen dos reglas: no-console que muestra una advertencia si se utiliza console.log en el código y no-unused-vars que muestra un error si se declaran variables no utilizadas.

    Puedes agregar, modificar o desactivar reglas según tus necesidades. Además, puedes consultar la documentación oficial de ESLint para obtener más información sobre las opciones de configuración y las reglas disponibles.

    Prettier es una herramienta de formateo de código que te ayuda a mantener un estilo de código consistente en tus proyectos. Su objetivo principal es eliminar las discusiones sobre la forma en que se debe formatear el código, ya que Prettier aplica automáticamente un estilo de formato consistente en todo el código.

    Uso de Prettier

    1. Instalación: Primero, debes instalar Prettier en tu proyecto. Puedes hacerlo ejecutando el siguiente comando en la terminal:
    npm install --save-dev prettier
    1. Configuración: Prettier se puede configurar utilizando un archivo de configuración .prettierrc en formato JSON o YAML, o mediante la sección "prettier" en el archivo package.json.

    Ejemplo de archivo .prettierrc:

    {
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "printWidth": 80
}

    En este ejemplo, se configuran algunas opciones como el uso de punto y coma, comillas simples, tamaño de tabulación y ancho de línea de 80 caracteres.

    1. Ejecución: Puedes ejecutar Prettier para formatear tu código utilizando el siguiente comando:
    npx prettier --write .

    El argumento --write indica que Prettier debe aplicar los cambios directamente en los archivos.

    Ejemplo de uso de Prettier

    Supongamos que tienes un archivo JavaScript llamado index.js con el siguiente código:

    function add(a, b) {return a+b;}
console.log(add(5,10));

    Después de ejecutar Prettier, el código se formateará automáticamente de la siguiente manera:

    function add(a, b) {
  return a + b;
}

console.log(add(5, 10));

    Prettier ajusta automáticamente la indentación, agrega espacios alrededor de los operadores y coloca correctamente los paréntesis.

    Recuerda que Prettier se puede integrar con ESLint para obtener un formateo de código aún más completo y consistente.

    Integración

    Lo ideal es usar ambos. ESLint busca errores lógicos, Prettier deja el código bonito.

    Ejemplo de Configuración Completa (package.json)

    {
  "name": "curso-daw-node",
  "version": "1.0.0",
  "scripts": {
    "start": "node dist/index.js",
    "dev": "nodemon src/index.ts",
    "lint": "eslint src/**/*.ts",
    "format": "prettier --write ."
  },
  "dependencies": {
    "express": "^4.18.2"
  },
  "devDependencies": {
    "@types/node": "^20.0.0",
    "eslint": "^8.0.0",
    "nodemon": "^3.0.0",
    "prettier": "^3.0.0",
    "ts-node": "^10.9.1",
    "typescript": "^5.0.0"
  }
}
