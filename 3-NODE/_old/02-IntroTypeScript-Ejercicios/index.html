    Tema 2: Ejercicios Prácticos de TypeScript

    🌟 Contexto del Proyecto: "EventHorizon Solutions"

    Bienvenido al equipo de desarrollo backend de EventHorizon Solutions. Nuestra empresa está migrando su antigua plataforma de gestión de eventos (escrita en JavaScript "spaghetti" de 2018) a una arquitectura robusta y escalable basada en Node.js y TypeScript.

    Tu misión como desarrollador es refactorizar módulos críticos, definir los contratos de datos (interfaces) y asegurar que el sistema no falle cuando miles de usuarios intenten comprar entradas simultáneamente. ¡Manos a la obra!

    ## Ejercicios de Consolidación

    1) Configuración del Entorno y "Hola Mundo" Tipado | Nivel: Fácil

    Objetivo

    Configurar un entorno de desarrollo profesional con TypeScript y verificar la transpilación a JavaScript.

    Setup Inicial

    Asegúrate de tener Node.js instalado. Crea una carpeta event-horizon-core e inicializa un proyecto (npm init -y). Instala TypeScript como dependencia de desarrollo.

    Tarea a realizar
    1. Genera el archivo tsconfig.json. Modifícalo para que:
      • El directorio de entrada sea ./src.
      • El directorio de salida sea ./dist.
      • La versión de JS objetivo sea ES2022.
      • El modo strict esté activado (True).
    2. Crea un archivo src/index.ts. Declara una variable llamada welcomeMessage de tipo string explícito con el valor "Sistema EventHorizon Iniciado".
    3. Intenta reasignar esa variable a un número (ej: 101) y observa el error en tu editor. Comenta la línea del error.
    4. Compila el proyecto ejecutando npx tsc.
    5. Ejecuta el archivo generado en dist/index.js con Node.
    Aplicación en el Mundo Real

    Antes de escribir lógica compleja, todo backend debe tener una "pipeline" de construcción (build) fiable. Si falla la configuración, no hay despliegue.

    2) Tipado de Funciones: Calculadora de Precios | Nivel: Fácil

    Objetivo

    Implementar funciones con tipado estricto en parámetros y retorno para evitar errores financieros.

    Tarea a realizar

    Vamos a crear una función para calcular el coste total de unas entradas. 1. Crea una función llamada calculateTotal que acepte: * price: número (precio base). * quantity: número (cantidad de entradas). * tax: número (opcional, por defecto 0.21 - 21% de IVA). 2. La función debe retornar explícitamente un number. 3. Implementa la lógica: (precio * cantidad) * (1 + impuestos). 4. Prueba a llamar la función enviando un string "2" en la cantidad y observa cómo TypeScript protege tu lógica financiera antes de ejecutar.

    Aplicación en el Mundo Real

    En JS, 100 * "2" funciona, pero 100 + "2" concatena ("1002"). Estos errores de tipos en sistemas de facturación pueden costar millones. TS lo evita.

    3) Modelado de Datos: La Interfaz del Evento | Nivel: Fácil

    Objetivo

    Definir la estructura de datos principal de la aplicación usando Interfaces.

    Tarea a realizar

    Necesitamos estandarizar qué es un "Evento" en nuestra plataforma. 1. Crea una interface llamada EventItem. 2. Debe tener las siguientes propiedades: * id: número. * title: cadena de texto. * date: objeto Date. * description: cadena de texto opcional (a veces no hay descripción). * organizerId: número o cadena (Union Type). 3. Crea un objeto constante llamado launchParty que cumpla estrictamente con esta interfaz.

    Aplicación en el Mundo Real

    Las interfaces actúan como contratos. Si el equipo de Frontend sabe que el objeto siempre tendrá un id y un title, pueden programar sin miedo a recibir undefined.

    4) Gestión de Estados con Enums | Nivel: Fácil

    Objetivo

    Utilizar Enums para manejar un conjunto finito de estados conocidos.

    Tarea a realizar

    Los tickets de un evento tienen estados muy específicos. No queremos usar strings mágicos como "vendido" o "libre" que pueden tener errores tipográficos ("venddio"). 1. Define un enum llamado TicketStatus con los valores: AVAILABLE, RESERVED, SOLD, CANCELED. 2. Crea una variable currentStatus de tipo TicketStatus e inicialízala en "Disponible". 3. Escribe una función printStatus(status: TicketStatus) que imprima un mensaje diferente según el estado.

    Aplicación en el Mundo Real

    Los enums hacen el código legible (if status === TicketStatus.SOLD) y evitan errores humanos al escribir cadenas de texto repetitivas.

    5) Depuración de Código: El Bug del Becario | Nivel: Fácil

    Objetivo

    Identificar malas prácticas (any) y errores de lógica en un código existente, refactorizándolo para que sea seguro (Type Safety).

    Tarea a realizar

    Un becario dejó este código para procesar datos de usuarios externos. Está lleno de peligros. Código Legacy (con errores): 

    function processUserData(user: any) {
    console.log("Procesando usuario: " + user.name.toUpperCase());
    // Queremos saber si es admin, pero a veces viene como string "true" o boolean true
    if (user.role == "admin" || user.isAdmin) {
         return user.secretCode;
    }
    return "Acceso denegado";
}

// Si pasamos esto, explota:
// processUserData({ id: 1 });

    Tu Misión: 1. Copia el código en tu editor. 2. Define una interface UserData adecuada. 3. Elimina el tipo any y usa la interfaz. 4. Usa Optional Chaining (?.) para evitar que explote si name no existe. 5. Asegúrate de que la función devuelve un tipo consistente (ej. string).

    Aplicación en el Mundo Real

    El tipo any es el enemigo #1 en TypeScript. Desactiva todas las protecciones. En producción, recibir un objeto incompleto (sin name) haría caer el servidor si no lo validamos.

    6) Asincronía Tipada: Simulando la Base de Datos | Nivel: Fácil

    Objetivo

    Manejar promesas tipadas y funciones async/await.

    Tarea a realizar
    1. Crea una interfaz Venue (Lugar del evento) con id (number) y name (string).
    2. Crea una función getVenueById(id: number) que retorne una Promise<Venue>.
    3. Dentro, usa setTimeout para simular un retardo de 1 segundo y devuelve un objeto dummy.
    4. Crea una función async main() que consuma esa promesa con await e imprima el nombre del lugar.
    Aplicación en el Mundo Real

    Todo acceso a base de datos (Postgres, Mongo) o APIs externas en Node.js es asíncrono. Tipar la Promesa (Promise<User>) es vital para saber qué nos devolverá la base de datos "en el futuro".

    ## Ejercicios de Refuerzo

    7) Programación Orientada a Objetos: Usuarios y Organizadores | Nivel: Medio

    Objetivo

    Utilizar Clases, Herencia y modificadores de acceso (protected, private) para modelar actores del sistema.

    Setup Inicial

    Piensa en la jerarquía: Un organizador es un usuario, pero con más permisos.

    Tarea a realizar
    1. Crea una clase base User con:
      • Propiedades: name (public), email (private), active (boolean, default true).
      • Método login(): imprime "User [name] logged in".
      • Añade un método para validar el email (lógica simulada) que solo pueda usarse dentro de la clase (private).
    2. Crea una clase Organizer que extienda de User.
      • Propiedad nueva: eventList (array de strings).
      • Método createEvent(eventName: string): añade el evento a la lista e imprime un mensaje.
    3. Instancia un Organizer e intenta acceder a su propiedad email desde fuera. ¿Qué pasa?
    Aplicación en el Mundo Real

    La POO permite encapsular lógica. El email no debe ser modificable directamente desde cualquier parte del código (principio de encapsulamiento), debe protegerse dentro de la clase.

    8) Genéricos: La Respuesta API Universal | Nivel: Medio

    Objetivo

    Crear una estructura genérica reutilizable para estandarizar todas las respuestas del servidor.

    Tarea a realizar

    Tu API devuelve datos de usuarios, eventos o tickets, pero siempre envueltos en el mismo formato JSON (con status, éxito/error, mensaje). No queremos escribir una interfaz para cada cosa. 1. Define una interfaz genérica ApiResponse<T>. * Debe tener: status (number), success (boolean), message (string) y data (tipo T). 2. Usa la interfaz EventItem del ejercicio 3. 3. Crea una respuesta simulada eventResponse que sea de tipo ApiResponse<EventItem>. 4. Crea otra respuesta stringResponse de tipo ApiResponse<string[]> para una lista de categorías.

    Pista

    Recuerda usar los brackets <T> al definir la interfaz y sustituir T por el tipo real al usarla.

    Aplicación en el Mundo Real

    Los genéricos son fundamentales en backend. Permiten que una función como http.get<User>('/api/user') sepa automáticamente que lo que devuelve es un Usuario, habilitando el autocompletado en todo el proyecto.

    9) Utility Types: Actualización de Perfil | Nivel: Medio

    Objetivo

    Manipular tipos existentes usando Partial, Omit y Pick para crear DTOs (Data Transfer Objects).

    Tarea a realizar

    Tienes la siguiente interfaz completa de base de datos: 

    interface UserProfile {
    id: number;
    username: string;
    email: string;
    createdAt: Date;
    lastLogin: Date;
}
    1. Crea un tipo UserUpdateDTO usando Partial<T> sobre UserProfile. Esto simula que al actualizar, no tienes que enviar todos los campos. 2. Pero espera... ¡el id y createdAt no deberían poder actualizarse nunca! 3. Mejora UserUpdateDTO: Primero usa Omit para quitar id y createdAt, y luego aplica Partial al resultado. 4. Crea una función updateUser(id: number, data: UserUpdateDTO) que simplemente imprima qué campos se van a actualizar.

    Aplicación en el Mundo Real

    Nunca expongas tus modelos de Base de Datos directamente en la API. Usar Utility Types te permite derivar versiones seguras de tus tipos (DTOs) sin duplicar código. Si cambia UserProfile, tus DTOs se adaptan solos.

    ## Ejercicios de Ampliación

    10) Lógica Compleja: Sistema de Permisos y Roles (Intersections) | Nivel: Alto

    Objetivo

    Combinar tipos usando Intersection Types (&) y Type Guards para un sistema de seguridad avanzado.

    Tarea a realizar

    En EventHorizon, un "SuperUsuario" es alguien que es a la vez Admin y Editor. 1. Define type Admin = { id: number; manageUsers: () => void; }. 2. Define type Editor = { id: number; editContent: () => void; }. 3. Define type SuperUser = Admin & Editor. 4. Implementa una función createSuperUser() que devuelva un objeto que cumpla con SuperUser. Debe implementar ambos métodos. 5. Reto: Crea una función executeTask(user: Admin | Editor) que use un "Type Guard" (in operator o propiedad discriminante) para decidir si ejecutar manageUsers o editContent.

    Aplicación en el Mundo Real

    La composición de tipos (&) es más flexible que la herencia clásica para mezclar capacidades. Es muy usada en arquitecturas funcionales o Mixins.

    11) Refactorización Legacy: De Módulo JS a TS Estricto | Nivel: Alto

    Objetivo

    Convertir un archivo de utilidades "sucio" en un módulo TypeScript moderno y bien tipado.

    Setup Inicial

    Crea un archivo legacy-utils.js con este código: 

    export function process(input) {
    if (typeof input === 'string') return input.toLowerCase();
    if (Array.isArray(input)) return input.map(i => i * 2);
    return null;
}

    Tarea a realizar
    1. Renombra el archivo a .ts.
    2. Usa Function Overloads (Sobrecarga) para definir que:
      • Si recibe string, devuelve string.
      • Si recibe number[], devuelve number[].
      • Si recibe otra cosa, devuelve null.
    3. Implementa la función tipada correctamente.
    4. Crea un archivo main.ts que importe esta función y demuestre su uso.
    Aplicación en el Mundo Real

    Esta es la tarea más común al migrar proyectos reales. Mejorar el tipado de funciones polimórficas (que actúan diferente según el input) hace que el código sea autodocumentado.

    12) Investigación y Peer Review: Validación en Runtime (Zod/Joi) | Nivel: Alto

    Objetivo

    Investigar cómo TypeScript pierde sus "superpoderes" en tiempo de ejecución y cómo solucionarlo con librerías de validación.

    Tarea a realizar
    1. Investigación: TypeScript comprueba tipos al compilar, pero si tu API recibe un JSON corrupto desde el cliente, TS no lo sabe hasta que explota. Investiga qué es Zod o Joi.
    2. Coding: Crea un pequeño script que use Zod (o una librería similar) para definir un esquema de usuario (name, age > 18).
    3. Comparativa: Muestra cómo Zod puede inferir el tipo de TypeScript automáticamente (z.infer<typeof Schema>).
    4. Peer Review: Explica a un compañero (o escribe un breve resumen) por qué definir solo una interface de TS no es suficiente para validar datos que vienen de un formulario web.
    Aplicación en el Mundo Real

    En el desarrollo profesional moderno (Next.js, Node APIs), se usa el patrón "Schema Validation". Definimos el esquema de validación y obtenemos el tipo de TS gratis. Esto une la seguridad en compilación con la seguridad en ejecución.
