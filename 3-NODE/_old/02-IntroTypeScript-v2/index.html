    Tema 2: TypeScript

    Introducción

    Si JavaScript fuera un coche de carreras, sería uno increíblemente rápido, flexible y capaz de tomar curvas imposibles... pero sin cinturón de seguridad, sin airbags y con los frenos un poco sueltos. Es emocionante hasta que te estrellas en producción porque sumaste un número con un texto.

    TypeScript es ese mismo coche, pero con sistemas de seguridad de Fórmula 1. No te impide correr, pero te avisa si intentas meter la marcha atrás mientras vas a 200 km/h.

    Como vimos en el tema anterior, JavaScript es el lenguaje de la web y de Node.js, pero su naturaleza dinámica (donde las variables pueden cambiar de tipo como de camisa) es una fuente inagotable de bugs en aplicaciones grandes. TypeScript es un superset (un superconjunto) de JavaScript que añade tipado estático. Esto significa que escribimos código TS, un compilador lo revisa, nos grita si hay errores, y finalmente lo "traduce" a JavaScript limpio que el navegador o Node.js pueden entender.

    1. Introducción a TypeScript

    ¿Qué es TypeScript y por qué usarlo en Node.js?

    Definición: TypeScript

    Lenguaje de programación de código abierto desarrollado por Microsoft. Es un superset estricto de JavaScript que añade tipado estático opcional y características modernas de ECMAScript.

    Imagina que estás construyendo un rascacielos (una API REST compleja). Con JavaScript puro, estás poniendo ladrillos esperando que aguanten. Con TypeScript, tienes planos arquitectónicos (los tipos) que te garantizan matemáticamente que la estructura encaja antes de poner el primer ladrillo.

    Ventajas en el Backend: 1. Detección temprana de errores: El 80% de los errores comunes (como undefined is not a function) se cazan al escribir, no al ejecutar. 2. IntelliSense y Autocompletado: El IDE (VS Code) "entiende" tu código. Si tienes un objeto Usuario, el editor sabe que tiene un email y te lo sugiere. 3. Refactorización segura: Cambiar el nombre de una función en 50 archivos es trivial y seguro.

    Configuración del proyecto (tsconfig.json)

    El navegador y Node.js NO entienden TypeScript. Necesitamos un traductor: el compilador tsc.

    El proceso de transformación se llama Transpilación.

    B -->|Si hay errores| C[Error en Consola]
    B -->|Si todo OK| D[Código JavaScript .js]
    D --> E[Node.js Runtime]

    Para configurar cómo se comporta este traductor, usamos el archivo tsconfig.json.

    Ejemplo de configuración profesional para Node.js:

    {
  "compilerOptions": {
    "target": "ES2020",          /* Versión de JS a generar */
    "module": "commonjs",        /* Sistema de módulos (Node usa CommonJS por defecto) */
    "outDir": "./dist",          /* Dónde guardar los .js resultantes */
    "rootDir": "./src",          /* Dónde están tus .ts */
    "strict": true,              /* ¡MODO DIOS! Activa todas las comprobaciones estrictas */
    "esModuleInterop": true      /* Compatibilidad entre módulos CommonJS y ES Modules */
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules"]
}

    Consejo Pro: strict: true

    Siempre, repito, SIEMPRE activa strict: true en proyectos nuevos. Empezar sin modo estricto es como ir al gimnasio a comer pizza: pierdes el propósito principal de usar TypeScript.

    Diferencias clave con JavaScript

    Característica JavaScript TypeScript
    Tipado Dinámico (se resuelve en ejecución) Estático (se resuelve en compilación)
    Errores Saltan cuando el usuario usa la App Saltan mientras escribes el código
    Datos let a = 10; a = "hola"; (Válido) let a: number = 10; a = "hola"; (Error)
    IDE Ayuda limitada Ayuda total (superpoderes)

    Ejemplo comparativo:

    JavaScript (Peligroso): 

    function calcularPrecio(precio, impuesto) {
    return precio + impuesto; // Si impuesto es "10" (string), concatena: "10010"
}
console.log(calcularPrecio(100, "10")); // Resultado: "10010" (Error lógico grave)

    TypeScript (Seguro): 

    function calcularPrecio(precio: number, impuesto: number): number {
    return precio + impuesto;
}
// calcularPrecio(100, "10"); // ERROR: Argument of type 'string' is not assignable to parameter of type 'number'.

    TypeScript hereda los tipos primitivos de JS y añade una capa de tipos estructurales para poner orden en el caos.

    Tipos Primitivos

    Son los bloques de construcción básicos. TypeScript es muy listo y tiene Inferencia de Tipos. Si declaras y asignas a la vez, no necesitas decir el tipo explícitamente.

    // Inferencia explícita (redundante pero válida)
let nombreUsuario: string = "Alan Turing";

// Inferencia implícita (Recomendada para primitivos simples)
let vidaRestante = 100; // TS sabe que es number
let estaVivo = true;    // TS sabe que es boolean

// vidaRestante = "cero"; // ¡Error! No puedes cambiar el tipo una vez inferido.

    Arrays, Tuples y Enums

    Arrays: Listas de cosas del mismo tipo. Tuples: Arrays de longitud fija donde cada posición tiene un tipo específico (muy útil para filas de CSV o coordenadas). Enums: Conjunto de constantes con nombre. Ideal para estados o roles.

    // --- Arrays ---
const lenguajes: string[] = ["JS", "TS", "Python"];
const notas: Array<number> = [5, 8, 9]; // Sintaxis alternativa (Genéricos)

// --- Tuples ---
// Definimos: [ID, Nombre, EsAdmin]
let usuarioBD: [number, string, boolean]; 
usuarioBD = [1, "Admin", true];
// usuarioBD = ["Admin", 1, true]; // Error: el orden importa.

// --- Enums ---
enum Rol {
    USER = "USUARIO",
    ADMIN = "ADMINISTRADOR",
    GUEST = "INVITADO"
}

const miRol: Rol = Rol.ADMIN;

if (miRol === Rol.ADMIN) {
    console.log("Tienes acceso total");
}

    Any, Unknown, Void y Never

    Cuidado aquí, estos tipos definen la "seguridad" de tu código.

    • any: El comodín. Desactiva TypeScript. Úsalo solo si quieres dispararte en el pie o estás migrando código JS antiguo.
    • unknown: El any seguro. "No sé qué es esto, pero no te dejaré usarlo hasta que compruebes qué es".
    • void: Ausencia de valor (común en funciones que no retornan nada).
    • never: Valores que nunca ocurren (funciones que lanzan errores siempre o bucles infinitos).
    // --- Any vs Unknown ---
let variablePeligrosa: any = 4;
variablePeligrosa.metodoQueNoExiste(); // TS no se queja. Crash en runtime. 💥

let variableSegura: unknown = 4;
// variableSegura.toFixed(2); // Error: Object is of type 'unknown'.

if (typeof variableSegura === 'number') {
    console.log(variableSegura.toFixed(2)); // Ahora sí, TS sabe que es un número.
}

// --- Void y Never ---
function logMensaje(msj: string): void {
    console.log(msj);
    // No retorna nada
}

function lanzarError(msj: string): never {
    throw new Error(msj);
    // Nunca llega al final de la función, el script se detiene o salta.
}

    Union Types e Intersection Types

    Aquí es donde TypeScript brilla modelando datos reales.

    • Union (|): "O esto O aquello".
    • Intersection (&): "Esto Y aquello".
    // --- Union Type ---
type ID = string | number; // Puede ser texto o número

function buscarPorId(id: ID) {
    console.log(`Buscando ID: ${id}`);
}
buscarPorId(101);    // OK
buscarPorId("A-23"); // OK

// --- Intersection Type ---
type Coordenada = { x: number; y: number };
type Etiqueta = { label: string };

// Un PuntoEtiquetado tiene TODO lo de Coordenada Y TODO lo de Etiqueta
type PuntoEtiquetado = Coordenada & Etiqueta;

const punto: PuntoEtiquetado = {
    x: 10,
    y: 20,
    label: "Casa"
};

    Type Aliases vs Literal Types

    Podemos crear nuestros propios nombres para tipos complejos. Los tipos literales restringen una variable a un valor exacto.

    // Type Alias
type EstadoServidor = "ENCENDIDO" | "APAGADO" | "MANTENIMIENTO"; // Literal Types

let estadoActual: EstadoServidor;

estadoActual = "ENCENDIDO"; // OK
// estadoActual = "EXPLOTADO"; // Error: Type '"EXPLOTADO"' is not assignable to type 'EstadoServidor'.

    3. Nulabilidad y manejo de valores opcionales

    El creador del concepto null lo llamó "El error del billón de dólares". En JS, intentar acceder a una propiedad de algo que es null o undefined rompe la ejecución.

    Strict Null Checks

    Si tienes "strict": true en tu tsconfig.json, TypeScript no te permite asignar null o undefined a una variable a menos que lo digas explícitamente.

    let nombre: string = "Juan";
// nombre = null; // Error en modo estricto. ¡Gracias TS!

let apellido: string | null = "Pérez";
apellido = null; // Esto sí es válido porque lo definimos explícitamente.

    Optional Properties y Optional Chaining (?.)

    A veces, los datos no vienen completos. El signo ? indica opcionalidad. El encadenamiento opcional ?. es el salvavidas para no verificar existencia paso a paso.

    type Usuario = {
    id: number;
    datos?: { // 'datos' es opcional
        email?: string; // 'email' también es opcional
        telefono: string;
    }
};

const user1: Usuario = { id: 1 }; // No tiene datos

// --- Forma Antigua (Dolorosa) ---
// if (user1.datos && user1.datos.email) { console.log(user1.datos.email); }

// --- Forma TypeScript (Elegante) ---
// Si 'datos' es undefined, se detiene y devuelve undefined. No crashea.
console.log(user1.datos?.email);

    Nullish Coalescing (??)

    ¿Recuerdas usar || para valores por defecto? Tiene un bug: el número 0 o el string vacío "" son considerados falsos en JS. ?? solo salta si el valor es estrictamente null o undefined.

    const inputUsuario = 0;

// Problema con OR (||)
const cantidad = inputUsuario || 10; 
console.log(cantidad); // 10 (¡Mal! El usuario escribió 0 y lo ignoramos)

// Solución con Nullish Coalescing (??)
const cantidadCorrecta = inputUsuario ?? 10;
console.log(cantidadCorrecta); // 0 (Correcto, respeta el 0)

    Non-null assertion operator (!)

    Es decirle a TypeScript: "Cállate, yo sé más que tú. Te juro que esto no es nulo". Úsalo con extrema precaución, es un code smell si se abusa de él.

    const boton = document.getElementById("mi-boton"); 
// boton puede ser HTMLElement | null

// boton.click(); // Error: Object is possibly 'null'.

// Solución arriesgada: Usar !
const botonSeguro = document.getElementById("mi-boton")!;
botonSeguro.click(); // Si el botón no existe en el HTML, esto explota en runtime.

    🧠 Ejercicios Reflexivos

    1. ¿En qué escenario usar || sería mejor que usar ???
    2. ¿Por qué se considera peligroso el operador !? ¿Qué alternativa segura (usando if) podrías implementar?
    3. Define una interfaz para un Producto donde la descripcion sea opcional, pero el precio obligatorio.


    4. Funciones en TypeScript

    Las funciones son el corazón de cualquier aplicación backend. Tiparlas correctamente es esencial para que tus compañeros (o tu "yo" del futuro) sepan qué diablos hace esa función.

    Tipado de parámetros y retorno

    Debemos ser explícitos. TypeScript inferirá el retorno, pero es buena práctica escribirlo.

    // (a: tipo, b: tipo): tipoRetorno
const multiplicar = (a: number, b: number): number => {
    return a * b;
};

    Parámetros opcionales y por defecto

    // apellido es opcional (?)
// edad tiene un valor por defecto (18)
function registrar(nombre: string, edad: number = 18, apellido?: string): string {
    if (apellido) {
        return `${nombre} ${apellido}, ${edad} años.`;
    }
    return `${nombre}, ${edad} años.`;
}

console.log(registrar("Ana")); // "Ana, 18 años."
console.log(registrar("Luis", 25, "Gómez")); // "Luis Gómez, 25 años."

    Rest Parameters y Spread

    El operador ... (Rest) permite recibir un número indefinido de argumentos como un array. Debemos tipar ese array.

    // backend: función para sumar carrito de compras
function sumarPrecios(moneda: string, ...precios: number[]): string {
    const total = precios.reduce((acc, curr) => acc + curr, 0);
    return `${total} ${moneda}`;
}

console.log(sumarPrecios("EUR", 10, 20, 5, 100)); // "135 EUR"

    Sobrecarga de Funciones (Overloads)

    A veces una función puede comportarse de forma distinta según los argumentos. TypeScript permite definir varias "firmas" (signatures) para una misma función. Muy común en librerías de Node.js.

    // 1. Firmas (Lo que ve el exterior)
function getInfo(id: number): string;
function getInfo(email: string): string;

// 2. Implementación (Lo que hace la función, debe cubrir todos los casos)
function getInfo(valor: number | string): string {
    if (typeof valor === "number") {
        return `Buscando usuario por ID: ${valor}`;
    } else {
        return `Buscando usuario por Email: ${valor}`;
    }
}

const res1 = getInfo(1);           // OK
const res2 = getInfo("a@a.com");   // OK
// const res3 = getInfo(true);     // Error: No coincide con ninguna firma.

    sequenceDiagram
    participant Call as Llamada
    participant TS as TypeScript Checker
    participant Func as Implementación

    Call->>TS: getInfo(123)
    TS->>TS: ¿Coincide con firma (id: number)? ¡SÍ!

    5. Objetos e Interfaces

    Aquí modelamos nuestros datos de negocio. ¿Usuario? ¿Producto? ¿Factura? Todo son objetos.

    Interfaces vs Types

    Es la pregunta del millón. Ambos sirven para definir la forma de un objeto.
    * Interface: Mejor para definir objetos y clases. Soporta "merging" (se pueden sumar definiciones). Orientado a POO.
    * Type: Más flexible. Puede definir uniones, primitivos, tuplas. Orientado a Programación Funcional.

    Característica Interface Type Alias
    Definir Objetos ✅ Sí ✅ Sí
    Extender (Herencia) extends Intersección &
    Declaration Merging ✅ Sí (se fusionan) ❌ No (error de duplicado)
    Tipos primitivos ❌ No ✅ Sí (type Nombre = string)

    Ejemplo de Interfaz (Recomendado para Modelos de Datos):

    interface Cliente {
    id: number;
    nombre: string;
    readonly dni: string; // Solo lectura, no se puede modificar tras crearlo
    saludar(): void;
}

const c1: Cliente = {
    id: 1,
    nombre: "Empresa S.L.",
    dni: "B123456",
    saludar() { console.log("Hola"); }
};

// c1.dni = "B99999"; // Error: Cannot assign to 'dni' because it is a read-only property.

    Extensión de Interfaces

    Imagina que tienes un sistema de usuarios y administradores. El admin es un usuario con superpoderes.

    interface UsuarioBase {
    username: string;
    email: string;
}

// Admin hereda todo lo de UsuarioBase y añade permisos
interface Admin extends UsuarioBase {
    permisos: string[];
    nivel: number;
}

const superAdmin: Admin = {
    username: "root",
    email: "root@server.com",
    permisos: ["read", "write", "delete"],
    nivel: 99
};

    Index Signatures

    Cuando no sabes exactamente el nombre de las propiedades, pero sí su tipo. Útil para caches o configuraciones dinámicas.

    interface CacheAplicacion {
    [key: string]: any; // Puedo tener cualquier clave string
}

const cache: CacheAplicacion = {
    usuario_1: { nombre: "Pepe" },
    config_color: "dark",
    ultima_visita: 12345678
};

    1. Si estás creando una librería pública que otros desarrolladores van a extender, ¿deberías usar interface o type? ¿Por qué?
    2. ¿Para qué sirve la palabra clave readonly en una propiedad de una interfaz?
    3. Intenta definir un type que sea una unión de un Usuario y un Error. ¿Podrías hacer esto con una interface?


    6. Clases y Programación Orientada a Objetos

    TypeScript convierte a JavaScript (que es basado en prototipos) en un lenguaje orientado a clases "clásico" como Java o C#. Esto facilita mucho la arquitectura en backend (especialmente con patrones como Inyección de Dependencias).

    Clases: Propiedades y Modificadores

    • public: (Por defecto) Accesible desde cualquier sitio.
    • private: Solo accesible dentro de la clase.
    • protected: Accesible dentro de la clase y en sus hijas (herencia).
    class CuentaBancaria {
    // Propiedades
    public titular: string;
    private saldo: number; // Nadie puede tocar el saldo directamente desde fuera

    constructor(titular: string, saldoInicial: number) {
        this.titular = titular;
        this.saldo = saldoInicial;
    }

    public depositar(cantidad: number): void {
        this.saldo += cantidad;
        this.auditoria();
    }

    // Método privado, solo para uso interno
    private auditoria(): void {
        console.log(`Saldo actual modificado: ${this.saldo}`);
    }
}

const cuenta = new CuentaBancaria("Tony Stark", 1000000);
cuenta.depositar(500);
// cuenta.saldo = 0; // Error: Property 'saldo' is private.
// cuenta.auditoria(); // Error: Property 'auditoria' is private.

    Parameter Properties (Sintaxis Corta)

    A los desarrolladores no nos gusta escribir de más. TypeScript permite definir y asignar propiedades directamente en el constructor.

    class Coche {
    // Al poner el modificador (public/private) en el constructor, 
    // TS crea la propiedad y la asigna automáticamente. Magia. ✨
    constructor(
        public marca: string, 
        private modelo: string,
        readonly año: number
    ) {}

    getDescripcion() {
        return `Coche: ${this.marca} ${this.modelo} (${this.año})`;
    }
}

const miCoche = new Coche("Toyota", "Corolla", 2022);

    Clases Abstractas e Interfaces

    Una Clase Abstracta es un molde que no se puede instanciar directamente, sirve para que otras hereden de ella. Puede tener implementación (código real) y contratos (métodos abstractos).

    classDiagram
    class Animal {
        <<Abstract>>
        +comer()
        +hacerSonido()*
    }
    class Perro {
        +hacerSonido()
    }
    class Gato {
        +hacerSonido()
    }
    Animal <|-- Perro
    Animal <|-- Gato
    abstract class Animal {
    constructor(public nombre: string) {}

    // Método con implementación (común para todos)
    comer(): void {
        console.log(`${this.nombre} está comiendo.`);
    }

    // Método abstracto (cada hijo DEBE implementarlo a su manera)
    abstract hacerSonido(): void;
}

class Perro extends Animal {
    hacerSonido(): void {
        console.log("Guau!");
    }
}

// const bicho = new Animal("Bicho"); // Error: Cannot create an instance of an abstract class.
const toby = new Perro("Toby");
toby.comer(); // Heredado
toby.hacerSonido(); // Propio

    Decoradores (Breve introducción)

    Los verás en profundidad cuando uses frameworks como NestJS. Son funciones que modifican clases o métodos usando @.

    // Ejemplo conceptual (necesita configuración en tsconfig)
@Controller('/users') // Decorador de clase
class UserController {
    @Get() // Decorador de método
    findAll() { return "Todos los usuarios"; }
}

    7. Genéricos (Generics)

    Los genéricos son la herramienta más potente para crear código reutilizable. Piensa en ellos como variables para tipos. Permiten que una función o clase trabaje con múltiples tipos de datos, pero manteniendo la seguridad de tipos, en lugar de usar any.

    Imagina una función que devuelve lo que le pasas. Sin genéricos, tendrías que usar any. Con genéricos, capturas el tipo.

    Sintaxis básica <T>

    // T es un "placeholder" o variable de tipo. 
// Cuando use la función, T tomará el valor del tipo que pase.
function identidad<T>(arg: T): T {
    return arg;
}

let numero = identidad<number>(5); // T es number
let texto = identidad<string>("Hola"); // T es string
let inferido = identidad(true); // TS infiere que T es boolean automáticamente

    Genéricos en Interfaces y Clases (Caso Real: Respuesta API)

    En backend, casi todas las respuestas de una API tienen la misma forma: un estado, un mensaje y unos datos. Los datos cambian, la estructura no.

    interface ApiResponse<Data> {
    status: number;
    message: string;
    data: Data; // Aquí usamos el genérico
}

interface Usuario { id: number; nombre: string; }
interface Producto { sku: string; precio: number; }

// Respuesta que contiene un Usuario
const responseUser: ApiResponse<Usuario> = {
    status: 200,
    message: "OK",
    data: { id: 1, nombre: "Pepe" } // TS comprueba que esto sea un Usuario
};

// Respuesta que contiene un Producto
const responseProduct: ApiResponse<Producto> = {
    status: 200,
    message: "OK",
    data: { sku: "ABC", precio: 99 } // TS comprueba que esto sea un Producto
};

    Constraints (Restricciones)

    A veces queremos que el genérico sea flexible, pero no tanto. Usamos extends para limitar qué tipos son válidos.

    // Queremos acceder a .length, así que T debe tener esa propiedad
function longitud<T extends { length: number }>(arg: T): number {
    return arg.length;
}

longitud("Hola"); // OK (string tiene length)
longitud([1, 2, 3]); // OK (array tiene length)
// longitud(10); // Error: Number no tiene propiedad length

    8. Módulos y Namespaces

    Para mantener el código organizado, dividimos la aplicación en ficheros. TypeScript soporta el sistema de módulos estándar de ES6 (import/export), que es el recomendado hoy en día frente a los antiguos Namespaces.

    ES Modules (El estándar)

    // math.ts
export const PI = 3.14;
export function sumar(a: number, b: number): number { return a + b; }

// app.ts
import { PI, sumar } from "./math"; // Importación nombrada
import * as MathUtils from "./math"; // Importar todo como objeto

    En Node.js, dependiendo de tu configuración (package.json -> "type": "module"), TS compilará esto a require (CommonJS) o import (ESM).

    Tipado de librerías externas (@types)

    Muchas librerías de NPM están escritas en JavaScript puro (ej: express o lodash). TypeScript no sabe qué tipos tienen. Para solucionarlo, la comunidad mantiene tipos definidos en ficheros .d.ts (Definition Types).

    Si instalas express: npm install express -> Código JS. npm install -D @types/express -> Tipos TS para Express.

    Los archivos .d.ts son como un mapa para un ciego. No contienen código lógico, solo describen las formas de las funciones y objetos para que el compilador TS no se pierda.

    9. Asincronía en TypeScript

    Node.js es asíncrono por naturaleza. TypeScript nos ayuda muchísimo a saber qué devuelve una Promesa.

    Promises tipadas

    Una Promesa no devuelve un valor inmediatamente, sino en el futuro. Usamos el genérico Promise<T> para indicar qué valor resolverá.

    // Simula una consulta a Base de Datos
function buscarUsuarioBD(id: number): Promise<Usuario> {
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve({ id, nombre: "Usuario Simulado" });
        }, 1000);
    });
}

    Async / Await

    Es azúcar sintáctico sobre las promesas, pero con tipos se ve genial.

    async function main() {
    // TS sabe que 'user' es de tipo 'Usuario', no 'Promise<Usuario>'
    // porque hemos usado 'await'.
    const user = await buscarUsuarioBD(1); 
    console.log(user.nombre);
}

    Manejo de errores

    El error en un catch(error) suele ser de tipo any o unknown por defecto, porque en JS puedes lanzar (throw) cualquier cosa (un número, un string, un objeto...).

    try {
    await operacionPeligrosa();
} catch (error) {
    if (error instanceof Error) {
        console.log("Mensaje:", error.message);
    } else {
        console.log("Error desconocido:", error);
    }
}

    10. Tipos avanzados útiles en Backend

    TypeScript incluye Utility Types que transforman tipos existentes. Son vitales para no repetir código (DRY - Don't Repeat Yourself).

    Partial, Required, Pick, Omit

    Imagina que tienes este modelo de Base de Datos:

    interface Articulo {
    id: number;
    titulo: string;
    contenido: string;
    autor: string;
    fecha?: Date;
}
    • Partial<T>: Hace todo opcional. Útil para operaciones de actualización (PATCH) donde solo mandas algunos campos.
    • Required<T>: Hace todo obligatorio.
    • Pick<T, Keys>: Selecciona solo algunas propiedades.
    • Omit<T, Keys>: Elimina algunas propiedades.
    // Para crear un artículo, no necesitamos ID (lo pone la BD) ni fecha.
// Usamos Omit para quitar esos campos de la interfaz base.
type ArticuloDTO = Omit<Articulo, "id" | "fecha">;

function crearArticulo(datos: ArticuloDTO) {
    // ...
}

// Para actualizar, podemos recibir cualquier campo suelto.
// Partial hace que titulo, contenido, etc., sean opcionales.
function actualizarArticulo(id: number, cambios: Partial<Articulo>) {
    // ...
}

    Record

    Útil para definir diccionarios o mapas de objetos.

    // Un objeto cuyas claves son strings y valores son números
const inventario: Record<string, number> = {
    "manzanas": 10,
    "peras": 5,
    "platanos": 20
};

    Tipado de process.env

    En Node.js, las variables de entorno son strings o undefined. Deberíamos extender la definición global para tener autocompletado.

    // global.d.ts
namespace NodeJS {
  interface ProcessEnv {
    PORT: string;
    DB_URI: string;
    JWT_SECRET: string;
  }
}

// Ahora TS sabe que process.env.DB_URI existe y es string
const db = process.env.DB_URI;
