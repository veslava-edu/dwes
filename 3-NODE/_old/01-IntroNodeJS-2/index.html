    Introducción a Node.js

    Introducción: El Chef Multitarea

    Imaginad una cocina de un restaurante con mucha demanda.

    En el modelo tradicional (PHP, Java clásico), tenemos un ejército de cocineros. Cada vez que entra una comanda (petición HTTP), asignamos un cocinero exclusivo a esa mesa. Si el cliente tarda 5 minutos en decidir el vino, ese cocinero se queda de brazos cruzados esperando, bloqueado, sin poder atender a nadie más. Si se llenan las mesas y se acaban los cocineros, la gente espera fuera.

    Node.js es diferente. Es un solo cocinero, pero es Flash. Es increíblemente rápido tomando notas y repartiendo tareas.

    1. Llega la comanda 1: "Quiero un filete". El Chef (Event Loop) grita al horno: "¡Filete marchando!" y, sin esperar, pasa a la siguiente mesa.
    2. Llega la comanda 2: "Una ensalada". El Chef se pone a cortar lechuga inmediatamente.
    3. El horno avisa "¡DIN!" (Callback). El Chef deja un segundo la lechuga, saca el filete, lo sirve, y vuelve a la ensalada.

    Este modelo, basado en eventos y no bloqueo, es lo que hace que Node.js pueda manejar miles de conexiones concurrentes con muy pocos recursos. Hoy vamos a entender cómo funciona esta magia.

    1. ¿Qué es Node.js?

    Definición Técnica

    Node.js NO es un lenguaje de programación ni un framework. Es un entorno de ejecución (Runtime Environment) para JavaScript construido sobre el motor V8 de Chrome.

    Históricamente, JavaScript vivía encerrado en la jaula del navegador (Frontend). En 2009, Ryan Dahl tuvo la genial idea de arrancar el motor V8 de Chrome, separarlo del navegador y añadirle herramientas para interactuar con el Sistema Operativo (archivos, red, procesos). Así nació Node.js: JavaScript en el servidor.

    Características Principales

    1. Motor V8: Desarrollado por Google, compila JS a código máquina nativo a una velocidad vertiginosa.
    2. Single-Threaded (Monohilo): Usa un único hilo principal para ejecutar código JavaScript.
    3. Non-blocking I/O (Entrada/Salida no bloqueante): Las operaciones pesadas (leer disco, consultar DB) no detienen la ejecución del programa.
    4. Full Stack JS: Permite usar el mismo lenguaje en cliente y servidor, unificando tipos de datos y lógica.

    Ejemplos de Código

    Ejemplo 1.1: Servidor HTTP básico (TypeScript) Este ejemplo muestra lo sencillo que es levantar un servidor sin necesidad de herramientas externas como Apache.

    // Importamos el módulo nativo 'http'
import * as http from 'http';

const hostname = '127.0.0.1';
const port = 3000;

// Creamos el servidor
// req: IncomingMessage (Petición del cliente)
// res: ServerResponse (Respuesta nuestra)
const server = http.createServer((req: http.IncomingMessage, res: http.ServerResponse) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hola Mundo desde Node.js con TypeScript\n');
});

server.listen(port, hostname, () => {
  console.log(`Servidor corriendo en http://${hostname}:${port}/`);
});

    Ejemplo 1.2: Lectura de archivos (La filosofía Node)

    import * as fs from 'fs';
import * as path from 'path';

// Ruta al archivo
const filePath = path.join(__dirname, 'archivo.txt');

// FORMA INCORRECTA EN NODE (Bloqueante)
// Esto detiene todo el servidor hasta que se lea el archivo
try {
  const data = fs.readFileSync(filePath, 'utf8');
  console.log('Lectura Síncrona:', data);
} catch (err) {
  console.error(err);
}

// FORMA CORRECTA (No bloqueante)
// Pasamos una función (callback) que se ejecutará cuando termine
fs.readFile(filePath, 'utf8', (err, data) => {
  if (err) {
    console.error('Error leyendo:', err);
    return;
  }
  console.log('Lectura Asíncrona:', data);
});

console.log('Esto se imprime ANTES que la lectura asíncrona');

    Consejo Profesional

    Aunque veas métodos que terminan en Sync (como readFileSync), en un servidor web de producción casi nunca debes usarlos, ya que congelarían tu API para todos los usuarios mientras el disco duro gira.

    2. Arquitectura interna de Node.js

    La arquitectura de Node es una obra de ingeniería diseñada para delegar. Se compone principalmente de:

    1. V8: El motor de JS.
    2. Node.js Bindings (API): El puente entre JS y C++.
    3. Libuv: Una librería en C++ que gestiona el Event Loop y el Thread Pool.

    El Event Loop (Bucle de Eventos)

    Es el corazón de Node.js. Es un bucle infinito que comprueba si hay tareas pendientes. Imagina una rotonda. El tráfico (eventos) entra, da vueltas, y sale cuando está listo.

    El mito del Single Thread

    Node.js es monohilo solo en la ejecución de tu código JavaScript. Pero por debajo, Libuv tiene un Thread Pool (piscina de hilos) (generalmente 4 hilos) para operaciones costosas como manejo de archivos, criptografía o compresión. Node delega el trabajo pesado a C++ y sigue atendiendo peticiones.

    Diagrama de Flujo del Event Loop

    graph TD
    start((Inicio)) --> timers[Fase 1: Timers<br/>setTimeout, setInterval]
    timers --> pending[Fase 2: Pending Callbacks<br/>Errores de sistema I/O]
    pending --> idle[Fase 3: Idle, Prepare<br/>Uso interno]
    idle --> poll[Fase 4: Poll<br/>Recuperar nuevos eventos I/O<br/>y ejecutar su código]
    poll --> check[Fase 5: Check<br/>setImmediate]
    check --> close[Fase 6: Close Callbacks<br/>socket.on('close')]
    close --> exit{¿Hay más referencias?}
    exit -- Sí --> timers
    exit -- No --> fin((Salir del proceso))

    Call Stack vs Callback Queue

    Para entender la asincronía, debemos visualizar tres componentes:

    1. Call Stack (Pila de llamadas): Donde se ejecuta el código síncrono (LIFO: Last In, First Out).
    2. Node APIs: Donde se ejecutan las tareas delegadas (esperar un temporizador, esperar una respuesta HTTP).
    3. Callback Queue (Cola de tareas): Donde esperan las funciones listas para volver al Stack.

    El Event Loop simplemente mira: "¿Está vacío el Stack? Sí. ¿Hay algo en la Queue? Sí. ¡Pues muévelo al Stack!"

    Diagrama de Secuencia: Síncrono vs Asíncrono

    sequenceDiagram
    participant Main as Main Thread (JS)
    participant Libuv as Libuv / OS
    participant DB as Base de Datos

    Note over Main: Código Síncrono
    Main->>Main: Ejecuta console.log('Inicio')

    Note over Main: Operación Asíncrona
    Main->>Libuv: Pide datos a DB (Callback)
    Note right of Main: Main Thread se libera<br/>y sigue trabajando
    Main->>Main: Ejecuta console.log('Fin')

    Libuv->>DB: Consulta SQL
    DB-->>Libuv: Datos retornados
    Libuv->>Main: Pone Callback en Queue

    Note over Main: Event Loop mueve<br/>Callback al Stack
    Main->>Main: Ejecuta el Callback con los datos

    Tabla 3: Tipos de Tareas en el Loop

    Tipo Descripción Ejemplo Prioridad
    Macrotask Tareas estándar del loop setTimeout, setInterval, I/O Normal
    Microtask Tareas que se ejecutan inmediatamente tras la operación actual Promise.then, process.nextTick Alta (Se cuelan antes que la siguiente vuelta del loop)

    Tabla 4: Bloqueo del Event Loop

    Acción Consecuencia Solución
    while(true) CPU al 100%, servidor colgado Eliminar bucles infinitos
    JSON.parse (JSON enorme) Bloqueo temporal del hilo Usar streams o librerías asíncronas
    Procesamiento de Imagen Bloqueo severo Delegar a Worker Threads o servicio externo

    Ejemplos de Código

    Ejemplo 2.1: Orden de Ejecución (El examen clásico) Intenta adivinar el orden antes de ejecutarlo.

    console.log('1. Inicio del script');

setTimeout(() => {
  console.log('2. Timeout 0ms');
}, 0);

setTimeout(() => {
  console.log('3. Timeout 100ms');
}, 100);

// setImmediate se ejecuta en la fase 'Check', después de I/O
setImmediate(() => {
  console.log('4. Immediate');
});

// nextTick tiene prioridad máxima (Microtask)
process.nextTick(() => {
  console.log('5. Next Tick');
});

console.log('6. Fin del script');

/* Salida esperada:
1. Inicio del script
6. Fin del script
5. Next Tick (Microtasks siempre van primero tras limpiar el stack)
2. Timeout 0ms (Depende del rendimiento, pero suele ganar a immediate al inicio)
4. Immediate
3. Timeout 100ms
*/

    Ejemplo 2.2: Bloqueando el Event Loop (Lo que NO hay que hacer)

    import * as http from 'http';

const server = http.createServer((req, res) => {
  if (req.url === '/bloqueo') {
    // ⚠️ ESTO ES PELIGROSO
    // Un bucle síncrono pesado congela TODO el servidor
    // Nadie más puede acceder a ninguna ruta mientras esto corre
    const start = Date.now();
    while (Date.now() - start < 5000) {
      // No hacer nada por 5 segundos
    }
    res.end('Bloqueo terminado');
  } else {
    res.end('Hola, soy rápido');
  }
});

server.listen(3000);

    3. Instalación y configuración inicial

    Para trabajar profesionalmente, no basta con instalar Node. Necesitamos un entorno robusto, reproducible y tipado.

    Instalación vía NVM (Recomendado)

    Evita los instaladores de 'Siguiente, Siguiente'

    Instalar Node.js directamente desde la web oficial en Windows o macOS a veces causa problemas de permisos al instalar paquetes globales (EACCES).

    La mejor práctica profesional es usar nvm (Node Version Manager). Te permite tener múltiples versiones de Node instaladas (ej. la 18 para un proyecto legacy y la 22 para uno nuevo) y cambiar entre ellas al instante.

    Tabla 5: Comandos Esenciales de NVM

    Comando Acción
    nvm install --lts Instala la última versión LTS (Long Term Support) - Recomendada
    nvm use <versión> Cambia la versión activa en tu terminal
    nvm alias default <versión> Fija una versión predeterminada al abrir nuevas terminales
    nvm list Muestra las versiones instaladas

    Inicialización de un proyecto: package.json

    El DNI de tu proyecto. Define quién es, qué necesita y cómo arranca.

    mkdir mi-api-node
cd mi-api-node
npm init -y  # El flag -y acepta todas las preguntas por defecto

    Configuración de TypeScript y Tooling

    En 2025, escribir Node.js sin TypeScript es como conducir sin cinturón. Vamos a configurar un entorno profesional con TypeScript, ESLint (para calidad de código) y Prettier (para formato).

    Paso 1: Instalar dependencias

    # Dependencias de desarrollo (sólo necesarias para programar, no para producción)
npm install -D typescript ts-node @types/node nodemon eslint prettier

    Tabla 6: Herramientas del Entorno

    Herramienta Función Analogía
    npm Gestor de paquetes El almacén de suministros
    TypeScript Lenguaje tipado Un corrector gramatical estricto
    @types/node Definiciones de tipos para Node El diccionario para que TS entienda Node
    ts-node Ejecuta TS directamente (dev) Traductor simultáneo
    Nodemon Reinicia el server al guardar Un asistente que vigila cambios

    **Paso 2: Configurar tsconfig.json** Este archivo le dice al compilador cómo comportarse.

    {
  "compilerOptions": {
    "target": "es2020",          // Versión de JS a la que compilamos
    "module": "commonjs",        // Sistema de módulos de Node estándar
    "outDir": "./dist",          // Dónde va el código compilado (JS)
    "rootDir": "./src",          // Dónde está nuestro código fuente (TS)
    "strict": true,              // Modo estricto activado (Google Style)
    "esModuleInterop": true      // Permite importar módulos CommonJS como ES6
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules"]
}

    **Paso 3: Scripts en package.json** Automatizamos tareas comunes.

    "scripts": {
  "start": "node dist/index.js",        // Para producción (código compilado)
  "build": "tsc",                       // Compilar TS a JS
  "dev": "nodemon src/index.ts",        // Para desarrollo (reinicio auto + ts-node)
  "lint": "eslint src/**/*.ts",         // Revisar calidad
  "format": "prettier --write ."        // Formatear código
}

import * as dotenv from 'dotenv';

// Cargar variables del fichero .env
dotenv.config();
