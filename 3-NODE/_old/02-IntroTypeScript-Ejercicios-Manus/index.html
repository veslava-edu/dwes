    Ejercicios Prácticos: TypeScript para Backend (Node.js)

    Narrativa Temática: Estás trabajando en "Nexus Hub", una plataforma de gestión de proyectos interna. Tu tarea es migrar y desarrollar nuevos módulos en TypeScript para asegurar la robustez y escalabilidad del sistema.

    Ejercicios de Consolidación (Nivel Fácil)

    1) Tipado Básico y Detección de Errores | Nivel: Fácil

    Objetivo:

    Asegurar la comprensión de los tipos primitivos (string, number, boolean) y la capacidad de TypeScript para detectar errores de tipo en tiempo de edición.

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio1.ts.

    Tarea a realizar:

    El siguiente código JavaScript tiene un error lógico que TypeScript puede prevenir.

    function calcularTotal(precio: number, cantidad: number, descuento: string): number {
    // La función espera un descuento en formato string (ej: "10%")
    // pero realiza una operación matemática.
    const total = precio * cantidad;
    return total - parseFloat(descuento); 
}

console.log(calcularTotal(100, 2, "10")); // 190, pero el descuento debería ser 10% del total (200), no 10.
    1. Modifica la función calcularTotal para que el parámetro descuento sea de tipo number (representando el porcentaje, ej: 0.10).
    2. Asegúrate de que la función devuelva el tipo correcto (number).
    3. Escribe una línea de código que intente llamar a la función con un valor de descuento incorrecto (ej: un string) y explica el error que muestra TypeScript.
    Aplicación en el Mundo Real:

    Prevenir errores de conversión de tipos es la razón principal para usar TypeScript en un backend, evitando que una API devuelva un resultado incorrecto o que un proceso de negocio falle silenciosamente.

    VER Solución. 
    function calcularTotal(precio: number, cantidad: number, descuentoPorcentaje: number): number {
    const total = precio * cantidad;
    // Aplicamos el descuento correctamente
    return total * (1 - descuentoPorcentaje); 
}

// Ejemplo de uso correcto
console.log(calcularTotal(100, 2, 0.10)); // Resultado: 180 (200 - 10%)

// Ejemplo de error detectado por TS:
// calcularTotal(100, 2, "diez"); 
// Error: Argument of type 'string' is not assignable to parameter of type 'number'.

    2) Configuración del Compilador (tsconfig.json) | Nivel: Fácil

    Objetivo:

    Comprender la función de las opciones clave en el archivo de configuración de TypeScript y su impacto en el proyecto.

    Setup Inicial (cuando aplique):

    Ninguno.

    Tarea a realizar:

    Responde a las siguientes preguntas basándote en el material didáctico sobre tsconfig.json:

    1. ¿Qué opción de compilerOptions define la carpeta donde se guardará el código JavaScript transpilado?
    2. ¿Por qué es crucial activar la opción "strict": true en un proyecto profesional de Node.js?
    3. Si un desarrollador está usando una versión moderna de Node.js (que soporta ES2022), ¿qué valor debería establecer para la opción "target"?
    4. Explica brevemente el proceso de transpilación en el contexto de TypeScript.
    Aplicación en el Mundo Real:

    Un tsconfig.json bien configurado es la primera línea de defensa para asegurar la calidad del código y la compatibilidad con el entorno de ejecución (Node.js).

    VER Solución.
    1. La opción es "outDir".
    2. Activar "strict": true obliga a TypeScript a ser lo más riguroso posible con el chequeo de tipos. Esto incluye verificar valores nulos (null o undefined), lo cual previene la mayoría de los errores comunes en JavaScript en tiempo de ejecución.
    3. Debería establecer "target": "ES2022" (o la versión más reciente que soporte su entorno de Node.js).
    4. La transpilación es el proceso de traducir el código fuente de TypeScript (.ts), que incluye tipos y sintaxis moderna, a código JavaScript plano (.js) que pueda ser ejecutado por el motor de Node.js.

    3) Modelado de Datos con Tuplas y Arrays | Nivel: Fácil

    Objetivo:

    Aplicar los tipos Array y Tuple para modelar colecciones de datos estructurados.

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio3.ts.

    Tarea a realizar:

    En Nexus Hub, necesitamos modelar dos estructuras de datos:

    1. Lista de Tags: Define un array llamado tagsProyecto que solo pueda contener cadenas de texto (string). Inicialízalo con al menos tres tags (ej: 'backend', 'typescript', 'api').
    2. Registro de Evento: Define una tupla llamada logEntry que represente un registro de evento. Debe tener exactamente tres elementos:
      • Un number para el timestamp.
      • Un string para el nivel de severidad (ej: 'ERROR', 'INFO').
      • Un string para el mensaje del evento.

    Asigna un valor a logEntry y luego intenta asignarle un valor con el orden de tipos incorrecto (ej: [string, number, string]) y observa el error de TS.

    Aplicación en el Mundo Real:

    Las tuplas son perfectas para modelar estructuras de datos fijas como coordenadas GPS, códigos de color RGB o, como en este caso, registros de log.

    VER Solución. 
    // 1. Lista de Tags (Array)
const tagsProyecto: string[] = ['backend', 'typescript', 'api', 'node'];
// tagsProyecto.push(123); // Error: Argument of type 'number' is not assignable to parameter of type 'string'.

// 2. Registro de Evento (Tupla)
type LogEntry = [number, string, string];

let logEntry: LogEntry;

// Asignación correcta
logEntry = [Date.now(), 'INFO', 'Usuario root ha iniciado sesión.']; 

// Asignación incorrecta (TS detecta el error en el orden de los tipos)
// logEntry = ['ERROR', Date.now(), 'Mensaje'];

    4) Uso de Void y Never en Funciones | Nivel: Fácil

    Objetivo:

    Diferenciar el uso de los tipos de retorno void y never en funciones.

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio4.ts.

    Tarea a realizar:

    Analiza las siguientes dos funciones y responde:

    1. ¿Qué tipo de retorno debe tener la función imprimirLog y por qué?
    2. ¿Qué tipo de retorno debe tener la función lanzarErrorCritico y por qué?
    3. ¿Qué ocurriría si intentas asignar el resultado de lanzarErrorCritico a una variable?
    function imprimirLog(mensaje: string) {
    console.log(`[LOG] ${mensaje}`);
    // No devuelve nada explícitamente
}

function lanzarErrorCritico(mensaje: string): any {
    throw new Error(mensaje);
    // Esta línea nunca se alcanza
}
    Aplicación en el Mundo Real:

    Usar never ayuda a TypeScript a entender que ciertas partes del código son inalcanzables, lo cual es útil para el análisis de flujo de control y para asegurar que todas las ramas de un switch han sido manejadas.

    VER Solución.
    1. La función imprimirLog debe tener el tipo de retorno void. Esto indica que la función no devuelve un valor significativo (aunque internamente devuelva undefined).
    2. La función lanzarErrorCritico debe tener el tipo de retorno never. Esto indica que la función nunca termina su ejecución de forma normal, ya que lanza una excepción que rompe el flujo de control.
    3. Si intentas asignar el resultado de lanzarErrorCritico a una variable, TypeScript lo permitirá (ya que never es un subtipo de todos los tipos), pero en tiempo de ejecución, el programa se detendrá en el throw new Error(), y la variable nunca recibirá un valor.

    5) Funciones con Parámetros Opcionales y por Defecto | Nivel: Fácil

    Objetivo:

    Implementar funciones que utilicen parámetros opcionales y parámetros con valores por defecto.

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio5.ts.

    Tarea a realizar:

    Crea una función llamada generarToken que simule la creación de un token de seguridad para un usuario.

    1. La función debe aceptar el userId (obligatorio, number).
    2. Debe aceptar un parámetro duracionHoras que sea opcional (number).
    3. Debe aceptar un parámetro algoritmo que tenga un valor por defecto de 'HS256' (string).
    4. La función debe devolver un string que simule el token.

    Ejemplo de salida esperada: Token para usuario 101, duración: 24h, algoritmo: HS256

    Aplicación en el Mundo Real:

    Es una práctica común en el desarrollo de APIs definir valores por defecto para parámetros opcionales, como el tamaño de página (pageSize) o el algoritmo de cifrado.

    VER Solución. 
    function generarToken(
    userId: number, 
    duracionHoras?: number, 
    algoritmo: string = 'HS256'
): string {
    // Si duracionHoras es undefined (opcional no proporcionado), usamos 24 por defecto.
    const duracion = duracionHoras ?? 24; 

    return `Token para usuario ${userId}, duración: ${duracion}h, algoritmo: ${algoritmo}`;
}

// Uso 1: Solo obligatorio
console.log(generarToken(101)); 
// Salida: Token para usuario 101, duración: 24h, algoritmo: HS256

// Uso 2: Opcional y por defecto
console.log(generarToken(202, 48)); 
// Salida: Token para usuario 202, duración: 48h, algoritmo: HS256

// Uso 3: Todos los parámetros
console.log(generarToken(303, 1, 'RSA512')); 
// Salida: Token para usuario 303, duración: 1h, algoritmo: RSA512

    Objetivo:

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio6.ts.

    Tarea a realizar:

    En Nexus Hub, necesitamos modelar los datos de los empleados y los administradores.

    1. Define una interfaz base llamada Empleado con las siguientes propiedades:
      • id: number (solo lectura).
      • nombre: string.
      • departamento: string.
    2. Define una interfaz llamada Administrador que extienda de Empleado y añada las siguientes propiedades:
      • permisos: string[] (un array de cadenas).
      • fechaContratacion: Date (opcional).
    3. Crea un objeto admin de tipo Administrador y un objeto empleado de tipo Empleado.
    4. Pista: Recuerda usar la palabra clave readonly para la propiedad id.
    Aplicación en el Mundo Real:

    Las interfaces son la herramienta fundamental para definir la estructura de los datos que se envían y reciben en las APIs (Data Transfer Objects - DTOs).

    interface Empleado {

// Administrador extiende de Empleado, heredando id, nombre y departamento

    7) Gestión de Datos Externos: Any vs Unknown | Nivel: Medio

    Objetivo:

    Demostrar la diferencia de seguridad entre usar any y unknown al manejar datos provenientes de fuentes externas (ej: una API).

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio7.ts.

    Tarea a realizar:

    Simula la recepción de un objeto JSON de una API externa que contiene un campo data.

    1. Crea una función procesarDatosAny que acepte un parámetro de tipo any. Dentro de la función, intenta llamar a un método que solo existe en strings (.toUpperCase()) sobre una propiedad que podría ser un número (data.id).
    2. Crea una función procesarDatosUnknown que acepte un parámetro de tipo unknown. Intenta hacer la misma llamada (.toUpperCase()) sin realizar ninguna comprobación de tipo.
    3. Corrige la función procesarDatosUnknown para que solo llame al método si se ha comprobado que el tipo de la propiedad es string (usando Type Narrowing).
    Aplicación en el Mundo Real:

    Los datos de APIs externas son inherentemente inseguros. unknown es la forma de forzar al desarrollador a validar los datos antes de usarlos, previniendo fallos en producción.

    VER Solución. 
    interface ApiData {
    id: number;
    payload: string;
}

// Simulación de datos recibidos (podrían ser incorrectos)
const apiResponse: ApiData = { id: 123, payload: "mensaje de prueba" };

// 1. Función con ANY (Peligro)
function procesarDatosAny(data: any): void {
    // TS no se queja, pero si 'data.id' fuera un número, esto fallaría en runtime.
    console.log("ANY (Peligro):", data.payload.toUpperCase()); 
}

// 2. Función con UNKNOWN (Seguro)
function procesarDatosUnknown(data: unknown): void {
    // console.log(data.payload.toUpperCase()); // Error: Object is of type 'unknown'. TS te protege.

    // 3. Corrección con Type Narrowing
    if (typeof data === 'object' && data !== null && 'payload' in data && typeof data.payload === 'string') {
        console.log("UNKNOWN (Seguro):", data.payload.toUpperCase());
    } else {
        console.log("Error: Datos no válidos.");
    }
}

procesarDatosAny(apiResponse);
procesarDatosUnknown(apiResponse);

    8) Clases y Modificadores de Acceso | Nivel: Medio

    Objetivo:

    Aplicar los modificadores de acceso (public, private, protected) y la sintaxis abreviada del constructor (Parameter Properties).

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio8.ts.

    Tarea a realizar:

    Crea una clase ServicioAuditoria para gestionar el log de operaciones críticas en Nexus Hub.

    1. Utiliza la sintaxis abreviada del constructor para definir las propiedades nombreServicio (público) y claveAcceso (privado).
    2. Define una propiedad log (privada) que sea un array de strings.
    3. Crea un método registrarOperacion (público) que reciba un mensaje y lo añada al log.
    4. Crea un método obtenerLog (público) que devuelva el contenido del log.
    5. Intenta acceder a claveAcceso y log desde fuera de la clase y explica por qué TypeScript lo impide.
    Aplicación en el Mundo Real:

    Los modificadores de acceso son esenciales para el encapsulamiento, asegurando que el estado interno de un objeto (como una clave de API o un log) solo pueda ser modificado a través de métodos controlados.

    VER Solución. 
    class ServicioAuditoria {
    // Propiedad privada para el log
    private log: string[] = [];

    // 1. Uso de Parameter Properties para definir y asignar propiedades
    constructor(
        public nombreServicio: string, // Público
        private claveAcceso: string    // Privado
    ) {
        console.log(`Servicio ${this.nombreServicio} inicializado.`);
    }

    public registrarOperacion(mensaje: string): void {
        const timestamp = new Date().toISOString();
        this.log.push(`[${timestamp}] ${mensaje}`);
    }

    public obtenerLog(): string[] {
        // Solo la clase puede acceder al log privado
        return this.log;
    }
}

const auditoria = new ServicioAuditoria("AuthService", "super-secreto-123");
auditoria.registrarOperacion("Intento de login fallido: usuario 'admin'");
auditoria.registrarOperacion("Usuario 'root' ha cambiado su contraseña.");

console.log(auditoria.obtenerLog());

// 5. Intentos de acceso fallidos:
// console.log(auditoria.claveAcceso); // Error: Property 'claveAcceso' is private.
// console.log(auditoria.log);         // Error: Property 'log' is private.

    9) Diseño de Arquitectura: Clases Abstractas y Herencia | Nivel: Alto

    Objetivo:

    Diseñar una jerarquía de clases utilizando clases abstractas para definir un contrato de base de datos, forzando a las clases hijas a implementar métodos específicos.

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio9.ts.

    Tarea a realizar:

    En Nexus Hub, todos los modelos de datos deben interactuar con la base de datos de forma estandarizada.

    1. Define una clase abstracta llamada BaseRepository que acepte un tipo genérico T (el tipo de la entidad, ej: User, Project).
    2. Esta clase debe tener un constructor que reciba la tableName (string) y la asigne a una propiedad protected.
    3. Define los siguientes métodos abstractos que deben ser implementados por cualquier repositorio hijo:
      • findById(id: number): Promise<T | null>
      • save(entity: T): Promise<T>
      • delete(id: number): Promise<boolean>
    4. Crea una clase concreta UserRepository que extienda de BaseRepository<User> e implemente todos los métodos abstractos. Para simplificar, los métodos solo deben devolver un valor simulado (ej: Promise.resolve(true)).
    5. Define una interfaz User para el tipo genérico.
    Aplicación en el Mundo Real:

    Este patrón (Repository Pattern) es fundamental en arquitecturas de backend para desacoplar la lógica de negocio de la tecnología de la base de datos.

    Peer Review:

    Pide a un compañero que revise tu implementación de UserRepository. ¿Ha implementado todos los métodos abstractos? ¿Ha usado correctamente el tipo genérico T?

    VER Solución. 
    interface User {
    id: number;
    username: string;
    email: string;
}

// 1. Clase Abstracta
abstract class BaseRepository<T extends { id: number }> {
    // 2. Propiedad protegida para el nombre de la tabla
    constructor(protected tableName: string) {
        console.log(`Repositorio para tabla: ${this.tableName}`);
    }

    // 3. Métodos abstractos (contrato)
    abstract findById(id: number): Promise<T | null>;
    abstract save(entity: T): Promise<T>;
    abstract delete(id: number): Promise<boolean>;
}

// 4. Clase Concreta
class UserRepository extends BaseRepository<User> {
    // Llama al constructor padre con el nombre de la tabla
    constructor() {
        super("users"); 
    }

    // Implementación de los métodos abstractos
    async findById(id: number): Promise<User | null> {
        console.log(`Buscando usuario ${id} en la tabla ${this.tableName}...`);
        // Simulación de resultado
        return Promise.resolve({ id, username: `user_${id}`, email: `user${id}@nexus.com` });
    }

    async save(user: User): Promise<User> {
        console.log(`Guardando usuario ${user.username} en la tabla ${this.tableName}...`);
        return Promise.resolve(user);
    }

    async delete(id: number): Promise<boolean> {
        console.log(`Eliminando usuario ${id} de la tabla ${this.tableName}...`);
        return Promise.resolve(true);
    }
}

// Uso
const userRepo = new UserRepository();
userRepo.findById(42).then(user => console.log("Encontrado:", user));

    10) Tipos de Intersección y Decoradores (Investigación) | Nivel: Alto

    Objetivo:

    Combinar Intersection Types para crear un tipo complejo y realizar una investigación sobre el uso de Decoradores en un framework de Node.js.

    Setup Inicial (cuando aplique):

    Crea un archivo ejercicio10.ts.

    Tarea a realizar:

    Parte A: Intersection Types

    1. Define dos tipos: Auditable (con propiedades createdAt: Date y updatedAt: Date) y SoftDeletable (con una propiedad opcional deletedAt?: Date).
    2. Crea un nuevo tipo llamado BaseEntity que sea la intersección de Auditable y SoftDeletable.
    3. Crea un objeto project de tipo BaseEntity y asígnale valores.

    Parte B: Investigación sobre Decoradores

    1. Investiga cómo se utilizan los Decoradores en un framework de backend de Node.js basado en TypeScript (ej: NestJS o TypeORM).
    2. Escribe un breve párrafo (3-4 líneas) explicando cómo un decorador como @Controller() (en NestJS) o @Entity() (en TypeORM) utiliza la funcionalidad de los decoradores de TypeScript para añadir metadatos a las clases.
    Aplicación en el Mundo Real:

    Los tipos de intersección se usan para componer tipos complejos a partir de tipos más simples (Composición sobre Herencia). Los decoradores son la base de la inyección de dependencias y la configuración de metadatos en frameworks modernos.

    VER Solución.

    Parte A: Intersection Types 

    // 1. Definición de tipos
type Auditable = {
    createdAt: Date;
    updatedAt: Date;
};

type SoftDeletable = {
    deletedAt?: Date;
};

// 2. Tipo de Intersección
type BaseEntity = Auditable & SoftDeletable;

// 3. Creación del objeto
const project: BaseEntity = {
    createdAt: new Date('2023-01-01'),
    updatedAt: new Date('2024-05-15'),
    // deletedAt es opcional
};

const deletedProject: BaseEntity = {
    createdAt: new Date('2023-01-01'),
    updatedAt: new Date('2024-05-15'),
    deletedAt: new Date('2024-06-01'),
};

console.log(project);

    Parte B: Investigación sobre Decoradores

    Los decoradores en TypeScript son una característica experimental (o estándar en versiones recientes) que permite adjuntar y manipular metadatos a clases, métodos, propiedades o parámetros en tiempo de diseño. Frameworks como NestJS utilizan intensamente los decoradores (ej: @Controller(), @Get(), @Inject()) para definir la estructura de la aplicación. Cuando se aplica un decorador a una clase, este ejecuta una función que, internamente, utiliza la API de metadatos de TypeScript (reflect-metadata) para registrar información sobre esa clase (por ejemplo, que es un controlador de rutas o que necesita una dependencia específica). El runtime del framework lee estos metadatos para saber cómo instanciar la clase y cómo enrutar las peticiones HTTP, permitiendo una configuración declarativa y limpia.
