    npm Cheat Sheet: Referencia Rápida

    Comandos Esenciales

    Inicialización y Configuración

    npm init              # Crear package.json interactivamente
npm init -y           # Crear package.json con defaults
npm config get npm_username  # Ver usuario npm
npm whoami            # Ver usuario loguado

    Instalación de Paquetes

    npm install pkg           # Instalar y agregar a dependencies
npm install -D pkg        # Instalar como devDependency
npm install --save-dev pkg # Forma larga
npm install --production  # Solo dependencias (sin dev)
npm ci                    # Clean install (reproducible)
npm update pkg            # Actualizar paquete específico
npm update                # Actualizar todos los paquetes

    Desinstalación

    npm uninstall pkg     # Desinstalar paquete
npm rm pkg            # Forma corta
npm prune             # Eliminar paquetes no usados
npm cache clean --force  # Limpiar caché

    Información y Listado

    npm list              # Listar dependencias instaladas
npm list --depth=0    # Solo dependencias directas
npm outdated          # Ver qué está desactualizado
npm view pkg          # Info de un paquete en npm
npm search keyword    # Buscar paquetes
npm ls --production   # Solo dependencias de producción

    Seguridad

    npm audit             # Escanear vulnerabilidades
npm audit fix         # Intentar arreglarlas automáticamente
npm audit --json      # Reporte en JSON

    Publicación y Versiones

    npm version patch     # 1.2.3 → 1.2.4
npm version minor     # 1.2.3 → 1.3.0
npm version major     # 1.2.3 → 2.0.0
npm publish           # Publicar en npm (requiere cuenta)
npm login             # Loguear en npm
npm logout            # Desloguear

    Scripts

    npm start             # Ejecuta script "start"
npm test              # Ejecuta script "test"
npm run script        # Ejecuta cualquier script
npm run script -- arg # Pasar argumentos

    Miscelánea

    npm help              # Ver ayuda general
npm help install      # Ver ayuda de comando específico
npx package           # Ejecutar sin instalar
npm link              # Instalar localmente para testing
npm unlink pkg        # Desinstalar local

    Rangos de Versión

    Rango Significado Ejemplo
    1.2.3 Exacto Instala solo 1.2.3
    ^1.2.3 Compatible 1.2.3 - 1.999.999 (no mayor)
    ~1.2.3 Aproximado 1.2.3 - 1.2.999 (no minor)
    >=1.2.3 Mayor o igual 1.2.3 y superiores
    ^1.2.3 <2 Rango 1.2.3 a 1.999.999
    * Cualquiera Versión más nueva disponible
    latest Última Tag "latest" en npm

    package.json: Campos Clave

    {
  "name": "@scope/paquete",        // Identificador único
  "version": "1.2.3",              // Versionado semántico
  "description": "Descripción",     // Para npm search
  "main": "dist/index.js",         // Punto de entrada
  "types": "dist/index.d.ts",      // TypeScript types
  "bin": { "cmd": "bin/cli.js" },  // Para CLIs
  "scripts": {                      // Comandos npm run
    "start": "node dist/index.js",
    "build": "tsc",
    "test": "jest"
  },
  "dependencies": {},               // Producción
  "devDependencies": {},            // Desarrollo
  "peerDependencies": {},           // Para plugins
  "keywords": ["word1", "word2"],   // Para búsqueda
  "author": "Nombre <email>",
  "license": "MIT",                 // SPDX
  "homepage": "https://...",
  "repository": {                   // Git repo
    "type": "git",
    "url": "git+https://github.com/user/repo.git"
  },
  "engines": {                      // Requerimientos
    "node": ">=18.0.0",
    "npm": ">=9.0.0"
  },
  "private": false                  // No publicar si true
}

    Estructura de Proyecto Típico

    mi-proyecto/
├── package.json              // Definición del proyecto
├── package-lock.json         // Versiones exactas (commitear)
├── tsconfig.json             // Configuración TypeScript
├── src/                       // Código fuente
│   ├── index.ts
│   └── utils.ts
├── dist/                      // Compilado (generado)
├── tests/                     // Tests
├── node_modules/             // Paquetes (no commitear)
├── .gitignore
├── README.md
└── .npmignore                // Qué excluir si publicas

    Dependencias: Dónde va cada cosa?

    Paquete Dónde Por qué
    express dependencies Runtime necesita
    typescript devDependencies Compilar, no runtime
    jest devDependencies Solo testing
    eslint devDependencies Solo lintear
    dotenv dependencies Runtime necesita variables
    @types/express devDependencies Solo tipos TypeScript
    nodemon devDependencies Desarrollo, no runtime

    package name: (carpeta)          # Nombre único
version: (1.0.0)                 # Semver
description:                     # Una línea de descripción
entry point: (index.js)          # Archivo main
test command:                    # npm test
git repository:                  # URL del repo

    Workflows Comunes

    Desarrollo Local

    npm install          # Instalar todo
npm run dev          # Ejecutar con hot reload
npm test             # Correr tests
npm run build        # Compilar para producción

    Publicar un Paquete

    npm login            # Loguear
npm version minor    # Bumpar versión
npm publish          # Publicar en npm

    Limpiar y Reinstalar

    rm -rf node_modules package-lock.json
npm install
# O simplemente:
npm ci

    Auditar Seguridad

    npm audit            # Ver vulnerabilidades
npm audit fix        # Intentar arreglarse
npm audit fix --force  # Forzar actualización

    package-lock.json: Conceptos

    • Generado automáticamente: No edites manualmente
    • Commitea a Git: Asegura reproducibilidad
    • Especifica versiones exactas: No rangos
    • Incluye hashes: Para verificar integridad
    • Transitividad: Todas las dependencias anidadas

    Cuándo usar: - npm install en desarrollo - npm ci en CI/CD y producción

    Errores Comunes y Soluciones

    Error Solución
    EACCES Instalar npm sin sudo o usar nvm
    ENOTFOUND registry.npmjs.org Verificar conexión internet
    peer dep missing Instalar manualmente la dependencia
    package not found Verificar nombre del paquete en npmjs.com
    conflicting peer deps Usar npm audit fix o actualizar paquetes

    Tips Profesionales

    1. Siempre commitea package-lock.json (excepto librerías)
    2. Usa npm ci en CI/CD (no npm install)
    3. Ejecuta npm audit regularmente
    4. Actualiza paquetes regularmente (pero revisa cambios)
    5. Usa scopes para paquetes privados (@org/package)
    6. No instales globalmente (usa npx en su lugar)
    7. Prefiere devDependencies cuando sea posible
    8. Usa git + GitHub para colaboración en paquetes
