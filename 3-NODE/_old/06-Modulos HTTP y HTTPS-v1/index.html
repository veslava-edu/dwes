    Módulos HTTP y HTTPS en Node.js con TypeScript

    Introducción: El Camarero Digital

    Imagina que entras en un restaurante muy concurrido. Tú (el Cliente) te sientas y miras la carta. Decides qué quieres y llamas al camarero. El camarero (el Servidor) toma nota de tu pedido (Request), lo lleva a la cocina (Procesamiento), espera a que el chef termine y te trae el plato a la mesa (Response).

    Si el camarero no existiera, tendrías que entrar a la cocina a gritos, pelearte con los ingredientes y probablemente quemar el local. En el mundo del desarrollo web, Node.js nos proporciona ese camarero eficiente, rápido y capaz de atender cientos de mesas a la vez mediante los módulos http y https.

    En el tema anterior aprendimos a manipular ficheros con fs. Ahora, vamos a exponer esos ficheros y datos al mundo entero. Vamos a levantar los cimientos de Internet.

    Filosofía Node.js

    Node.js implementa el protocolo HTTP como un ciudadano de primera clase. A diferencia de otros lenguajes (como PHP tradicional) que necesitan un servidor web externo como Apache o Nginx para funcionar, Node.js ES el servidor web.

    1. Introducción a los módulos http y https

    El corazón de cualquier aplicación backend en Node.js reside en su capacidad para comunicarse a través de la red. Los módulos node:http y node:https son nativos, lo que significa que no necesitas instalar nada con npm para empezar a crear un servidor.

    Propósito y Diferencias

    Estos módulos permiten crear tanto servidores (que escuchan y responden) como clientes (que piden datos a otros servidores) sin dependencias externas.

    Característica Módulo http Módulo https
    Seguridad Texto plano (cualquiera puede "espiar" los paquetes). Cifrado mediante TLS/SSL (Transport Layer Security).
    Puerto por defecto 80 443
    Uso principal Desarrollo local, redes internas, redirecciones. Producción, APIs públicas, e-commerce, login.
    Complejidad Baja (Plug & Play). Media (Requiere certificados y claves privadas).

    Arquitectura basada en Eventos

    Como casi todo en Node.js, estos servidores heredan de EventEmitter. Esto significa que no hay un bucle while(true) bloqueante esperando conexiones. El servidor "duerme" hasta que alguien "toca la puerta" (emite un evento request), momento en el que Node.js despierta, ejecuta tu callback, y vuelve a dormir.

    Ejemplos Prácticos

    Ejemplo 1.1: Importación moderna en TypeScript Desde versiones recientes de Node, se recomienda usar el prefijo node:.

    // Importación explícita del protocolo node:
import http from 'node:http';
import https from 'node:https';

// Verificamos que tenemos acceso a los métodos principales
console.log('Métodos HTTP disponibles:', http.METHODS);
console.log('Códigos de estado disponibles:', http.STATUS_CODES);

    Ejemplo 1.2: Tipado estático con TypeScript TypeScript nos ayuda a saber qué estamos manejando.

    import http, { IncomingMessage, ServerResponse, Server } from 'node:http';

// Definimos el tipo de nuestro servidor explícitamente
const miServidor: Server = http.createServer();

// Node.js es orientado a eventos
miServidor.on('request', (req: IncomingMessage, res: ServerResponse) => {
    // req: Lo que nos llega
    // res: Lo que enviamos
    console.log('¡Evento request disparado!');
});

    2. Modelo Cliente–Servidor y fundamentos HTTP

    Para programar un servidor, debemos entender las reglas del juego: el protocolo HTTP (HyperText Transfer Protocol).

    Definición: Protocolo Stateless

    HTTP es un protocolo sin estado. El servidor tiene memoria de pez dorado. No recuerda si la petición que llega ahora es del mismo usuario que hizo una petición hace 10 milisegundos, a menos que usemos mecanismos externos como Cookies o Tokens.

    El Ciclo de Vida

    1. Request (Petición): El cliente (navegador, móvil, otro servidor) envía un mensaje con: Método (verbo), URL, Cabeceras y Cuerpo (opcional).
    2. Processing (Procesamiento): Tu código Node.js recibe los datos, consulta BBDD, lee ficheros, calcula, etc.
    3. Response (Respuesta): El servidor envía de vuelta: Código de estado, Cabeceras y Cuerpo.

    Versiones del Protocolo

    Versión Características Clave Estado actual
    HTTP/1.1 Estándar durante años. Texto plano. Una petición por conexión TCP (con keep-alive). Sigue siendo la base de la mayoría de APIs simples.
    HTTP/2 Binario (no texto). Multiplexación (varias peticiones a la vez por un solo cable). Compresión de cabeceras. Estándar moderno para webs de alto rendimiento.
    HTTP/3 Basado en UDP (QUIC). Más rápido en redes inestables. El futuro, adopción creciente.

    Ejemplos Prácticos

    Ejemplo 2.1: Estructura de una Petición HTTP (Raw) Aunque Node.js lo parsea, esto es lo que viaja por el cable.

    POST /api/login HTTP/1.1
Host: miservidor.com
Content-Type: application/json
User-Agent: Mozilla/5.0...

{"usuario": "admin", "pass": "1234"}

    Ejemplo 2.2: Interfaz TypeScript para entender el Request Simulación de lo que Node.js nos entrega en el objeto req.

    // Esto es una simplificación didáctica de IncomingMessage
interface IRequestDidactico {
    method: 'GET' | 'POST' | 'PUT' | 'DELETE';
    url: string;
    headers: Record<string, string>;
    httpVersion: string;
    // ... y es un Readable Stream
}

const simularLog = (req: IRequestDidactico) => {
    console.log(`Recibido ${req.method} en ${req.url} usando HTTP/${req.httpVersion}`);
}

    3. Creación de un servidor HTTP básico

    Vamos a mancharnos las manos. Crear un servidor en Node.js es casi insultantemente sencillo comparado con configurar un Apache.

    La función createServer

    Esta función recibe un callback que se ejecutará cada vez que llegue una petición.

    Ejemplos Prácticos

    Ejemplo 3.1: El "Hola Mundo" del servidor web

    import http, { IncomingMessage, ServerResponse } from 'node:http';

const server = http.createServer((req: IncomingMessage, res: ServerResponse) => {
    // 1. Establecemos cabeceras
    res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });

    // 2. Enviamos el cuerpo y cerramos la respuesta
    res.end('¡Hola mundo desde Node.js con TypeScript! 🚀');
});

// 3. Ponemos el servidor a escuchar
server.listen(3000, () => {
    console.log('Servidor escuchando en http://localhost:3000');
});

    Ejemplo 3.2: Configuración robusta con Hostname y Backlog El método listen acepta más parámetros. El backlog es la cola de conexiones pendientes antes de empezar a rechazar nuevas.

    const PORT = 8080;
const HOST = '0.0.0.0'; // Escuchar en todas las interfaces de red (local y wifi)
const BACKLOG = 511;    // Cola de espera máxima

const server = http.createServer((req, res) => {
    res.end('Servidor robusto activo');
});

server.listen(PORT, HOST, BACKLOG, () => {
    console.log(`Servidor corriendo en http://${HOST}:${PORT}`);
});

    Ejemplo 3.3: Manejo de errores del servidor Un servidor profesional debe controlar si el puerto está ocupado.

    server.on('error', (e: any) => {
    if (e.code === 'EADDRINUSE') {
        console.error(`🚨 Error: El puerto ${PORT} ya está en uso.`);
        console.error('Intenta cerrar el otro proceso o usar otro puerto.');
        // Opcional: Reintentar en otro puerto
        setTimeout(() => {
            server.close();
            server.listen(PORT + 1);
        }, 1000);
    } else {
        console.error('Error del servidor:', e);
    }
});

    Error común: EADDRINUSE

    Este error ocurre cuando intentas arrancar tu servidor (ej. puerto 3000) pero ya tienes otra terminal ejecutándolo. Mata el proceso anterior con Ctrl + C.

    🧠 Reflexiona

    1. ¿Qué pasa si quitas la línea res.end() en el código del servidor? (Pruébalo).
    2. ¿Por qué usamos 0.0.0.0 como host en lugar de localhost o 127.0.0.1 cuando desplegamos en Docker o la nube?
    3. ¿Qué hace exactamente el parámetro backlog?


    4. Creación de un servidor HTTPS

    Para salir a producción hoy en día, HTTPS es obligatorio. Google te penaliza si no lo tienes, y los navegadores muestran un candado rojo feísimo.

    Certificados TLS/SSL

    Para que HTTPS funcione, necesitas dos ficheros clave: 1. Private Key (key.pem): Solo la tiene el servidor. Nunca se comparte. 2. Certificate (cert.pem): Es público. Contiene tu clave pública y la firma de una autoridad (CA).

    Desarrollo vs Producción

    En producción usas certificados reales (de Let's Encrypt, Verisign, etc.). En desarrollo generamos certificados "autofirmados" (Self-signed). El navegador se quejará ("Sitio no seguro"), pero la conexión irá cifrada.

    Ejemplos Prácticos

    Ejemplo 4.1: Generar certificados (Comando de Terminal) Necesitas tener openssl instalado (viene con Git Bash en Windows o nativo en Linux/Mac).

    # Ejecuta esto en tu terminal antes de arrancar el código
openssl req -nodes -new -x509 -keyout server.key -out server.cert -days 365
# Te pedirá datos (País, etc.), puedes dejarlos en blanco para desarrollo local

    Ejemplo 4.2: Servidor HTTPS básico

    import https from 'node:https';
import fs from 'node:fs';

// Leemos los certificados de forma síncrona (solo al arrancar)
// Bloquear aquí está bien porque el servidor no ha empezado
const options = {
    key: fs.readFileSync('server.key'),
    cert: fs.readFileSync('server.cert')
};

const secureServer = https.createServer(options, (req, res) => {
    res.writeHead(200);
    res.end('Estás conectado de forma segura 🔒');
});

secureServer.listen(443, () => {
    console.log('Servidor HTTPS corriendo en https://localhost');
});

    Ejemplo 4.3: Redirección automática HTTP a HTTPS Un patrón profesional es levantar dos servidores.

    import http from 'node:http';
import https from 'node:https';
import fs from 'node:fs';

const httpsOptions = { /* ... key y cert ... */ key: fs.readFileSync('server.key'), cert: fs.readFileSync('server.cert') };

// Servidor HTTPS (El real)
https.createServer(httpsOptions, (req, res) => {
    res.end('Bienvenido al sitio seguro');
}).listen(443);

// Servidor HTTP (Solo para redirigir)
http.createServer((req, res) => {
    // 301 = Moved Permanently
    res.writeHead(301, { "Location": `https://${req.headers.host}${req.url}` });
    res.end();
}).listen(80);

    🧠 Reflexiona

    1. ¿Por qué leemos los certificados con readFileSync y no con readFile asíncrono?
    2. ¿Qué diferencia hay entre un certificado autofirmado y uno emitido por una CA?
    3. ¿Por qué el puerto estándar es 443 para HTTPS?


    5. Manejo de solicitudes (Request – IncomingMessage)

    El objeto req (IncomingMessage) es un Readable Stream. Piensa en él como una tubería por donde llega agua (datos).

    Propiedades Clave y Parsing

    No recibimos los datos de golpe (especialmente si suben un archivo grande). Los recibimos en "chunks" (trozos).

    Ejemplos Prácticos

    Ejemplo 5.1: Analizando Método y URL

    import http from 'node:http';

const server = http.createServer((req, res) => {
    // Desestructuración segura
    const { method, url, headers } = req;

    // Obtenemos el User-Agent para saber quién nos visita
    const userAgent = headers['user-agent'] || 'Desconocido';

    console.log(`--> ${method} solicitud a ${url} desde ${userAgent}`);

    if (method === 'GET' && url === '/usuarios') {
        res.end('Lista de usuarios');
    } else {
        res.statusCode = 404;
        res.end('Ruta no encontrada');
    }
});
server.listen(3000);

    Ejemplo 5.2: Leyendo el Body (Streams y Buffers) Este es el patrón más importante para entender Node.js a bajo nivel.

    const server = http.createServer((req, res) => {
    if (req.method === 'POST') {
        let body: Buffer[] = [];

        // Evento 'data': Se dispara cada vez que llega un trozo de información
        req.on('data', (chunk: Buffer) => {
            body.push(chunk);
            console.log(`Recibido chunk de: ${chunk.length} bytes`);
        });

        // Evento 'end': Ya no hay más datos, procesamos el total
        req.on('end', () => {
            // Unimos todos los trozos en un solo Buffer y lo pasamos a String
            const bodyParsed = Buffer.concat(body).toString();
            console.log('Cuerpo completo:', bodyParsed);

            res.end('Datos recibidos correctamente');
        });
    }
});

    Ejemplo 5.3: Procesando JSON con seguridad Es vital proteger el servidor de datos mal formados.

    req.on('end', () => {
    const rawData = Buffer.concat(body).toString();

    try {
        const jsonData = JSON.parse(rawData); // Intentamos convertir a objeto JS
        console.log('Usuario recibido:', jsonData.nombre);
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ status: 'success', received: jsonData }));
    } catch (error) {
        console.error('JSON inválido');
        res.writeHead(400, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ error: 'Invalid JSON format' }));
    }
});

    Backpressure y Seguridad

    Si un usuario malintencionado te envía un archivo de 10GB en una petición POST y guardas todos los chunks en un array en memoria RAM... tu servidor explotará (Crash). En producción, siempre debes limitar el tamaño máximo del body o usar streams para volcar a disco directamente.

    2. ¿Cómo evitarías que alguien colapse tu servidor enviando el Quijote entero en un JSON?
    3. ¿Cuál es la diferencia entre req.url y usar new URL(req.url, base)?


    6. Manejo de respuestas (Response – ServerResponse)

    El objeto res es un Writable Stream. Escribimos en él para enviar datos al cliente.

    Estados y Tipos de Contenido

    Debemos ser educados y decir al navegador qué le estamos enviando (HTML, JSON, una imagen) y cómo fue todo (200 OK, 404 Not Found, 500 Error).

    Comparativa de Formatos

    Formato Content-Type Uso típico
    Texto text/plain Logs, mensajes simples, debug.
    HTML text/html Páginas web, renderizado en servidor (SSR).
    JSON application/json APIs REST, comunicación App-Backend.
    Binario image/png, application/pdf Descarga de archivos.

    Ejemplos Prácticos

    Ejemplo 6.1: Enviando JSON (API REST básica)

    const server = http.createServer((req, res) => {
    const datosUsuario = {
        id: 1,
        nombre: "Alan Turing",
        rol: "Admin"
    };

    // Importante: Avisar que es JSON
    res.setHeader('Content-Type', 'application/json');
    res.statusCode = 200;

    // JSON.stringify es obligatorio, res.end espera string o buffer
    res.end(JSON.stringify(datosUsuario));
});

    Ejemplo 6.2: Streaming de un archivo (Eficiencia máxima) En lugar de leer todo el archivo en memoria y enviarlo, usamos pipe para conectar el disco con la red.

    import fs from 'node:fs';

http.createServer((req, res) => {
    const rutaArchivo = './video-grande.mp4';
    const stat = fs.statSync(rutaArchivo);

    res.writeHead(200, {
        'Content-Type': 'video/mp4',
        'Content-Length': stat.size
    });

    // Creamos un stream de lectura del archivo
    const readStream = fs.createReadStream(rutaArchivo);

    // "Enchufamos" la lectura a la respuesta
    readStream.pipe(res);
}).listen(3000);

    Ejemplo 6.3: Redirecciones Mover al usuario de un sitio a otro.

    http.createServer((req, res) => {
    if (req.url === '/antiguo') {
        // 301: Movido permanentemente
        // 302: Movido temporalmente
        res.writeHead(301, {
            'Location': '/nuevo-sitio'
        });
        res.end(); // Finalizamos sin cuerpo
    }
}).listen(3000);

    🧠 Reflexiona

    1. ¿Qué pasa si envías un JSON pero pones Content-Type: text/html? ¿Cómo reacciona el navegador?
    2. ¿Por qué pipe es mejor que fs.readFile para archivos grandes?
    3. Investiga qué es el código de estado 418.


    7. Cabeceras HTTP y control del protocolo

    Las cabeceras (Headers) son los metadatos de la carta. No son el mensaje, sino las instrucciones para el cartero y el destinatario.

    Cabeceras Esenciales

    • Content-Type: Qué te envío.
    • Content-Length: Cuánto ocupa.
    • Cache-Control: Cuánto tiempo puedes guardarlo en memoria.
    • Authorization: ¿Tienes permiso?

    Ejemplos Prácticos

    Ejemplo 7.1: Configurando CORS (Cross-Origin Resource Sharing) CORS es el portero de discoteca del navegador. Por defecto, impide que un JS en dominioA.com pida datos a dominioB.com.

    http.createServer((req, res) => {
    // Permitir acceso desde cualquier origen (Inseguro para prod, útil para dev)
    res.setHeader('Access-Control-Allow-Origin', '*');
    // Métodos permitidos
    res.setHeader('Access-Control-Allow-Methods', 'GET, POST, OPTIONS');
    // Cabeceras permitidas
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type');

    if (req.method === 'OPTIONS') {
        // Respuesta rápida a la petición "Preflight" del navegador
        res.writeHead(204);
        res.end();
        return;
    }

    res.end('CORS configurado');
});

    Ejemplo 7.2: Control de Caché Hacer que el navegador no nos vuelva a pedir lo mismo en 1 hora.

    res.setHeader('Cache-Control', 'public, max-age=3600'); 
// 3600 segundos = 1 hora
res.end('Esta respuesta se guardará en tu navegador por una hora.');

    Ejemplo 7.3: Set-Cookie

    res.setHeader('Set-Cookie', ['type=ninja', 'language=javascript; HttpOnly']);
res.end('Te he enviado unas cookies. Revisa las devtools.');

    8. Cliente HTTP/HTTPS en Node.js

    Node.js no solo sirve, también pide. A menudo tu servidor necesita llamar a otra API (ej. pedir el tiempo, validar un pago en PayPal).

    Métodos de Cliente

    Método Descripción Node.js Version
    http.get() Solo para peticiones GET sencillas. Clásico (v0.1+)
    http.request() Para POST, PUT, DELETE, etc. Más control. Clásico (v0.1+)
    fetch() Estándar moderno (igual que en navegadores). Moderno (v18+, experimental en v17.5)

    Ejemplos Prácticos

    Ejemplo 8.1: http.get (El clásico)

    import https from 'node:https';

const url = 'https://jsonplaceholder.typicode.com/todos/1';

https.get(url, (res) => {
    let data = '';

    // Recibimos datos por chunks (igual que en el servidor)
    res.on('data', (chunk) => {
        data += chunk;
    });

    res.on('end', () => {
        console.log('Respuesta recibida:', JSON.parse(data));
    });

}).on('error', (err) => {
    console.error('Error en la petición:', err.message);
});

    Ejemplo 8.2: http.request (Haciendo un POST) Enviar datos requiere más configuración.

    const dataToSend = JSON.stringify({ name: 'Morpheus', job: 'Leader' });

const options = {
    hostname: 'reqres.in',
    path: '/api/users',
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'Content-Length': dataToSend.length
    }
};

const req = https.request(options, (res) => {
    console.log(`Estado: ${res.statusCode}`);

    res.on('data', (d) => {
        process.stdout.write(d);
    });
});

req.on('error', (error) => {
    console.error(error);
});

// ¡Importante! Hay que escribir los datos y finalizar la petición
req.write(dataToSend);
req.end();

    Ejemplo 8.3: fetch API (El estándar moderno) Mucho más limpio y basado en Promesas.

    // En Node 18+ no hace falta importar nada para fetch
async function obtenerDatos() {
    try {
        const response = await fetch('https://jsonplaceholder.typicode.com/todos/1');
        if (!response.ok) throw new Error(`Error HTTP: ${response.status}`);

        const data = await response.json();
        console.log('Datos con fetch:', data);
    } catch (error) {
        console.error('Fallo en fetch:', error);
    }
}

obtenerDatos();

    9. Operaciones avanzadas y buenas prácticas

    Un servidor real no es solo un if/else. Necesita estructura, limpieza y seguridad.

    Routing Manual Básico

    Sin un framework, debemos construir nuestro propio sistema de rutas. Es como ser un guardia de tráfico.

    Diagrama de Flujo de Routing

    graph TD
    A[Petición Entrante] --> B{¿Método GET?}
    B -- Sí --> C{¿URL /api?}
    B -- No --> D{¿Método POST?}
    C -- Sí --> E[Ejecutar lógica API]
    C -- No --> F[404 Not Found]
    D -- Sí --> G[Leer Body y procesar]
    D -- No --> H[405 Method Not Allowed]

    Ejemplos Prácticos

    Ejemplo 9.1: Router con Switch

    const server = http.createServer((req, res) => {
    const { url, method } = req;

    // Normalizar URL (quitar query params básicos)
    const cleanUrl = url?.split('?')[0];

    switch (cleanUrl) {
        case '/':
            res.end('Home');
            break;
        case '/api/productos':
            if (method === 'GET') res.end('Listado productos');
            else if (method === 'POST') res.end('Creando producto');
            else {
                res.statusCode = 405; // Method not allowed
                res.end('Método no permitido');
            }
            break;
        default:
            res.statusCode = 404;
            res.end('Página no encontrada');
    }
});

    Ejemplo 9.2: Graceful Shutdown (Cierre elegante) Cuando quieres actualizar el servidor, no puedes matar el proceso y dejar a usuarios con peticiones a medias.

    // Capturamos la señal de terminación (Ctrl+C o kill del sistema)
process.on('SIGINT', () => {
    console.log('\nRecibida señal de cierre. Cerrando servidor...');

    server.close((err) => {
        if (err) {
            console.error('Error al cerrar', err);
            process.exit(1);
        }
        console.log('Servidor cerrado. Conexiones terminadas.');
        // Aquí cerraríamos BBDD, Redis, etc.
        process.exit(0);
    });
});

    Ejemplo 9.3: Modularización No escribas todo en un solo fichero.

    // routes.ts (hipotético)
export const handleUserRoutes = (req: IncomingMessage, res: ServerResponse) => {
    // Lógica solo de usuarios
};

// server.ts
import { handleUserRoutes } from './routes';

http.createServer((req, res) => {
    if (req.url?.startsWith('/users')) {
        handleUserRoutes(req, res);
    }
});

    10. Visión profesional y camino a frameworks

    Llegados a este punto, te estarás preguntando: "¿De verdad la gente escribe req.on('data') y parsea Buffers a mano en el trabajo?". La respuesta corta es: No habitualmente, pero sí cuando es necesario.

    La Pirámide de la Abstracción

    1. Node.js Nativo (http): Control total, máximo rendimiento, código verboso.
    2. Micro-frameworks (Connect): Ligera capa de plugins.
    3. Frameworks Minimalistas (Express, Fastify): Lo estándar. Enrutado fácil, middlewares.
    4. Frameworks Estructurados (NestJS): Arquitectura empresarial sobre Express/Fastify.

    ¿Por qué aprender esto?

    Entender el módulo http es la diferencia entre un programador que usa herramientas y un ingeniero que entiende cómo funcionan. - Si Express falla, sabrás depurarlo. - Si necesitas rendimiento extremo (streaming de video), bajarás al metal (http). - Entenderás qué son realmente los Middlewares (solo funciones que envuelven req y res).

    Ejemplos Prácticos

    Ejemplo 10.1: Lo que hace Express por debajo (Simplificado) Express es básicamente un envoltorio de http.createServer.

    // Pseudo-código de cómo nace un framework
function miMiniExpress() {
    return {
        get: (path, handler) => { /* guardar ruta */ },
        listen: (port) => {
            http.createServer((req, res) => {
                // buscar ruta y ejecutar handler
            }).listen(port);
        }
    }
}
