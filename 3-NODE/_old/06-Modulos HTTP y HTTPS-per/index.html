    HTTP y HTTPS en Node.js: Fundamentos y Arquitectura

    Introducción a los módulos http y https

    ¿Alguna vez te has preguntado qué sucede cuando escribes una URL en tu navegador? Tu computadora envía una petición a un servidor web, que la procesa y te devuelve una respuesta. Node.js te permite ser tanto el cliente como el servidor en esta conversación, gracias a sus módulos http y https integrados.

    Imagina que los módulos HTTP y HTTPS son como dos líneas telefónicas:
    - HTTP: una línea abierta, cualquiera puede escuchar lo que dices (insegura, puerto 80)
    - HTTPS: una línea encriptada, solo tú y la otra persona pueden entender la conversación (segura, puerto 443)

    Ambas líneas funcionan de la misma manera en cuanto a estructura y protocolo, pero HTTPS añade una capa de seguridad mediante certificados TLS/SSL. Y lo mejor: no necesitas instalar nada, estos módulos vienen incluidos en Node.js.

    Propósito fundamental

    Los módulos http y https permiten:
    - Crear servidores web sin dependencias externas como Apache o Nginx
    - Realizar peticiones HTTP/HTTPS a otros servidores
    - Trabajar directamente con el protocolo, sin abstracción
    - Integrar con componentes del sistema operativo mediante streams y eventos

    Importación moderna (node:)

    En Node.js moderno, la forma recomendada de importar es usar el prefijo node::

    // CommonJS
const http = require('node:http');
const https = require('node:https');
const fs = require('node:fs');

// ES Modules (moderno, recomendado)
import http from 'node:http';
import https from 'node:https';
import fs from 'node:fs';
import type { IncomingMessage, ServerResponse } from 'node:http';

    ¿Por qué node: es importante?

    El prefijo node: es una característica introducida en Node.js 14.18.0 que hace explícito que estás importando un módulo core de Node.js. Esto mejora la claridad del código y facilita herramientas de análisis estático.

    Arquitectura EventEmitter e integración con el Event Loop

    Los servidores HTTP en Node.js heredan de EventEmitter, lo que significa que todo funciona mediante eventos. El servidor no está bloqueado esperando peticiones; en su lugar, escucha eventos en el Event Loop y reacciona cuando llega una petición.

    Modelo Cliente–Servidor y fundamentos HTTP

    Antes de crear servidores, es crucial entender cómo funciona la comunicación HTTP. El protocolo HTTP define un patrón de solicitud-respuesta basado en un modelo cliente-servidor donde el cliente siempre inicia la conversación.

    Rol del servidor y del cliente

    Componente Rol Ejemplo
    Cliente Inicia la conexión, envía solicitudes Navegador web, aplicación móvil
    Servidor Escucha en un puerto, responde solicitudes Tu aplicación Node.js
    Red Transporta datos entre ambos Internet, protocolo TCP/IP

    El Corazón de la Comunicación: http vs https

    Característica Módulo http Módulo https
    Protocolo HTTP (HyperText Transfer Protocol) HTTPS (HTTP Secure)
    Cifrado No cifrado (datos viajan en texto plano) Cifrado mediante TLS/SSL
    Puerto por Defecto 80 443
    Uso Principal Desarrollo local, pruebas, microservicios internos (intranet) Producción, cualquier comunicación que maneje datos sensibles (credenciales, pagos)

    ¡Alerta de Seguridad!

    Nunca utilices el módulo http para desplegar un servidor en producción que maneje datos de usuarios o información sensible. La información viaja sin cifrar y es vulnerable a ataques de tipo Man-in-the-Middle.

    Ciclo completo Request → Processing → Response

    La comunicación HTTP sigue un ciclo de vida bien definido:

    1. Request (Solicitud): El cliente (ej. Chrome) envía un mensaje al servidor. Este mensaje incluye:
      • Método HTTP (GET, POST, PUT, DELETE, etc.).
      • URL del recurso solicitado.
      • Cabeceras (metadatos sobre la solicitud, como el tipo de navegador o la autenticación).
      • Cuerpo (Body) de la solicitud (para métodos como POST o PUT).
    2. Processing (Procesamiento): El servidor recibe la solicitud, la analiza, ejecuta la lógica de negocio (ej. consulta a una base de datos, cálculo) y prepara el resultado.
    3. Response (Respuesta): El servidor envía un mensaje de vuelta al cliente. Este mensaje incluye:
      • Código de Estado HTTP (ej. 200 OK, 404 Not Found, 500 Internal Server Error).
      • Cabeceras de Respuesta (metadatos sobre la respuesta, como el tipo de contenido).
      • Cuerpo (Body) de la respuesta (el contenido real: HTML, JSON, etc.).

    Comunicación stateless

    HTTP es stateless: cada solicitud es completamente independiente. El servidor no "recuerda" nada entre una petición y la siguiente, a menos que uses mecanismos como:

    • Cookies: Pequeños archivos de texto almacenados en el cliente
    • Sesiones: Datos almacenados en el servidor, identificados por una cookie
    • Tokens: Como JWT, donde el cliente envía credenciales en cada petición
    // Ejemplo: sin sesión, cada petición es nueva
GET /usuarios → Server responde usuarios (no recuerda quién eres)
GET /usuarios → Server responde usuarios (nuevamente, olvida la solicitud anterior)

// Con sesión/token:
GET /login → Server crea sesión/token
GET /usuarios?session=abc123 → Server verifica sesión y responde

    Versiones del protocolo: HTTP/1.1 vs HTTP/2

    Aspecto HTTP/1.1 HTTP/2
    Multiplexing Una solicitud por conexión Múltiples solicitudes simultáneas
    Compresión de headers No (usa más ancho de banda) Sí (HPACK)
    Push server No Sí, servidor envía recursos no solicitados
    Compatibilidad Amplia, legacy Moderno, navegadores nuevos
    Default en Node.js http Sí No, usa https solo

    HTTP/2 en Node.js

    Los módulos http y https de Node.js soportan HTTP/1.1 por defecto. Para HTTP/2, debes usar require('node:http2'), que tiene una API diferente. En esta lección nos enfocamos en HTTP/1.1, que sigue siendo el estándar.


    Creación de un servidor HTTP básico

    Ahora que comprendes la teoría, vamos a crear tu primer servidor HTTP. Este servidor será sencillo: responderá "Hola Mundo" a cualquier petición.

    http.createServer() y el callback de solicitud

    import http from 'node:http';

// Paso 1: Crear el servidor
const server = http.createServer((req, res) => {
  // req: objeto IncomingMessage (es una Readable stream)
  // res: objeto ServerResponse (es una Writable stream)

  // Paso 2: Configurar la respuesta
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });

  // Paso 3: Enviar el cuerpo de la respuesta
  res.end('¡Hola, Mundo desde Node.js!');
});

// Paso 4: Escuchar en un puerto
server.listen(3000, 'localhost', () => {
  console.log('Servidor ejecutándose en http://localhost:3000');
});

    ¿Qué ocurre aquí?

    1. http.createServer() crea un objeto http.Server
    2. La función callback se ejecuta cada vez que un cliente envía una solicitud
    3. res.writeHead(statusCode, headers) establece el código HTTP (200 = OK) y los headers
    4. res.end(data) envía el cuerpo y cierra la respuesta (obligatorio)
    5. server.listen(puerto, host, callback) pone el servidor a escuchar

    Ahora pruébalo: 

    # Terminal 1: ejecuta tu servidor
node servidor.ts

# Terminal 2: prueba el servidor
curl http://localhost:3000
# Salida: ¡Hola, Mundo desde Node.js!

    server.listen() y parámetros clave

    // Sintaxis completa de server.listen()
server.listen(
  port,              // número: puerto TCP (0-65535, típicamente 1024+)
  hostname,          // string: dirección IP o 'localhost'
  backlog,           // número: cola de conexiones pendientes (defecto: 511)
  callback           // función: se ejecuta cuando empieza a escuchar
);

// Variantes comunes:
server.listen(3000);                           // Escucha en 0.0.0.0:3000
server.listen(3000, 'localhost');              // Solo localhost (seguro en desarrollo)
server.listen(3000, '0.0.0.0');                // Todas las interfaces de red
server.listen({ port: 3000, host: '127.0.0.1' }); // Objeto de opciones
    Parámetro Significado Ejemplo
    port Puerto TCP donde escucha el servidor 3000, 8080, 80 (requiere sudo)
    hostname Dirección IP o nombre 'localhost' (127.0.0.1), '0.0.0.0'
    backlog Conexiones pendientes en cola 511 (suficiente para desarrollo)
    callback Se ejecuta cuando está listo Mostrar un log de confirmación

    Elegir un puerto

    • Puertos 1-1023: reservados, requieren permisos de administrador
    • Puertos 1024+: puedes usar como usuario normal
    • 3000, 8080: populares para desarrollo
    • Evita puertos en uso: netstat -tuln | grep LISTEN (Unix) o netstat -ano | findstr :3000 (Windows)

    Manejo básico de errores y eventos del servidor

    import http from 'node:http';

const server = http.createServer((req, res) => {
  try {
    // Tu lógica aquí
    res.writeHead(200);
    res.end('OK');
  } catch (err) {
    res.writeHead(500);
    res.end('Error interno');
  }
});

// Manejar errores del servidor
server.on('error', (err: NodeJS.ErrnoException) => {
  if (err.code === 'EADDRINUSE') {
    console.error(`Puerto 3000 ya está en uso`);
  } else {
    console.error('Error del servidor:', err);
  }
});

// Manejar cierre ordenado (graceful shutdown)
process.on('SIGTERM', () => {
  console.log('Cerrando servidor...');
  server.close(() => {
    console.log('Servidor cerrado');
    process.exit(0);
  });
});

server.listen(3000, () => {
  console.log('Servidor listo en puerto 3000');
});

    Ejemplo de servidor robusto:

    import http from 'node:http';
import type { IncomingMessage, ServerResponse } from 'node:http';

const PORT = process.env.PORT || 3000;
const HOST = process.env.HOST || 'localhost';

function requestListener(req: IncomingMessage, res: ServerResponse): void {
  // Registrar solicitud
  console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);

  // Enrutamiento simple
  if (req.url === '/' && req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>Bienvenido a mi servidor</h1>');
  } else if (req.url === '/api/health' && req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ status: 'ok', timestamp: Date.now() }));
  } else {
    res.writeHead(404, { 'Content-Type': 'text/plain' });
    res.end('No encontrado');
  }
}

const server = http.createServer(requestListener);

server.on('error', (err: NodeJS.ErrnoException) => {
  console.error('Error del servidor:', err.message);
  process.exit(1);
});

server.listen(PORT, String(HOST), () => {
  console.log(`✓ Servidor ejecutándose en http://${HOST}:${PORT}`);
});

// Cierre ordenado al recibir SIGTERM o SIGINT
process.on('SIGTERM', () => {
  console.log('\nCerrando servidor gracefully...');
  server.close(() => {
    console.log('Servidor cerrado');
    process.exit(0);
  });
});

    Creación de un servidor HTTPS

    HTTPS (HTTP Secure) es idéntico a HTTP, excepto que encripta toda la comunicación mediante TLS/SSL. Esto protege los datos de ser interceptados.

    El módulo https y diferencias con http

    import https from 'node:https';
import fs from 'node:fs';

// La API es casi idéntica, pero requiere opciones de certificado
const options = {
  // key: contenido de la clave privada
  key: fs.readFileSync('ruta/a/server-key.pem'),
  // cert: contenido del certificado
  cert: fs.readFileSync('ruta/a/server-cert.pem'),
};

const server = https.createServer(options, (req, res) => {
  res.writeHead(200);
  res.end('Conexión HTTPS segura');
});

server.listen(443);  // Puerto HTTPS estándar
    Aspecto HTTP HTTPS
    Puerto 80 443
    Encriptación No TLS/SSL
    Certificado No necesario Obligatorio
    Performance Muy rápido Ligeramente más lento (encriptación)
    Seguridad Baja Alta

    Certificados autofirmados para desarrollo

    Para desarrollo, puedes crear un certificado autofirmado que no requiere autoridad certificadora:

    # Generar certificado autofirmado válido por 365 días
openssl req -x509 -newkey rsa:2048 -nodes -sha256 \
  -subj '/CN=localhost' \
  -keyout server-key.pem \
  -out server-cert.pem \
  -days 365

    Manejo de JSON, formularios y uploads

    import http from 'node:http';

function handleRequest(req: http.IncomingMessage, res: http.ServerResponse): void {
  let body = '';
  const chunks: Buffer[] = [];

  // Recolectar datos del body
  req.on('data', (chunk: Buffer) => {
    chunks.push(chunk);
    // Control de tamaño: evitar DoS
    if (chunks.reduce((acc, b) => acc + b.length, 0) > 1e6) {
      req.destroy(); // Destruir si supera 1MB
    }
  });

  req.on('end', () => {
    const contentType = req.headers['content-type'] || '';

    // TIPO 1: JSON
    if (contentType.includes('application/json')) {
      try {
        const json = JSON.parse(Buffer.concat(chunks).toString('utf-8'));
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ tipo: 'JSON', datos: json }));
      } catch {
        res.writeHead(400);
        res.end('JSON inválido');
      }
    }
    // TIPO 2: Form URL-encoded
    else if (contentType.includes('application/x-www-form-urlencoded')) {
      const params = new URLSearchParams(Buffer.concat(chunks).toString());
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({
        tipo: 'Form',
        datos: Object.fromEntries(params),
      }));
    }
    // TIPO 3: Texto plano
    else if (contentType.includes('text/plain')) {
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({
        tipo: 'Texto',
        datos: Buffer.concat(chunks).toString('utf-8'),
      }));
    }
    // TIPO 4: Multipart (archivos)
    else if (contentType.includes('multipart/form-data')) {
      // Para archivos, normalmente usarías una librería como 'busboy'
      // Por ahora, solo detectamos el tipo
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(JSON.stringify({ tipo: 'Multipart/Upload', tamaño: Buffer.concat(chunks).length }));
    }
    else {
      res.writeHead(415); // Unsupported Media Type
      res.end('Tipo de contenido no soportado');
    }
  });
}

const server = http.createServer(handleRequest);
server.listen(3000);

    Seguridad y límites de tamaño (backpressure)

    Un concepto crucial en streams es la backpressure (contrapresión). Si los datos llegan más rápido de lo que los procesas, pueden saturar la memoria:

    import http from 'node:http';
import fs from 'node:fs';

const server = http.createServer((req, res) => {
  // Escribir a un archivo de forma segura respetando backpressure
  const writeStream = fs.createWriteStream('/tmp/upload.bin');

  // Si escribes sin esperar, y el stream está lleno, acumula en memoria
  req.on('data', (chunk: Buffer) => {
    // Opción 1: Hacerlo de forma segura
    const canContinue = writeStream.write(chunk);

    if (!canContinue) {
      console.log('Buffer lleno, pausando lectura');
      req.pause(); // Detener recepción de datos
    }
  });

  // Cuando el stream está vacío, reanudar lectura
  writeStream.on('drain', () => {
    console.log('Buffer drenado, reanudando lectura');
    req.resume();
  });

  // Opción 2: Usar pipe (maneja backpressure automáticamente)
  // req.pipe(writeStream);

  req.on('end', () => {
    res.writeHead(200);
    res.end('Archivo guardado');
  });

  req.on('error', (err) => {
    console.error('Error:', err);
    writeStream.destroy();
  });

  writeStream.on('error', (err) => {
    console.error('Error escritura:', err);
    res.writeHead(500);
    res.end('Error al guardar');
  });
});

    Manejo de respuestas (Response – ServerResponse)

    El objeto res (de tipo ServerResponse) es nuestra herramienta para comunicarnos de vuelta con el cliente. Es un Stream escribible (Writable Stream), lo que nos permite enviar datos en trozos, aunque en la mayoría de los casos de API se usa para enviar la respuesta final de una sola vez.

    Envío de Respuestas y Flujo (write, end)

    El flujo de respuesta sigue estos pasos:

    1. res.writeHead(statusCode, headers): (Opcional, pero recomendado) Escribe las cabeceras de la respuesta y el código de estado. Si no se llama, Node.js lo hace automáticamente con 200 OK cuando se llama a res.end() o res.write() por primera vez.
    2. res.write(chunk): Envía un trozo del cuerpo de la respuesta. Se puede llamar múltiples veces.
    3. res.end(data): Finaliza la respuesta. Es obligatorio llamarlo. Si se le pasa un argumento, ese dato se envía como el último trozo del cuerpo.

    Error Común

    Si olvidas llamar a res.end(), el cliente se quedará esperando la respuesta indefinidamente, lo que resultará en un timeout (tiempo de espera agotado) y una mala experiencia de usuario.

    Estados HTTP (statusCode, statusMessage)

    El código de estado HTTP es crucial, ya que indica el resultado de la operación al cliente.

    Tabla 6.1: Códigos de Estado HTTP Esenciales

    Rango Significado Ejemplos Clave Uso en Node.js (res.writeHead)
    1xx Informativo 100 Continue Raro en el servidor, más para proxies.
    2xx Éxito 200 OK, 201 Created, 204 No Content Operación exitosa.
    3xx Redirección 301 Moved Permanently, 307 Temporary Redirect Mover al cliente a otra URL.
    4xx Error del Cliente 400 Bad Request, 401 Unauthorized, 404 Not Found El cliente cometió un error (ej. URL incorrecta, datos inválidos).
    5xx Error del Servidor 500 Internal Server Error, 503 Service Unavailable El servidor falló al procesar la petición.

    Streaming de respuestas (archivos, datos grandes)

    Para enviar archivos grandes (ej. un video o un archivo ZIP), es fundamental usar el streaming de respuesta. Esto evita cargar todo el archivo en la memoria del servidor antes de enviarlo.

    Podemos "conectar" un Readable Stream (el archivo) directamente a nuestro Writable Stream (res) usando el método pipe().

    import http from 'node:http';
import fs from 'node:fs';
import path from 'node:path';

const server = http.createServer((req, res) => {
  // OPCIÓN 1: pipe() - La forma elegante y eficiente
  if (req.url === '/descargar') {
    const filePath = path.join(__dirname, 'archivo-grande.zip');

    // Verificar que el archivo existe
    if (!fs.existsSync(filePath)) {
      res.writeHead(404);
      res.end('Archivo no encontrado');
      return;
    }

    // Headers para descarga
    const stat = fs.statSync(filePath);
    res.writeHead(200, {
      'Content-Type': 'application/octet-stream',
      'Content-Length': stat.size,
      'Content-Disposition': `attachment; filename="${path.basename(filePath)}"`,
    });

    // Usar pipe para streaming eficiente
    fs.createReadStream(filePath).pipe(res);
  }
  // OPCIÓN 2: Video en streaming (range requests)
  else if (req.url === '/video') {
    const videoPath = path.join(__dirname, 'video.mp4');
    const stat = fs.statSync(videoPath);

    res.writeHead(200, {
      'Content-Type': 'video/mp4',
      'Content-Length': stat.size,
    });

    fs.createReadStream(videoPath).pipe(res);
  }
  // OPCIÓN 3: Datos generados en tiempo real
  else if (req.url === '/stream-datos') {
    res.writeHead(200, {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
    });

    // Enviar datos periódicamente
    let contador = 0;
    const intervalo = setInterval(() => {
      res.write(`data: Mensaje ${++contador}\n\n`);
      if (contador >= 10) {
        clearInterval(intervalo);
        res.end();
      }
    }, 1000);

    // Si el cliente cierra, limpiar
    req.on('close', () => {
      clearInterval(intervalo);
    });
  }
});

    const datos = JSON.stringify({ datos: Array(1000).fill('contenido') });

    // Verificar si el cliente soporta gzip
    const acceptEncoding = req.headers['accept-encoding'] || '';

    res.setHeader('Vary', 'Accept-Encoding');

    if (acceptEncoding.includes('gzip')) {
      res.writeHead(200, {
        'Content-Type': 'application/json',
        'Content-Encoding': 'gzip',
      });
      zlib.gzip(Buffer.from(datos), (err, compressed) => {
        if (err) {
          res.writeHead(500);
          res.end('Error de compresión');
        } else {
          res.end(compressed);
        }
      });
    } else {
      // Sin compresión
      res.writeHead(200, { 'Content-Type': 'application/json' });
      res.end(datos);
    }
  }
});

    Routing manual básico

    import http from 'node:http';
import { URL } from 'node:url';

interface Route {
  method: string;
  path: string;
  handler: (req: http.IncomingMessage, res: http.ServerResponse) => void;
}

class Router {
  private routes: Route[] = [];

  register(method: string, path: string, handler: Route['handler']): void {
    this.routes.push({ method, path, handler });
  }

  handle(req: http.IncomingMessage, res: http.ServerResponse): void {
    const url = new URL(req.url || '/', `http://${req.headers.host}`);

    for (const route of this.routes) {
      if (req.method === route.method && url.pathname === route.path) {
        return route.handler(req, res);
      }
    }

    // 404
    res.writeHead(404);
    res.end('No encontrado');
  }
}

// Uso
const router = new Router();

router.register('GET', '/', (req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/html' });
  res.end('<h1>Inicio</h1>');
});

router.register('GET', '/api/usuarios', (req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify([{ id: 1, nombre: 'Juan' }]));
});

router.register('POST', '/api/usuarios', (req, res) => {
  let body = '';
  req.on('data', (chunk) => { body += chunk; });
  req.on('end', () => {
    const usuario = JSON.parse(body);
    res.writeHead(201, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ id: 2, ...usuario }));
  });
});

const server = http.createServer((req, res) => {
  router.handle(req, res);
});

server.listen(3000, () => {
  console.log('Router listo en puerto 3000');
});

    Seguridad básica (prevención de DoS, validación)

    import http from 'node:http';

const MAX_BODY_SIZE = 1e6;        // 1MB máximo
const MAX_REQUESTS_PER_MINUTE = 100;
const requestLimiter = new Map<string, number[]>();

function getRateLimitKey(req: http.IncomingMessage): string {
  return req.socket.remoteAddress || 'unknown';
}

function isRateLimited(req: http.IncomingMessage): boolean {
  const key = getRateLimitKey(req);
  const now = Date.now();
  const oneMinuteAgo = now - 60000;

  if (!requestLimiter.has(key)) {
    requestLimiter.set(key, [now]);
    return false;
  }

  const timestamps = requestLimiter.get(key)!;
  const recentRequests = timestamps.filter((t) => t > oneMinuteAgo);

  if (recentRequests.length >= MAX_REQUESTS_PER_MINUTE) {
    return true;
  }

  recentRequests.push(now);
  requestLimiter.set(key, recentRequests);
  return false;
}

const server = http.createServer((req, res) => {
  // PROTECCIÓN 1: Rate limiting
  if (isRateLimited(req)) {
    res.writeHead(429, { 'Retry-After': '60' });
    res.end('Demasiadas solicitudes');
    return;
  }

  // PROTECCIÓN 2: Validar método
  const allowedMethods = ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'];
  if (!allowedMethods.includes(req.method!)) {
    res.writeHead(405);
    res.end('Método no permitido');
    return;
  }

  // PROTECCIÓN 3: Límite de tamaño
  const contentLength = parseInt(req.headers['content-length'] || '0');
  if (contentLength > MAX_BODY_SIZE) {
    res.writeHead(413);
    res.end('Cuerpo demasiado grande');
    return;
  }

  // PROTECCIÓN 4: Validar URL
  if (req.url!.length > 2048) {
    res.writeHead(414);
    res.end('URL demasiada larga');
    return;
  }

  res.writeHead(200);
  res.end('OK');
});

server.listen(3000);
