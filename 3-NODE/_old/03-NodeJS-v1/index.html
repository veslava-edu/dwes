    Node.js: El Motor del Backend con TypeScript

    Node.js Environment

    Browser vs Node.js

    Aunque el lenguaje base es el mismo (JavaScript), el ecosistema donde vive es radicalmente opuesto. Es como saber hablar inglés: te sirve tanto en Londres (Navegador) como en Nueva York (Servidor), pero las leyes y las costumbres son diferentes.

    En el Navegador, tu preocupación principal es la interfaz de usuario, el DOM y la compatibilidad visual. En Node.js, tu prioridad es el sistema operativo, la red y el acceso a datos.

    Diferencias Clave

    Característica Navegador (Browser) Node.js (Servidor)
    Acceso al Sistema Restringido (Sandbox). No puede leer tus archivos locales por seguridad. Total. Puede leer, escribir y borrar archivos del SO (fs).
    Objeto Global window / document global / process. No existe el DOM.
    Fragmentación Debes soportar Chrome, Firefox, Safari (Babel/Polyfills). Tú controlas la versión exacta de Node.js donde corre tu código.
    Módulos ES Modules (reciente) o Bundlers (Webpack/Vite). CommonJS (histórico) y ES Modules (moderno).

    Ejemplos de Código (TypeScript)

    Ejemplo 1: Intentando acceder al DOM en Node (Error Común) 

    // archivo: error-dom.ts
// ❌ Esto fallará en Node.js
try {
  const titulo = document.getElementById('app');
  alert('Hola mundo');
} catch (error) {
  console.error('¡Error! En Node.js no existe "document" ni "alert".');
  // Output: ReferenceError: document is not defined
}

    Ejemplo 2: Acceso al Sistema Operativo (Exclusivo de Node) 

    // archivo: info-sistema.ts
import * as os from 'os';

// ✅ Esto funciona perfectamente en Node.js
const memoriaLibre = os.freemem();
console.log(`Memoria libre en el servidor: ${memoriaLibre / 1024 / 1024} MB`);

    2. ¿Qué ventaja tiene controlar la versión de Node.js en el servidor frente a la incertidumbre del navegador del usuario?
    3. ¿Por qué crees que Node.js se hizo tan popular para aplicaciones de tiempo real (chats, streaming) frente a tecnologías como PHP clásico?


    El REPL de Node.js (terminal interactiva)

    El REPL (Read-Eval-Print-Loop) es como la consola de desarrollador de Chrome, pero en tu terminal. Es ideal para probar pequeños fragmentos de lógica sin crear archivos.

    Para entrar, simplemente abre tu terminal y escribe node.

    Consejo Pro: REPL con TypeScript

    Por defecto, el comando node espera JavaScript. Si quieres probar código TypeScript directamente en una terminal interactiva, puedes instalar y usar ts-node (aunque en producción siempre compilaremos). Comando: npx ts-node

    Tabla: Comandos útiles del REPL

    Comando Descripción
    .help Muestra la ayuda de comandos.
    .editor Entra en modo editor para escribir funciones multilínea cómodamente.
    .break Sale de una expresión multilínea en curso.
    .exit o Ctrl+D Cierra la sesión del REPL.
    _ (guion bajo) Obtiene el resultado de la última operación ejecutada.

    Ejemplo de sesión REPL

    $ node
> const saludo = "Hola DAW";
undefined
> 10 + 20
30
> _ + 5  // El guion bajo toma el 30 anterior
35
> .exit

    Preguntas Reflexivas

    1. ¿En qué escenario laboral usarías el REPL en lugar de escribir un script en VS Code?
    2. ¿Cómo accederías al historial de comandos que escribiste en una sesión anterior del REPL?
    3. Si defines una variable con const en el REPL, ¿puedes redefinirla? ¿Por qué?


    Objectos Globales

    En el navegador, el rey es window. Todo cuelga de él. En Node.js, window no existe. Tenemos global. Sin embargo, hay variables que parecen globales pero son específicas de cada módulo (archivo), y otras que son verdaderamente globales.

    Cuidado con 'this'

    En el nivel superior de un archivo Node.js (CommonJS), this es module.exports, no el objeto global. En el REPL, this sí es el objeto global. ¡Confuso al principio!

    Variables Globales y "Pseudo-Globales" Importantes

    Variable Tipo Descripción Disponibilidad
    global Objeto El equivalente a window. Contiene métodos como setTimeout, console. Verdaderamente Global
    process Objeto Información sobre el proceso actual (env vars, argumentos). Verdaderamente Global
    __dirname String Ruta absoluta al directorio del archivo actual. Solo en CommonJS
    __filename String Ruta absoluta al archivo actual (incluye nombre). Solo en CommonJS
    module Objeto Referencia al módulo actual (usado para exportar). Solo en CommonJS

    Nota sobre TypeScript y ES Modules: Si configuras tu proyecto TypeScript para usar ES Modules modernos (lo recomendado hoy día), __dirname y __filename dejan de existir. Debemos recrearlos.

    Ejemplos de Código (TypeScript)

    Ejemplo 1: Usando process y console (Globales) 

    // global-demo.ts
// No hace falta importar 'process' ni 'console'
console.log(`Estás ejecutando Node versión: ${process.version}`);
console.log(`Tu usuario de sistema es: ${process.env.USER || process.env.USERNAME}`);

// Tip: setTimeout también es global
setTimeout(() => {
  console.log('Han pasado 2 segundos en el servidor.');
}, 2000);

    Ejemplo 2: __dirname en Modern TypeScript (ESM) Como __dirname no existe en ES Modules, usamos import.meta.url.

    // path-moderno.ts
import { fileURLToPath } from 'url';
import { dirname } from 'path';

// Recreando __dirname y __filename
const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

console.log(`Directorio actual: ${__dirname}`);
console.log(`Archivo actual: ${__filename}`);

    3. Investiga: ¿Qué es globalThis y por qué se introdujo recientemente?


    Primer programa con Node.js

    Vamos a crear un "Hola Mundo" vitaminado. Usaremos TypeScript, por lo que necesitaremos un paso de transpilación.

    Flujo de Trabajo Profesional

    1. Escribir código en .ts.
    2. Compilar con tsc (TypeScript Compiler) -> genera .js.
    3. Ejecutar con node el archivo .js.

    Configuración Mínima

    Necesitas un archivo tsconfig.json. Ejecuta npx tsc --init para crearlo.

    Ejemplos de Código

    Ejemplo 1: El Código (index.ts) 

    // index.ts
interface Usuario {
  id: number;
  nombre: string;
  admin: boolean;
}

const usuarios: Usuario[] = [
  { id: 1, nombre: 'Ana', admin: true },
  { id: 2, nombre: 'Carlos', admin: false }
];

function saludarAdmin(users: Usuario[]): void {
  const admins = users.filter(u => u.admin);
  console.table(admins); // ¡console.table es genial en Node!
  console.log(`¡Servidor listo! Detectados ${admins.length} administradores.`);
}

saludarAdmin(usuarios);

    Ejemplo 2: Ejecución (Terminal) 

    # Opción A: Tradicional (Producción)
$ npx tsc index.ts   # Genera index.js
$ node index.js      # Ejecuta el JS

# Opción B: Desarrollo Rápido (ts-node)
$ npx ts-node index.ts

    Preguntas Reflexivas

    1. ¿Qué ocurre si intentas ejecutar node index.ts directamente sin ts-node?
    2. ¿Por qué en un servidor de producción se prefiere ejecutar el .js compilado en lugar de usar ts-node?
    3. Modifica el programa para que lea un argumento desde la terminal (pista: process.argv).


    Módulos en Node.js

    Crear un módulo

    En el desarrollo profesional, dividir es vencer. No escribimos todo el código en un fichero index.ts de 5000 líneas. Usamos módulos. Un módulo en Node.js es simplemente un archivo JavaScript/TypeScript que encapsula una funcionalidad específica y expone solo lo que quiere que otros vean (Interfaz Pública).

    Es como una cocina de restaurante: - Tu módulo: La estación de postres. - Lo privado: Tus recetas secretas, ingredientes sucios. - Lo público (export): El pastel terminado.

    Tipos de Sistemas de Módulos

    1. CommonJS (CJS): El clásico de Node. Usa require y module.exports. Síncrono.
    2. ES Modules (ESM): El estándar oficial de JavaScript y TypeScript. Usa import y export. Asíncrono y estático.

    Nos enfocaremos en cómo TypeScript maneja esto, priorizando ESM pero entendiendo CJS.


    Exportar e importar (module.exports y require)

    Aunque TypeScript prefiere import/export, en el mundo laboral encontrarás mucho código legado (legacy) o configuraciones específicas que usan CommonJS.

    Importante

    Para que TypeScript compile a CommonJS (y use require por debajo), tu tsconfig.json debe tener "module": "commonjs".

    Tabla Comparativa: CJS vs ESM

    Característica CommonJS (Legacy Node) ES Modules (Moderno TS/JS)
    Sintaxis Export module.exports = ... export const ... / export default
    Sintaxis Import const x = require('./x') import x from './x'
    Carga Síncrona (bloqueante) Asíncrona
    Uso principal Scripts antiguos, herramientas de build. Frontend moderno, Node.js actual, Deno.

    Diagrama de Carga de Módulos

    graph LR
    A[main.ts] -- require('./utils') --> B(Busca utils.ts/.js)
    B -- Lee archivo --> C{¿Tiene caché?}
    C -- Sí --> D[Devuelve exports de caché]
    C -- No --> E[Ejecuta código del módulo]
    E --> F[Guarda en caché]
    F --> G[Devuelve module.exports]

    Ejemplos de Código (Estilo CommonJS en TS)

    Ejemplo 1: Exportando (math.ts) 

    // math.ts
const PI = 3.1416; // Privado

function sumar(a: number, b: number): number {
    return a + b;
}

function restar(a: number, b: number): number {
    return a - b;
}

// Sintaxis CommonJS clásica
module.exports = {
    sumar,
    restar
    // PI no se exporta, es privada
};

    Ejemplo 2: Importando con require (app.ts) 

    // app.ts
// TypeScript nos permite usar require si declaramos los tipos o usamos una sintaxis especial:
// import x = require('./x') es la forma "TypeScript-ish" de hacerlo para CJS.
import operaciones = require('./math');

const resultado = operaciones.sumar(5, 10);
console.log(`Resultado: ${resultado}`);

    Preguntas Reflexivas

    1. ¿Qué significa que require sea síncrono? ¿Cómo afecta eso al inicio de tu servidor?
    2. ¿Qué sucede si dos archivos se hacen require mutuamente (referencia circular)?
    3. Si cambias el valor de una variable exportada en el módulo origen, ¿cambia en el destino? (Pista: Primitivos vs Objetos).


    Configuración necesaria para habilitar ES Modules

    Para usar la sintaxis moderna (estándar en TypeScript y en la industria actual) y que Node.js la interprete nativamente como ESM, debemos configurar el entorno.

    1. En package.json: Añadir "type": "module".
    2. En tsconfig.json:
      • "target": ES2020 (o superior).
      • "module": NodeNext o ESNext.
      • "moduleResolution": NodeNext.

    Esto le dice a Node: "Oye, trátame los archivos .js (resultado de compilar TS) como módulos modernos, no como CommonJS antiguo".

    Exportar varios elementos

    En ES Modules (la forma preferida en TypeScript), tenemos dos formas de exportar: Named Exports (Exportaciones Nombradas) y Default Exports (Exportación por Defecto).

    Buenas Prácticas

    Google Style Guide y la comunidad TS prefieren Named Exports. Hacen que el refactoring sea más fácil y el autocompletado del IDE más preciso. Evita export default si puedes.

    Ejemplos de Código (Sintaxis ESM)

    Ejemplo 1: Exportaciones Nombradas (Recomendado) 

    // utils/text-helpers.ts

export const mayusculas = (str: string): string => str.toUpperCase();

export const minusculas = (str: string): string => str.toLowerCase();

export const CAPACIDAD_MAXIMA = 100;

    Ejemplo 2: Importando Varios Elementos 

    // main.ts
// Notad la extensión .js obligatoria si usamos "type": "module" en Node puro
import { mayusculas, CAPACIDAD_MAXIMA } from './utils/text-helpers.js';

console.log(mayusculas('hola daw'));
console.log(`Capacidad: ${CAPACIDAD_MAXIMA}`);

    Preguntas Reflexivas

    1. ¿Cuál es la ventaja de tener que usar las llaves { } al importar?
    2. ¿Se pueden renombrar las exportaciones al importarlas para evitar conflictos de nombres? (Ej: import { suma as sumaTotal } ...)
    3. ¿Qué ocurre si intentas importar algo que no ha sido exportado?


    Sintaxis de desestructuración y require

    Volviendo un momento a CommonJS (o al interoperar con librerías antiguas). Cuando hacemos require('modulo'), obtenemos un objeto gigante. A menudo solo queremos una pieza. Aquí entra la Desestructuración (Destructuring) de JavaScript.

    Es como pedir una pizza entera pero solo poner en tu plato una porción de pepperoni.

    Diagrama de Secuencia: Desestructuración

    sequenceDiagram
    participant Main as "Archivo Principal"
    participant Modulo as "Módulo 'fs'"

    Note over Main, Modulo: Sin Desestructuración
    Main->>Modulo: const fs = require('fs')
    Modulo-->>Main: Devuelve objeto { readFile, writeFile, ... }
    Main->>Main: Uso: fs.readFile()

    Note over Main, Modulo: Con Desestructuración
    Main->>Modulo: const { readFile } = require('fs')
    Modulo-->>Main: Devuelve objeto completo
    Main->>Main: Extrae SOLO 'readFile'
    Main->>Main: Uso: readFile()

    Ejemplos de Código

    Ejemplo 1: CommonJS con Desestructuración 

    // legacy-code.ts
// Imaginemos que usamos una librería vieja sin tipos ESM
// Importamos TODO el objeto
const path = require('path');
console.log(path.join('a', 'b'));

// VS

// Desestructuramos directamente
const { join, resolve } = require('path');
console.log(join('carpeta', 'archivo.txt'));

    Ejemplo 2: Desestructuración en Imports (ESM) Aunque técnicamente en ESM se llama "Named Imports", la sintaxis visual es idéntica a la desestructuración de objetos.

    // modern-code.ts
import { arch } from 'os'; // Extraemos solo 'arch' del módulo 'os'

console.log(`Arquitectura del CPU: ${arch()}`);

    Preguntas Reflexivas

    1. ¿Mejora el rendimiento la desestructuración o es solo azúcar sintáctico (syntactic sugar)?
    2. ¿Cómo harías desestructuración si la propiedad se llama class (palabra reservada)?
    3. ¿Es posible desestructurar en niveles profundos? Ej: const { data: { id } } = require('./config').


    Módulos principales de Node.js

    Node.js viene con una "navaja suiza" de módulos incorporados (Core Modules). No necesitas instalar nada con NPM para usarlos. Son la base de todo.

    El módulo console

    Mucho más que console.log. Es tu herramienta principal de depuración y salida estándar.

    Métodos Avanzados

    Método Uso Ejemplo
    console.log Salida estándar (stdout). Info general.
    console.error Salida de error (stderr). Errores críticos.
    console.table Muestra arrays/objetos como tabla. Listados de datos.
    console.time / timeEnd Mide el tiempo de ejecución. Performance testing.
    console.trace Muestra la pila de llamadas (stack trace). ¿Quién llamó a esta función?

    Ejemplos de Código

    Ejemplo 1: Midiendo Performance 

    // benchmark.ts
console.time('Bucle Gigante');

let suma = 0;
for(let i=0; i<1000000; i++) {
    suma += i;
}

console.timeEnd('Bucle Gigante'); 
// Output: Bucle Gigante: 2.45ms

    Ejemplo 2: Depuración Visual 

    // debug.ts
const alumnos = [
    { nombre: 'Lucía', nota: 9 },
    { nombre: 'Marcos', nota: 4 }
];

// Mucho mejor que un JSON stringify
console.table(alumnos);


    El módulo process

    process es el puente entre tu código y el proceso del sistema operativo que lo está ejecutando. Es fundamental para la configuración de entornos (Dev vs Prod).

    Funcionalidades Clave

    • Variables de Entorno (process.env): Para guardar contraseñas, claves API y puertos sin escribirlos en el código ("hardcode").
    • Argumentos (process.argv): Leer inputs desde la línea de comandos.
    • Salida (process.exit): Terminar el programa (0 = éxito, 1 = error).

    Ejemplos de Código

    Ejemplo 1: Leyendo el Entorno 

    // config.ts
// Ejecutar en terminal: PORT=3000 node dist/config.js

const PUERTO = process.env.PORT || 8080; // Fallback a 8080 si no existe
const DB_PASS = process.env.DB_PASSWORD;

if (!DB_PASS) {
    console.error('CRITICAL: No hay contraseña de BD definida');
    process.exit(1); // Cierra el programa con código de error
}

console.log(`Servidor iniciando en puerto ${PUERTO}`);

    Ejemplo 2: Leyendo Argumentos 

    // args.ts
// Ejecutar: node dist/args.js --usuario=admin

console.log(process.argv);
// argv[0] = ruta al ejecutable node
// argv[1] = ruta al archivo ejecutado
// argv[2] = '--usuario=admin'


    El módulo os

    Te da información sobre el hardware y el sistema operativo. Muy útil si estás creando herramientas de monitoreo o balanceadores de carga.

    Tabla de Métodos Útiles

    Método Descripción
    os.cpus() Array con info de cada núcleo del procesador.
    os.freemem() Memoria RAM libre en bytes.
    os.homedir() Ruta a la carpeta del usuario actual.
    os.platform() 'win32', 'linux', 'darwin' (macOS).

    Ejemplos de Código

    Ejemplo 1: Diagnóstico del Servidor 

    import * as os from 'os';

const memoriaTotalGB = os.totalmem() / 1024 / 1024 / 1024;
const cpus = os.cpus();

console.log(`Sistema Operativo: ${os.type()} ${os.release()}`);
console.log(`Memoria Total: ${memoriaTotalGB.toFixed(2)} GB`);
console.log(`Núcleos de CPU: ${cpus.length}`);

    Ejemplo 2: Balanceo de Carga (Concepto) 

    import { cpus } from 'os';

// Un patrón común en Node (Cluster module) es lanzar
// tantos procesos como núcleos tenga la CPU
const numNucleos = cpus().length;

console.log(`Para máximo rendimiento, deberíamos lanzar ${numNucleos} instancias de la app.`);


    El módulo path

    En Windows las rutas usan backslash \ (ej: C:\Users\Pepe). En Linux/Mac usan slash / (ej: /home/pepe). Si escribes las rutas a mano ("carpeta/archivo.txt"), tu aplicación se romperá cuando cambies de sistema operativo.

    path resuelve esto normalizando las rutas automáticamente.

    Regla de Oro

    Nunca concatenes rutas con + (ej: dir + '/' + file). Usa siempre path.join().

    Ejemplos de Código

    Ejemplo 1: Uniendo rutas de forma segura 

    import path from 'path';

// Imagina que __dirname es '/var/www' (Linux) o 'C:\Users' (Windows)
const carpetaUploads = 'uploads';
const archivo = 'imagen.png';

// path.join maneja los separadores por ti
const rutaCompleta = path.join('/var/www', carpetaUploads, archivo);

console.log(rutaCompleta); 
// Linux: /var/www/uploads/imagen.png
// Windows: \var\www\uploads\imagen.png (lo adapta)

    Ejemplo 2: Extrayendo información de un archivo 

    import { parse, format } from 'path';

const ruta = '/home/usuario/documentos/reporte.pdf';

const info = parse(ruta);

console.table(info);
/*
┌──────────┬─────────────────────────────┐
│ (index)  │           Values            │
├──────────┼─────────────────────────────┤
│   root   │             '/'             │
│   dir    │  '/home/usuario/documentos' │
│   base   │        'reporte.pdf'        │
│   ext    │           '.pdf'            │
│   name   │          'reporte'          │
└──────────┴─────────────────────────────┘
*/

    🎓 Enriquecimiento Pedagógico

    Pensad en los módulos de Node.js como si fueran Lego. - El núcleo (Core Modules) son las piezas base grises que vienen en todas las cajas (placas base, ruedas estándar). - Los Módulos NPM son los sets especiales (Star Wars, Harry Potter) que compras aparte para tener funcionalidades increíbles sin fabricarlas tú mismo. - Tu código (exports) es la nave espacial que construyes uniendo esas piezas.

    Si no usas path para unir las piezas, es como intentar pegar los Legos con chicle: funcionará un rato, pero en cuanto lo muevas (cambies de SO), se caerá a pedazos.
