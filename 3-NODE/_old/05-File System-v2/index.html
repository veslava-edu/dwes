    05. El Módulo FS (File System) en Node.js

    Introducción

    Imagina que eres el gerente de un almacén gigantesco (tu servidor). Tienes a un empleado extremadamente rápido y eficiente llamado Event Loop, que atiende a los clientes (peticiones HTTP) en el mostrador. Pero, de vez en cuando, un cliente pide "ese expediente antiguo que está en el sótano" (leer un archivo del disco duro).

    Si el Event Loop baja al sótano, busca la llave, abre la caja y sube los papeles, dejará el mostrador vacío y la cola de clientes crecerá hasta la calle. Desastre total.

    Aquí es donde entra el sistema de archivos de Node.js. En lugar de bajar él mismo, el Event Loop le grita a un equipo de archiveros especializados (el Thread Pool de libuv): "¡Traedme el archivo X, avísame cuando lo tengas!". Mientras ellos trabajan, el Event Loop sigue atendiendo clientes.

    Como vimos en el tema anterior (04 - Timers y Asincronía), dominar esta delegación es la clave del éxito. En este tema, aprenderemos a controlar el disco duro de tu servidor sin congelar la aplicación.

    1. Introducción al Módulo FS

    El módulo fs (File System) es la navaja suiza de Node.js para interactuar con el disco duro. Es un módulo core (nativo), por lo que no necesitas instalar nada extra con npm.

    1.1. Propósito y alcance

    Su objetivo es permitir que JavaScript, un lenguaje que nació encerrado en la "jaula" del navegador, pueda salir y manipular el sistema operativo.

    Definición: Modelo POSIX

    Node.js modela sus operaciones basándose en POSIX (Portable Operating System Interface). Esto significa que intenta estandarizar cómo "hablamos" con el disco, ya sea que tu código corra en Windows, Linux o macOS. Sin embargo, no siempre es perfecto y hay discrepancias que veremos.

    1.2. Arquitectura y fundamentos

    • Rutas (Paths): El sistema necesita saber dónde buscar.
      • Absolutas: Desde la raíz del disco (C:\Users\Juan... o /home/juan...).
      • Relativas: Desde donde se ejecuta el script (./data/archivo.txt).
    • Buffers: Node.js no lee "texto" por defecto, lee datos binarios crudos. Si no especificas un formato (encoding), recibirás un Buffer (una tira de bytes hexadecimales) en lugar de un string.

    1.3. Importación Recomendada

    Desde Node.js 16+, y reafirmado en 2024/2025, la buena práctica es usar el prefijo de protocolo node:. Esto evita conflictos con paquetes de npm que pudieran llamarse igual y es ligeramente más rápido en la carga.

    Ejemplo 1: Importación moderna (ES Modules & TypeScript) 

    // 🟢 RECOMENDADO: Uso explícito de 'node:' y promesas por defecto
import * as fs from 'node:fs/promises';
import { constants } from 'node:fs';

// Para operaciones síncronas (raras) o streams, a veces importamos la base:
import { readFileSync, createReadStream } from 'node:fs';

    Ejemplo 2: Uso de __dirname en ESM En CommonJS (el sistema antiguo) __dirname existía mágicamente. En ES Modules (el estándar actual), debemos construirlo.

    import path from 'node:path';
import { fileURLToPath } from 'node:url';

// Recreando __dirname en ES Modules
const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

console.log(`Estoy ejecutándome en: ${__dirname}`);

    Ejemplo 3: Constantes del sistema 

    import { constants } from 'node:fs';

// Verificamos si tenemos permisos de lectura (R_OK) o escritura (W_OK)
// Estas constantes son máscaras de bits utilizadas por el sistema operativo
console.log('Valor constante Lectura:', constants.R_OK); 
console.log('Valor constante Escritura:', constants.W_OK);

    1.4. Las tres APIs disponibles

    Node.js es único porque ofrece tres formas distintas de hacer exactamente lo mismo. Entender cuál usar separa al junior del senior.

    1. Callbacks (Legacy): fs.readFile(path, (err, data) => ...)
    2. Síncrona (Blocking): fs.readFileSync(path)
    3. Promesas (Modern): await fs.readFile(path)
    Característica Callbacks Síncrona Promesas
    Complejidad Media (Callback Hell) Baja Baja/Media
    Bloquea Event Loop No SÍ (Peligro) No
    Manejo de Errores if (err) try/catch try/catch
    Uso Recomendado Rendimiento extremo Scripts CLI / Config General (App Web)
    Concepto Buffer String (utf8)
    ¿Qué es? Datos binarios crudos (bytes) Texto legible por humanos
    Uso Imágenes, PDFs, Zips JSON, HTML, TXT, Logs
    Velocidad Más rápido (sin conversión) Ligeramente más lento

    2. Las Tres APIs de FS: Diferencias y Cuándo Usar Cada Una

    Elegir la API incorrecta es la causa #1 de cuellos de botella en servidores Node.js.

    2.1. API Síncrona (Bloqueante)

    Los métodos terminados en Sync (ej: readFileSync) detienen la ejecución de JavaScript hasta que el disco responde.

    ¡Cuidado con el Bloqueo!

    Si usas readFileSync en una ruta de una API REST (ej: Express o Fastify), nadie más podrá usar tu servidor hasta que ese archivo se lea. Si el disco tarda 50ms, tu servidor queda congelado 50ms.

    Ejemplo 1: Uso Legítimo (Carga de Configuración) Es aceptable usar Sync solo al inicio de la aplicación, antes de empezar a escuchar peticiones.

    import { readFileSync } from 'node:fs';

try {
  // Bloqueamos a propósito: la app no puede arrancar sin config
  const rawData = readFileSync('./config.json', 'utf-8');
  const config = JSON.parse(rawData);
  console.log('✅ Configuración cargada:', config.dbName);
} catch (error) {
  console.error('❌ Error crítico: No se pudo leer config.json');
  process.exit(1); // Cerramos la app
}

    2.2. API de Callbacks (Asíncrona Tradicional)

    Usa el patrón "Error-First Callback". Es muy eficiente, pero conduce al "Callback Hell" si anidas muchas operaciones.

    Ejemplo 2: Lectura con Callback 

    import { readFile } from 'node:fs'; // Nota: sin /promises

// El código sigue ejecutándose inmediatamente después de llamar a readFile
readFile('./archivo.txt', 'utf-8', (err, data) => {
  if (err) {
    console.error('Error de lectura:', err.message);
    return;
  }
  console.log('Contenido recibido:', data);
});

console.log('👋 Esto se imprime ANTES que el contenido del archivo');

    2.3. API de Promesas (El Estándar Moderno)

    Desde node:fs/promises. Permite usar async/await, haciendo el código legible como si fuera síncrono, pero sin bloquear el Event Loop.

    Ejemplo 3: Lectura Secuencial con Async/Await 

    import { readFile, writeFile } from 'node:fs/promises';

async function duplicarArchivo() {
  try {
    // 1. Leemos (No bloquea otros procesos)
    const contenido = await readFile('./original.txt', 'utf-8');

    // 2. Procesamos
    const nuevoContenido = contenido.toUpperCase();

    // 3. Escribimos
    await writeFile('./copia_mayus.txt', nuevoContenido);
    console.log('✨ Proceso completado');

  } catch (error) {
    console.error('Algo falló:', error);
  }
}

duplicarArchivo();

    2.4. Comparativa de Rendimiento

    API Latencia (Tiempo de respuesta) Throughput (Peticiones/segundo) Legibilidad
    Sync Baja (en scripts simples) Pésima (en servidores) Alta
    Callback Mínima Máxima Baja
    Promises Baja Muy Alta (ligeramente menor que callbacks) Muy Alta

    🧠 Preguntas Reflexivas

    1. En un servidor web con 10,000 usuarios concurrentes, ¿qué efecto tendría usar writeFileSync para guardar un log de cada visita?
    2. ¿Por qué process.exit(1) es aceptable en el ejemplo síncrono de configuración pero terrible en una ruta de API?
    3. Transforma mentalmente el Ejemplo 3 (Promesas) a Callbacks. ¿Cuántos niveles de indentación (pirámide) tendrías?


    3. Operaciones Básicas de Lectura y Escritura

    Vamos a mancharnos las manos manipulando archivos. Usaremos preferentemente la API de promesas.

    3.1. Lectura de Archivos (readFile)

    Permite leer todo el contenido de un archivo en memoria.

    Ojo con la Memoria (RAM)

    readFile carga todo el archivo en la RAM. Si lees un video de 4GB y tu servidor tiene 2GB de RAM, la aplicación colapsará (Crash OOM - Out Of Memory). Para archivos grandes, usaremos Streams (Punto 7).

    Ejemplo 1: Lectura de JSON con tipado 

    import { readFile } from 'node:fs/promises';

interface UserData {
  id: number;
  name: string;
}

async function getUser(): Promise<UserData | null> {
  try {
    const data = await readFile('./users.json', { encoding: 'utf-8' });
    return JSON.parse(data) as UserData;
  } catch (error: any) {
    // Si el archivo no existe (ENOENT), retornamos null
    if (error.code === 'ENOENT') return null;
    throw error;
  }
}

    3.2. Escritura de Archivos (writeFile)

    Crea un archivo nuevo o sobrescribe completamente el existente.

    Ejemplo 2: Escritura segura (Flag 'wx') A veces no queremos sobrescribir accidentalmente un archivo importante. Usamos el flag wx (Write Exclusive). Falla si el archivo ya existe.

    import { writeFile } from 'node:fs/promises';

async function crearConfiguracionInicial(datos: object) {
  try {
    // 'wx': Falla si el path ya existe
    await writeFile('./config.json', JSON.stringify(datos, null, 2), { flag: 'wx' });
    console.log('Archivo creado.');
  } catch (error: any) {
    if (error.code === 'EEXIST') {
      console.warn('⚠️ El archivo ya existe, no se sobrescribió.');
    } else {
      console.error('Error de escritura:', error);
    }
  }
}

    3.3. Añadir contenido (appendFile)

    Ideal para logs. Agrega datos al final del archivo sin borrar lo anterior.

    Ejemplo 3: Sistema de Logging simple 

    import { appendFile } from 'node:fs/promises';

async function logActivity(mensaje: string) {
  const timestamp = new Date().toISOString();
  const linea = `[${timestamp}] ${mensaje}\n`; // Importante el salto de línea \n

  try {
    await appendFile('./server.log', linea, 'utf-8');
  } catch (error) {
    console.error('No se pudo escribir el log:', error);
  }
}

// Uso: await logActivity("Usuario logueado");

    Método Si el archivo no existe... Si el archivo existe...
    writeFile Lo crea Lo borra y escribe lo nuevo
    writeFile (flag 'wx') Lo crea Lanza error EEXIST
    appendFile Lo crea Agrega al final

    🧠 Preguntas Reflexivas

    1. ¿Qué diferencia hay entre usar JSON.stringify antes de escribir o pasar el objeto directo a writeFile? (Pista: writeFile espera string, buffer o Uint8Array).
    2. Si ejecutas writeFile y readFile en paralelo (sin await entre ellos) sobre el mismo archivo, ¿qué resultado obtendrías?
    3. ¿Por qué es importante añadir \n manualmente al usar appendFile para logs de texto?


    4. Gestión de Directorios y Estructuras

    Organizar los archivos es tan importante como crearlos.

    4.1. Creación (mkdir)

    La función clave aquí es recursive: true. Nos permite crear rutas profundas de una sola vez (ej: a/b/c) sin tener que crear a, luego b, etc.

    Ejemplo 1: Crear estructura de carpetas 

    import { mkdir } from 'node:fs/promises';

async function setupProject() {
  const dirs = ['src/controllers', 'src/models', 'logs'];

  for (const dir of dirs) {
    // recursive: true evita error si la carpeta ya existe
    await mkdir(dir, { recursive: true }); 
    console.log(`📁 Carpeta asegurada: ${dir}`);
  }
}

    4.2. Eliminación (rm vs rmdir)

    Antiguamente usábamos rmdir. Ahora se recomienda rm, que es más parecido al comando de UNIX rm -rf.

    Ejemplo 2: Limpieza de temporales 

    import { rm } from 'node:fs/promises';

async function limpiarTemp() {
  try {
    // force: true evita error si no existe. 
    // recursive: true borra carpetas con contenido.
    await rm('./temp', { recursive: true, force: true });
    console.log('🧹 Temporales eliminados');
  } catch (error) {
    console.error('Error al limpiar:', error);
  }
}

    4.3. Listado (readdir)

    Para saber qué hay dentro de una carpeta.

    Ejemplo 3: Escanear directorio distinguiendo tipos Usar withFileTypes: true es más eficiente que leer los nombres y luego hacer un stat de cada uno. Devuelve objetos Dirent en lugar de strings.

    import { readdir } from 'node:fs/promises';

async function listarContenido(ruta: string) {
  try {
    const entradas = await readdir(ruta, { withFileTypes: true });

    console.log(`Contenido de ${ruta}:`);
    for (const entrada of entradas) {
      const icono = entrada.isDirectory() ? '📁' : '📄';
      console.log(`${icono} ${entrada.name}`);
    }
  } catch (error) {
    console.error('No se pudo leer el directorio:', error);
  }
}

    🧠 Preguntas Reflexivas

    1. ¿Qué sucede si intentas usar rmdir (sin rm) en una carpeta que contiene archivos?
    2. ¿Por qué withFileTypes: true en readdir mejora el rendimiento en directorios grandes?
    3. Si usas mkdir sin recursive: true para crear ./logs/2025/enero, y ./logs no existe, ¿qué error obtienes?


    5. Manipulación de Archivos Individuales

    Operaciones del día a día: borrar, mover, renombrar y copiar.

    5.1. Eliminación y Renombrado (unlink, rename)

    unlink es el nombre técnico para "borrar archivo" (desvincularlo del sistema de archivos). rename sirve tanto para cambiar el nombre como para mover el archivo a otra carpeta.

    Ejemplo 1: Mover y renombrar (Cut & Paste) 

    import { rename } from 'node:fs/promises';
import { resolve } from 'node:path';

async function archivarLog() {
  const origen = resolve('./logs/actual.log');
  const destino = resolve('./logs/historico/2024-log.txt');

  try {
    await rename(origen, destino);
    console.log('Log archivado correctamente.');
  } catch (error) {
    console.error('Fallo al mover:', error);
  }
}

    5.2. Copiar (copyFile)

    A veces necesitamos duplicar sin alterar el original.

    Ejemplo 2: Backup seguro Usamos constantes (COPYFILE_EXCL) para evitar destruir un backup previo por error.

    import { copyFile, constants } from 'node:fs'; // constants viene del callback API
import { copyFile as copyFileAsync } from 'node:fs/promises';

async function backupDB() {
  try {
    // COPYFILE_EXCL: Falla si destino ya existe
    await copyFileAsync('db.sqlite', 'db.backup.sqlite', constants.COPYFILE_EXCL);
    console.log('Backup realizado.');
  } catch (error) {
    console.error('Error backup:', error);
  }
}

    5.3. Metadatos (stat vs lstat)

    Para saber el tamaño, fecha de creación o permisos.

    Tip Profesional: stat vs lstat

    • stat: Si apuntas a un enlace simbólico (acceso directo), te da info del archivo real.
    • lstat: Te da info del enlace simbólico en sí mismo.

    Ejemplo 3: Inspeccionar archivo 

    import { stat } from 'node:fs/promises';

async function checkSize(archivo: string) {
  const datos = await stat(archivo);

  const sizeMB = datos.size / (1024 * 1024);
  console.log(`Tamaño: ${sizeMB.toFixed(2)} MB`);
  console.log(`Modificado: ${datos.mtime.toLocaleString()}`);
  console.log(`Es archivo?: ${datos.isFile()}`);
}

    Comando Acción Equivalente CLI (Linux)
    unlink Borrar archivo rm archivo
    rename Mover/Renombrar mv origen destino
    copyFile Copiar cp origen destino
    stat Ver info ls -l / stat

    🧠 Preguntas Reflexivas

    1. Si intentas hacer rename('./a.txt', './carpeta_inexistente/b.txt'), ¿qué sucede?
    2. ¿Por qué crees que el comando de borrado se llama unlink y no delete? (Pista: tiene que ver con los inodos de Linux).
    3. ¿Para qué situación usarías lstat en lugar de stat?


    6. Control de Acceso y Permisos

    Seguridad ante todo. No siempre tu script tendrá permiso para leer o escribir donde quiera.

    6.1. Verificación (access)

    Comprueba si tenemos visibilidad sobre un archivo.

    Condición de Carrera (Race Condition)

    NO HAGAS ESTO: if (await access(file)) { await readFile(file) }. Entre el chequeo (access) y la lectura (readFile), otro proceso podría haber borrado el archivo. MEJOR: Intenta leer directamente y maneja el error try/catch.

    Ejemplo 1: Verificación (Solo para UI o chequeos no críticos) 

    import { access, constants } from 'node:fs/promises';

async function esEjecutable(archivo: string) {
  try {
    // Verificamos permiso de ejecución (X_OK)
    await access(archivo, constants.X_OK);
    console.log(`${archivo} se puede ejecutar.`);
  } catch {
    console.log(`${archivo} NO es ejecutable o no existe.`);
  }
}

    6.2. Modificación (chmod, chown)

    Cambiar permisos (chmod) o propietario (chown).

    Ejemplo 2: Hacer un script privado (Solo lectura/escritura para el dueño) 

    import { chmod } from 'node:fs/promises';

async function protegerClaves() {
  // 0o600: Dueño (rw-), Grupo (---), Otros (---)
  // Usamos notación octal (0o)
  await chmod('./claves_secretas.pem', 0o600);
  console.log('Permisos restringidos.');
}

    6.3. Nuevo Modelo de Permisos (Node.js 20/22+)

    Inspirado en Deno, Node.js ahora permite restringir qué puede hacer tu propio script mediante flags al ejecutarlo. Esto es vital para seguridad.

    Ejemplo 3: Ejecución restringida (CLI)

    No es código TypeScript, sino cómo ejecutas tu script en la terminal:

    # Solo permitimos leer en la carpeta /tmp y escribir en ./logs
node --allow-fs-read="/tmp/*" --allow-fs-write="./logs/*" index.js
    Si tu código index.js intenta leer /etc/passwd, Node lanzará un error de permiso denegado automáticamente.

    🧠 Preguntas Reflexivas

    1. ¿Qué significan los números 777 o 644 en chmod?
    2. ¿Por qué el patrón "Check then Act" (comprobar y luego actuar) es peligroso en sistemas de archivos?
    3. ¿Cómo ayuda el modelo de permisos --allow-fs-* a mitigar ataques si una librería de terceros (npm) intenta robar tus datos?


    7. Operaciones Avanzadas con Streams

    Hasta ahora hemos tratado los archivos como "bloques de datos". Pero, ¿y si el archivo es gigantesco?

    7.1. Problema de Memoria (Backpressure)

    Si lees un archivo de 10GB con readFile, Node intentará crear un Buffer de 10GB. Resultado: Crash.

    La solución es procesar el archivo por trozos (chunks), como un grifo de agua, no como un cubo.

    7.2. Streams (createReadStream, createWriteStream)

    Usamos streams para leer y escribir bit a bit.

    Ejemplo 1: Copia eficiente de archivos gigantes 

    import { createReadStream, createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';

async function copiarGigante() {
  // highWaterMark: Tamaño del "cubo" (chunk). 64KB por defecto.
  const source = createReadStream('./big-video.mp4', { highWaterMark: 64 * 1024 });
  const destination = createWriteStream('./copia-video.mp4');

  console.log('Iniciando transferencia eficiente...');

  // Pipeline maneja errores y limpieza automática mejor que .pipe()
  await pipeline(source, destination);

  console.log('Copia finalizada sin explotar la RAM.');
}

    7.3. Iteradores Asíncronos (for await...of)

    Podemos recorrer un stream como si fuera un array, gracias a que los streams son iterables asíncronos.

    Ejemplo 2: Procesar línea a línea (o chunk a chunk) 

    import { createReadStream } from 'node:fs';

async function analizarChunks() {
  const stream = createReadStream('./datos.txt', { encoding: 'utf-8' });
  let totalSize = 0;

  for await (const chunk of stream) {
    totalSize += chunk.length;
    console.log(`Recibido chunk de ${chunk.length} caracteres`);
    // Aquí podríamos buscar palabras clave sin cargar todo el archivo
  }
  console.log(`Total leído: ${totalSize}`);
}

    8. Observabilidad y Monitoreo

    Podemos pedirle a Node.js que nos avise si un archivo cambia.

    8.1. watch vs watchFile

    • watch: Usa eventos nativos del SO. Es eficiente y rápido. (Recomendado).
    • watchFile: Hace polling (pregunta cada X ms: "¿Cambiaste?"). Ineficiente, usa CPU. (Evitar).

    8.2. Caso de uso: Hot Reload

    Imagina reiniciar tu servidor automáticamente cuando cambias la configuración.

    Ejemplo 1: Vigilar cambios en config 

    import { watch } from 'node:fs/promises';

async function vigilarConfig() {
  const watcher = watch('./config.json');

  console.log('👀 Vigilando config.json...');

  for await (const event of watcher) {
    console.log(`Evento detectado: ${event.eventType}`);
    // Aquí recargaríamos la configuración
    console.log('🔄 Recargando configuración...');
  }
}
// Nota: watch devuelve un AsyncIterator

    Ejemplo 2: Watcher robusto con AbortController Para detener la vigilancia limpiamente. 

    import { watch } from 'node:fs';

const ac = new AbortController();
const { signal } = ac;

const watcher = watch('./temp', { signal }, (eventType, filename) => {
  console.log(`Cambio en ${filename}: ${eventType}`);
});

// Detener después de 10 segundos
setTimeout(() => {
  ac.abort();
  console.log('🛑 Vigilancia detenida.');
}, 10000);

    9. Integración con Otros Módulos y Buenas Prácticas

    El módulo FS no trabaja solo.

    9.1. Módulo Path: Tu mejor amigo

    Jamás concatenes rutas con strings (dir + '/' + file). Windows usa \, Linux /. El módulo path lo resuelve.

    Ejemplo 1: Rutas Cross-Platform 

    import path from 'node:path';
// MAL: const ruta = 'uploads/' + archivo;
// BIEN:
const rutaSegura = path.join('uploads', '2025', 'img.png'); 
// Resultado Windows: uploads\2025\img.png
// Resultado Linux: uploads/2025/img.png

    9.2. Seguridad: Path Traversal

    Un atacante podría enviar ../../etc/passwd como nombre de archivo para leer tus secretos.

    Ejemplo 2: Sanitización básica 

    import path from 'node:path';

function rutaSeguraUsuario(inputUser: string) {
  const directorioBase = path.resolve('./public');
  const rutaDestino = path.resolve(directorioBase, inputUser);

  // Verificamos que la ruta resultante siga estando DENTRO del directorio base
  if (!rutaDestino.startsWith(directorioBase)) {
    throw new Error('🚫 Intento de hackeo (Path Traversal)');
  }
  return rutaDestino;
}

    9.3. Manejo de Errores Comunes

    No todos los errores son iguales. - ENOENT: Error No Entry (Archivo no encontrado). - EACCES: Error Access (Permiso denegado). - EEXIST: Error Exist (El archivo ya existe y no debía).

    Ejemplo 3: Try-Catch con chequeo de código 

    try {
  await fs.readFile('no-existe.txt');
} catch (error: any) {
  if (error.code === 'ENOENT') {
    console.log('El archivo no está, crearemos uno por defecto.');
  } else if (error.code === 'EACCES') {
    console.error('¡No tengo permisos! Ejecuta como admin/sudo.');
  } else {
    throw error; // Re-lanzar si es algo inesperado
  }
}

    10. Conclusión y Recursos

    El módulo fs es el puente entre tu lógica de negocio y los datos persistentes físicos.

    1. Promesas por defecto: Usa node:fs/promises para casi todo.
    2. Streams para volumen: Si pesa más de 10-20MB, usa Streams.
    3. Cross-Platform: Usa siempre el módulo path.
    4. No bloquees: Evita *Sync en rutas calientes.
