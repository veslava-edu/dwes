    El Módulo FS (File System) en Node.js: Gestionando el Almacenamiento con Maestría

    Introducción Atractiva

    Imagina que tu servidor es una biblioteca gigante. Como programador, tú eres el bibliotecario jefe. El Módulo FS (File System) es tu manual de procedimientos, tus llaves y tus carritos de transporte. Sin él, los libros (tus datos) estarían flotando en el aire sin orden ni concierto; con él, puedes escribir nuevos tomos, archivar expedientes antiguos, crear pasillos enteros (directorios) o incluso destruir documentos confidenciales (shredding).

    Como vimos en el Tema 4: Timers y Asincronía, Node.js brilla cuando delega tareas pesadas. Leer un archivo de 2GB de un disco duro mecánico es una tarea "pesada" y lenta comparada con la velocidad de la CPU. Por eso, entender cómo el módulo FS interactúa con el sistema operativo y el Event Loop es la diferencia entre una aplicación fluida y una que se congela como un PC con Windows 95 intentando correr Cyberpunk 2077.

    1. Introducción al Módulo FS

    1.1. Propósito y alcance

    El módulo fs permite a Node.js interactuar con el sistema de archivos del sistema operativo siguiendo el estándar POSIX. Esto significa que, ya estés en Linux, macOS o Windows, Node intenta ofrecerte una interfaz unificada para manipular archivos y carpetas.

    Definición: POSIX

    Es una familia de estándares que definen la interfaz de programación de aplicaciones (API) para el software compatible con variantes de UNIX. En FS, esto significa que muchas funciones (como chmod o chown) heredan sus nombres y lógica de este estándar.

    1.2. Arquitectura y fundamentos

    Node.js no lee archivos "por arte de magia". Utiliza la librería libuv para delegar estas operaciones a un Thread Pool (un grupo de hilos de ejecución en segundo plano), evitando que el hilo principal (Event Loop) se detenga mientras el disco duro busca los datos.

    • Rutas: Es vital diferenciar entre rutas relativas (./datos.txt) y absolutas. En módulos ESM, no tenemos el clásico __dirname, por lo que usamos path.resolve().
    • Datos: Los archivos se pueden leer como string (especificando utf8) o como Buffer (datos binarios puros, como una imagen o un ejecutable).

    1.3. Importación y Constantes

    Desde Node.js v16+, se recomienda usar el prefijo node: para dejar claro que es un módulo nativo.

    // Estilo moderno (ESM)
import fs from 'node:fs';
import { promises as fsPromises } from 'node:fs';
import { constants } from 'node:fs';

// Ejemplo de uso de constantes para verificar permisos
console.log(constants.R_OK); // Indica permiso de lectura

    1.4. Las tres APIs disponibles

    Node nos da a elegir según nuestras necesidades:

    1. Callbacks: La vieja escuela (asíncrono).
    2. Síncrona: Bloqueante, pero sencilla.
    3. Promesas: La recomendada hoy en día (asíncrono con async/await).
    // Ejemplo 1: Importación recomendada en TypeScript
import { readFile } from 'node:fs/promises';

async function leerConfig() {
  try {
    const data = await readFile('./config.json', 'utf8');
    console.log('Contenido:', JSON.parse(data));
  } catch (err) {
    console.error('Error al leer:', err);
  }
}

    // Ejemplo 2: Uso de constantes para control de acceso
import { access, constants } from 'node:fs/promises';

async function verificarAcceso(path: string): Promise<void> {
  try {
    await access(path, constants.W_OK);
    console.log('¡Tenemos permiso de escritura!');
  } catch {
    console.error('Acceso denegado o archivo inexistente');
  }
}

    Comparativas y Reflexión

    Característica API Síncrona API Promesas
    Bloqueo Sí (Detiene el servidor) No (Usa el Thread Pool)
    Legibilidad Muy alta Alta (con async/await)
    Uso ideal Scripts de inicio/CLI Servidores Web API
    Formato de Datos Uso Principal Ventaja
    UTF-8 (String) Archivos de texto, JSON, HTML Manipulación directa de texto
    Buffer (Binario) Imágenes, PDFs, Vídeo Eficiencia y ahorro de memoria

    2. En un entorno profesional, ¿por qué es mejor usar import fs from 'node:fs' en lugar de import fs from 'fs'?
    3. Si olvidas poner 'utf8' al leer un archivo de texto, ¿qué recibes como resultado y por qué?

    2. Las Tres APIs de FS: Diferencias y Cuándo Usar Cada Una

    2.1. API Síncrona (Bloqueante)

    Las funciones que terminan en *Sync (ej. readFileSync) detienen la ejecución de TODO el programa hasta que el archivo se lee. Es como si en un restaurante el camarero se quedara quieto en la cocina esperando a que salga el plato, sin atender a otros clientes.

    Peligro en Producción

    Nunca uses métodos *Sync dentro de un controlador de una API Web (Express/Fastify). Si 100 usuarios piden un archivo a la vez, el servidor atenderá de uno en uno, arruinando la escalabilidad.

    2.2. API de Callbacks y 2.3. API de Promesas

    El patrón error-first callback ((err, data) => ...) fue el estándar durante años. Sin embargo, las promesas permiten un código lineal y limpio gracias a async/await, evitando el "Callback Hell".

    sequenceDiagram
    participant App as "Tu Código (Main Thread)"
    participant Pool as "Thread Pool (Libuv)"
    participant OS as "Sistema de Archivos"

    Note over App: Llamada a fs.readFile()
    App->>Pool: "Léeme este archivo"
    Note over App: ¡Sigue ejecutando otras cosas!
    Pool->>OS: Petición I/O
    OS-->>Pool: Datos listos
    Pool-->>App: Ejecuta el Callback / Resuelve Promesa

    // Ejemplo 1: El horror del Callback (No recomendado hoy)
import { readFile } from 'node:fs';

readFile('./log.txt', 'utf8', (err, data) => {
  if (err) throw err;
  console.log('Leído con callback:', data);
});

    // Ejemplo 2: El paraíso de las Promesas (Recomendado)
import { writeFile } from 'node:fs/promises';

async function guardarLog(msg: string): Promise<void> {
  const content = `[${new Date().toISOString()}] - ${msg}\n`;
  await writeFile('./app.log', content, { flag: 'a' }); 
  // 'a' significa append (añadir)
}

    Comparativas y Reflexión

    API Estilo de Manejo de Errores Complejidad en bucles
    Callbacks if (err) en cada nivel Muy alta (necesitas librerías externas)
    Promesas try / catch global o local Baja (usa for await o Promise.all)
    Caso de Uso API Recomendada Razón
    Script CLI de instalación Síncrona La ejecución es lineal y no hay concurrencia.
    Servidor Express de alto tráfico Promesas Permite manejar miles de peticiones sin bloquear.

    Preguntas reflexivas

    1. Si tienes un bucle que debe leer 50 archivos de forma independiente, ¿usarías un for con await o un Promise.all? Justifica tu respuesta.
    2. ¿Qué sucede con la memoria del servidor si 1000 usuarios ejecutan readFileSync sobre un archivo de 100MB simultáneamente?
    3. ¿Por qué el patrón de Callbacks se llama "error-first"?

    3. Operaciones Básicas de Lectura y Escritura

    3.1. Lectura y 3.2. Escritura

    Cuando usamos readFile o writeFile, Node.js carga todo el contenido en la RAM. Es como intentar leer un libro entero y memorizarlo antes de pasar a la siguiente tarea.

    Flag 'wx'

    Al escribir, si usas { flag: 'wx' }, la operación fallará si el archivo ya existe. Esto evita sobrescribir datos importantes por accidente. ¡Es el "Modo Seguro" de la escritura!

    3.3. Añadir contenido (Append)

    Ideal para logs. appendFile añade datos al final sin borrar lo que ya estaba.

    3.4. Operaciones de Bajo Nivel

    Para casos muy específicos (como leer solo los primeros 10 bytes de un archivo gigante), usamos open, read y los File Descriptors (un número entero que identifica el archivo abierto en el SO).

    // Ejemplo 1: Lectura completa con manejo de errores robusto
import { readFile } from 'node:fs/promises';

async function leerSeguro(path: string): Promise<string | null> {
  try {
    return await readFile(path, 'utf8');
  } catch (error: any) {
    if (error.code === 'ENOENT') {
      console.error('¡Archivo no encontrado!');
    }
    return null;
  }
}

    // Ejemplo 2: Escritura con File Descriptor (Bajo nivel)
import { open } from 'node:fs/promises';

async function escrituraManual() {
  const fd = await open('./secreto.bin', 'w');
  try {
    const buffer = Buffer.from('Datos binarios');
    await fd.write(buffer, 0, buffer.length, 0);
  } finally {
    // ¡Siempre cerrar el archivo para liberar memoria!
    await fd.close();
  }
}

    Comparativas y Reflexión

    Método Acción sobre el archivo ¿Qué pasa si el archivo no existe?
    writeFile Sobrescribe todo Lo crea
    appendFile Añade al final Lo crea
    Flag Nombre Efecto
    'r' Read Abre para lectura (error si no existe)
    'w' Write Abre para escritura (crea o trunca)
    'a' Append Abre para añadir

    Preguntas reflexivas

    1. ¿Cuál es el riesgo de usar readFile en un archivo de 4GB en un servidor con 2GB de RAM?
    2. ¿Para qué sirve el método close() cuando trabajamos con File Descriptors?
    3. En un sistema de logs de una tienda online, ¿usarías writeFile o appendFile para guardar cada nueva venta?

    4. Gestión de Directorios y Estructuras

    Manipular carpetas es como organizar los estantes de nuestra biblioteca.

    4.1. Creación (mkdir)

    Desde Node 10, podemos usar { recursive: true }. Esto permite crear rutas complejas como ./2025/proyectos/daw/ de un solo golpe, incluso si las carpetas intermedias no existen.

    4.2. Eliminación (rm y rmdir)

    rmdir solo borra carpetas vacías. Para borrar una carpeta con archivos dentro, usamos rm con { recursive: true, force: true }. Es el equivalente al rm -rf de Linux.

    4.3. Listado (readdir)

    Por defecto devuelve un array de nombres (string[]). Si usamos { withFileTypes: true }, devuelve objetos Dirent que nos permiten saber si es un archivo o una carpeta sin hacer llamadas extra al disco.

    // Ejemplo 1: Crear estructura anidada de forma segura
import { mkdir } from 'node:fs/promises';

async function inicializarProyecto(nombre: string) {
  const ruta = `./proyectos/${nombre}/src/assets`;
  await mkdir(ruta, { recursive: true });
  console.log('Estructura creada con éxito');
}

    // Ejemplo 2: Listar archivos filtrando directorios
import { readdir } from 'node:fs/promises';

async function listarSoloArchivos(path: string) {
  const entries = await readdir(path, { withFileTypes: true });
  const archivos = entries
    .filter(entry => entry.isFile())
    .map(entry => entry.name);

  console.log('Archivos encontrados:', archivos);
}

    Comparativas y Reflexión

    Operación Método Seguro Método "Peligroso"
    Borrar carpeta rmdir (solo vacías) rm(path, { recursive: true })
    Crear carpeta mkdir(p, { recursive: true }) mkdir(p) (falla si el padre no existe)
    Propiedad de Dirent Tipo Descripción
    entry.isFile() Boolean true si es un archivo regular
    entry.isDirectory() Boolean true si es un directorio

    2. Si listamos un directorio y vemos un archivo con el nombre .DS_Store o thumbs.db, ¿qué son y cómo deberíamos tratarlos en nuestro código?
    3. ¿Qué diferencia hay entre un symlink (enlace simbólico) y una carpeta real para el método readdir?

    5. Manipulación de Archivos Individuales

    5.1, 5.2 y 5.3. Mover, Copiar y Eliminar

    • Rename: Se usa tanto para cambiar el nombre como para mover un archivo de carpeta.
    • CopyFile: Más eficiente que leer y luego escribir manualmente.
    • Unlink: Es el nombre técnico para "borrar un archivo".

    5.4. Metadatos (stat)

    El método stat es como el "DNI" del archivo. Nos dice:

    • size: Tamaño en bytes.
    • mtime: Fecha de última modificación.
    • birthtime: Fecha de creación.
    // Ejemplo 1: Mover y renombrar un archivo con validación
import { rename, access } from 'node:fs/promises';

async function moverDocumento(origen: string, destino: string) {
  try {
    await rename(origen, destino);
    console.log('Movido correctamente');
  } catch (err) {
    console.error('No se pudo mover. ¿Existe el origen?');
  }
}

    // Ejemplo 2: Obtener el tamaño de un archivo en MB
import { stat } from 'node:fs/promises';

async function obtenerTamaño(path: string) {
  const stats = await stat(path);
  const tamañoMB = (stats.size / (1024 * 1024)).toFixed(2);
  console.log(`El archivo pesa ${tamañoMB} MB`);
  console.log('¿Es un directorio?', stats.isDirectory());
}

    Comparativas y Reflexión

    Método ¿Mueve el contenido? ¿Cambia el Inode (en Linux)?
    rename Sí No (normalmente)
    copyFile Crea una copia Sí (nuevo archivo)
    Método Stat Diferencia
    stat Sigue enlaces simbólicos al archivo original
    lstat Analiza el enlace simbólico en sí mismo

    2. ¿Por qué es importante comprobar stats.size antes de intentar leer un archivo en memoria?
    3. ¿Qué diferencia hay entre unlink y borrar un archivo en la papelera de reciclaje de Windows?

    6. Control de Acceso y Permisos

    En el mundo profesional, no todos pueden leer todo. Tu archivo .env con las contraseñas de la base de datos debe estar protegido.

    6.1. Verificación (access)

    Antes de intentar abrir un archivo, "preguntamos" si podemos. Esto evita lanzar excepciones costosas.

    6.3. Nuevo modelo de permisos (Node.js 22+)

    Node.js ha introducido un Permission Model experimental que permite restringir qué carpetas puede tocar el proceso de Node mediante flags en la terminal: node --allow-fs-read=/tmp/ index.js -> Tu código solo podrá leer de /tmp/.

    // Ejemplo 1: Verificación de permisos múltiples
import { access, constants } from 'node:fs/promises';

async function checkConfig() {
  try {
    // Comprobamos si existe Y si podemos leer
    await access('config.json', constants.F_OK | constants.R_OK);
    console.log('Configuración lista para ser leída');
  } catch {
    console.error('Configuración no accesible');
  }
}

    // Ejemplo 2: Cambiar permisos (Solo Unix-like)
import { chmod } from 'node:fs/promises';

async function protegerArchivo(path: string) {
  // Permisos 600: Solo el dueño lee/escribe
  await chmod(path, 0o600); 
  console.log('Permisos actualizados');
}

    Comparativas y Reflexión

    Constante Significado
    F_OK El archivo es visible (existe)
    R_OK Tenemos permiso de lectura
    W_OK Tenemos permiso de escritura
    X_OK Tenemos permiso de ejecución (Unix)
    Enfoque Seguridad Flexibilidad
    chmod manual Media (Depende del OS) Alta
    --allow-fs-read Muy Alta (Nivel proceso) Media (Configuración externa)

    1. ¿Por qué es una mala práctica dar permisos 777 (lectura/escritura/ejecución para todos) a los archivos de tu servidor?
    2. ¿Cómo ayuda el flag --allow-fs-write a prevenir ataques de "Path Traversal"?
    3. ¿En qué se diferencia access de stat a la hora de comprobar la existencia de un archivo?

    7. Operaciones Avanzadas con Streams y Optimización

    7.1. El problema de la memoria

    Si tu servidor tiene 500MB de RAM y un usuario sube un vídeo de 1GB, al usar readFile tu servidor morirá con un error de Out of Memory (OOM).

    7.2. Streams: La manguera de datos

    Los Streams permiten procesar el archivo por trozos (chunks). Es como beber agua de una manguera en lugar de intentar tragarte una piscina de golpe.

    7.3. Piping y Backpressure

    pipeline conecta un flujo de entrada con uno de salida automáticamente, gestionando la velocidad para no saturar al receptor.

    graph LR
    A[Archivo en Disco] -->|Stream de Lectura| B{Buffer de Memoria Chunks}
    B -->|Procesamiento/Transformación| C[Stream de Escritura]
    C -->|Guardado| D[Nuevo Archivo/Respuesta HTTP]

    // Ejemplo 1: Copiar un archivo gigante eficientemente
import { createReadStream, createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';

async function copiarGigante(origen: string, destino: string) {
  const readStream = createReadStream(origen);
  const writeStream = createWriteStream(destino);

  await pipeline(readStream, writeStream);
  console.log('Copia finalizada sin saturar la RAM');
}

    // Ejemplo 2: Procesar un archivo línea a línea con for await
import { createReadStream } from 'node:fs';
import readline from 'node:readline';

async function procesarLogs() {
  const stream = createReadStream('data.log');
  const rl = readline.createInterface({ input: stream });

  for await (const line of rl) {
    if (line.includes('ERROR')) {
      console.log('Alerta encontrada:', line);
    }
  }
}

    Comparativas y Reflexión

    Método Uso de Memoria Velocidad de Inicio
    readFile Alta (Todo el archivo) Lenta (debe cargar todo)
    Streams Muy Baja (Solo chunks) Instantánea (empieza al primer chunk)
    Concepto Definición en "humano"
    Chunk Un pedacito de datos (normalmente 64KB)
    Backpressure El freno que pone el receptor cuando no puede leer tan rápido como el emisor envía

    3. Si estás enviando un archivo por una respuesta HTTP a un cliente con conexión lenta, ¿por qué los Streams son obligatorios?

    8. Observabilidad y Monitoreo

    ¿Cómo sabe VS Code que un archivo ha cambiado para mostrarte el aviso de "Guardado"? Con Watchers.

    8.1. watch() vs watchFile()

    • watch() es más eficiente: usa eventos del sistema operativo (como inotify en Linux).
    • watchFile() hace "polling" (pregunta cada X milisegundos), lo que consume más CPU.
    // Ejemplo 1: Un mini-Nodemon casero
import { watch } from 'node:fs/promises';

async function vigilarCambios() {
  const watcher = watch('./src');
  console.log('Vigilando carpeta src...');

  for await (const event of watcher) {
    console.log(`Evento: ${event.eventType} en ${event.filename}`);
    if (event.eventType === 'change') {
      console.log('¡Compilando de nuevo...!');
    }
  }
}

    // Ejemplo 2: Vigilancia con filtrado
import { watch } from 'node:fs';

const monitor = watch('./config', (eventType, filename) => {
  if (filename?.endsWith('.json')) {
    console.log(`La configuración ${filename} ha cambiado via ${eventType}`);
  }
});

// Para detenerlo:
// monitor.close();

    Comparativas y Reflexión

    Característica fs.watch fs.watchFile
    Rendimiento Excelente (Event-driven) Pobre (Polling)
    Soporte OS Puede variar por plataforma Universal
    Uso recomendado Siempre que sea posible Solo si watch no funciona

    Preguntas reflexivas

    1. ¿Por qué no deberías vigilar la carpeta node_modules con watch?
    2. ¿Qué problemas de "Race Conditions" podrían ocurrir si dos procesos vigilan y escriben en el mismo archivo?
    3. ¿Cómo implementarías un sistema que recargue la configuración de tu App automáticamente sin reiniciarla?

    9. Integración con Otros Módulos y Buenas Prácticas

    9.1. Módulo Path

    REGLA DE ORO: Nunca concatenes rutas manualmente (folder + '/' + file). Usa path.join() para que funcione igual en Windows (\) que en Linux (/).

    9.2. Seguridad (Path Traversal)

    Si un usuario te envía un nombre de archivo como ../../etc/passwd, y tú lo concatenas ciegamente, ¡podría leer tus secretos! Valida siempre.

    9.4. Errores Comunes

    • ENOENT: "Error No Entity" (Archivo no encontrado).
    • EACCES: "Error Access" (Permisos insuficientes).
    • EEXIST: "Error Exist" (Ya existe y querías crearlo de cero).
