    Tema 5: El Módulo FS (File System) en Node.js

    Introducción

    En el tema anterior domamos el tiempo con Timers y Asincronía. Aprendimos a gestionar tareas que no suceden al instante. Pero, ¿de qué sirve procesar datos si estos se "evaporan" cuando apagamos el servidor? La memoria RAM es rápida, pero es volátil; es como una pizarra blanca que se borra cada noche.

    Hoy vamos a hablar de persistencia. Vamos a entrar en el almacén del servidor. El Módulo FS (File System) es el encargado de interactuar con el disco duro. Es vuestro bibliotecario personal, el mozo de almacén que guarda registros, lee configuraciones y mueve cajas de datos de un lado a otro.

    Sin el módulo FS, no podríais:
    - 📝 Guardar logs de errores.
    - ⚙️ Leer ficheros de configuración (.json o .env).
    - 🖼️ Subir imágenes de perfil de usuarios.
    - 📂 Crear carpetas dinámicamente.

    Preparaos, porque vamos a mancharnos las manos de "polvo digital" aprendiendo a manipular el sistema de archivos con TypeScript y Node.js.

    Conceptos Fundamentales

    Antes de escribir código, definamos las piezas del tablero.

    Definición: POSIX

    Siglas de Portable Operating System Interface. Es una familia de estándares (creada por la IEEE) para mantener la compatibilidad entre sistemas operativos. Node.js modela su sistema de archivos basándose en POSIX, lo que nos permite escribir código que funcione (casi) igual en Linux, macOS y Windows.

    Definición: Buffer

    Es un espacio de memoria cruda (raw memory) utilizado para almacenar datos binarios temporalmente. Cuando leemos un archivo sin especificar formato, Node.js nos devuelve un Buffer (una secuencia de bytes), no un string.

    Definición: File Descriptor (fd)

    Es un número entero que el sistema operativo asigna a un archivo abierto. Es como el "ticket de turno" que te dan en la carnicería; con ese número, el SO sabe a qué archivo te refieres en operaciones de bajo nivel.

    1. Introducción al Módulo FS

    1.1. Propósito y alcance

    El módulo fs es el puente entre tu código JavaScript/TypeScript y el disco duro físico o virtual de la máquina donde se ejecuta Node.js. A diferencia del JavaScript del navegador (que por seguridad no puede tocar tus archivos locales), en el backend tenemos poderes administrativos.

    Podemos realizar operaciones CRUD completas sobre archivos y directorios:
    - Create: Crear archivos y carpetas.
    - Read: Leer contenido y metadatos.
    - Update: Modificar, añadir contenido (append).
    - Delete: Borrar archivos y directorios.

    1.2. Arquitectura y fundamentos

    Node.js utiliza libuv por debajo para realizar estas operaciones de forma asíncrona. Aunque tu código JS es "single-threaded", las operaciones de disco se delegan al sistema operativo o a un thread pool (grupo de hilos) interno de libuv.

    Rutas: Absolutas vs Relativas

    Un error clásico de junior es confundir dónde está buscando el archivo Node.js.

    Tipo de Ruta Ejemplo Descripción
    Relativa ./data/user.json Depende desde dónde ejecutas el comando node. Peligroso en producción.
    Absoluta /var/www/app/data/user.json Ruta completa desde la raíz del disco. Es la forma segura.

    Consejo Pro: __dirname en ESM

    En CommonJS usábamos __dirname. En TypeScript moderno (ES Modules), usamos import.meta.url y path para construir rutas absolutas fiables.

    Formatos de Datos

    ¿Qué estamos leyendo? - Texto (utf8): Para archivos legibles por humanos (HTML, JSON, TXT). - Binario (Buffer): Para imágenes, PDFs, ejecutables o cuando no sabemos qué es.

    1.3. Importación

    Desde Node.js 16+, la recomendación oficial y el estándar de la industria es usar el prefijo de protocolo node:. Esto hace que la importación sea explícita, segura y ligeramente más rápida.

    // ❌ Forma antigua (aún funciona, pero evítala en proyectos nuevos)
import fs from 'fs';

// ✅ Forma moderna y profesional
import fs from 'node:fs'; 
import fsPromises from 'node:fs/promises'; // Para la API de promesas

    Ejemplo 1: Importación moderna (ES Modules & TypeScript) 

    // 🟢 RECOMENDADO: Uso explícito de 'node:' y promesas por defecto
import * as fs from 'node:fs/promises';
import { constants } from 'node:fs';

// Para operaciones síncronas (raras) o streams, a veces importamos la base:
import { readFileSync, createReadStream } from 'node:fs';

    Ejemplo 2: Uso de __dirname en ESM En CommonJS (el sistema antiguo) __dirname existía mágicamente. En ES Modules (el estándar actual), debemos construirlo.

    import path from 'node:path';
import { fileURLToPath } from 'node:url';

// Recreando __dirname en ES Modules
const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

console.log(`Estoy ejecutándome en: ${__dirname}`);

    Ejemplo 3: Constantes del sistema 

    import { constants } from 'node:fs';

// Verificamos si tenemos permisos de lectura (R_OK) o escritura (W_OK)
// Estas constantes son máscaras de bits utilizadas por el sistema operativo
console.log('Valor constante Lectura:', constants.R_OK); 
console.log('Valor constante Escritura:', constants.W_OK);

    1.4. Las tres APIs disponibles

    Node.js es único porque ofrece tres formas distintas de hacer exactamente lo mismo. Entender cuál usar separa al junior del senior.

    1. Callbacks (Legacy): fs.readFile(path, (err, data) => ...)
    2. Síncrona (Blocking): fs.readFileSync(path)
    3. Promesas (Modern): await fs.readFile(path)
    Característica Callbacks Síncrona Promesas

    Bloquea Event Loop No SÍ (Peligro) No
    Manejo de Errores if (err) try/catch try/catch
    Uso Recomendado Rendimiento extremo Scripts CLI / Config General (App Web)
    Concepto Buffer String (utf8)
    ¿Qué es? Datos binarios crudos (bytes) Texto legible por humanos
    Uso Imágenes, PDFs, Zips JSON, HTML, TXT, Logs
    Velocidad Más rápido (sin conversión) Ligeramente más lento

    2. Las Tres APIs de FS: Diferencias y Cuándo Usar Cada Una

    Esta es la sección más crítica para el rendimiento de tu aplicación. Elegir la API incorrecta puede convertir un servidor rápido en una tortuga.

    2.1. API síncrona (bloqueante)

    Los métodos terminan en Sync (ej. readFileSync). Comportamiento: Node.js detiene todo el universo hasta que el disco duro responde. Si el disco tarda 1 segundo, tu servidor no responde a ninguna otra petición durante ese segundo.

    ¡Peligro!

    Nunca uses métodos Sync dentro de una ruta de Express/Fastify o en bucles calientes. Matarás la escalabilidad de tu API.

    Ejemplo Código Síncrono (TypeScript): 

    import { readFileSync } from 'node:fs';

try {
  // Bloqueamos a propósito: la app no puede arrancar sin config
  const rawData = readFileSync('./config.json', 'utf-8');
  const config = JSON.parse(rawData);
  console.log('✅ Configuración cargada:', config.dbName);
} catch (error) {
  console.error('❌ Error crítico: No se pudo leer config.json');
  process.exit(1); // Cerramos la app
}

    2.2. API de callbacks (asíncrona tradicional)

    Usa el patrón "Error-First Callback". No bloquea, pero anidar varias operaciones lleva al temido "Callback Hell".

    Ejemplo Código Callbacks (TypeScript): 

    import { readFile } from 'node:fs'; // Nota: sin /promises

// El código sigue ejecutándose inmediatamente después de llamar a readFile
readFile('./archivo.txt', 'utf-8', (err, data) => {
  if (err) {
    console.error('Error de lectura:', err.message);
    return;
  }
  console.log('Contenido recibido:', data);
});

console.log('👋 Esto se imprime ANTES que el contenido del archivo');

    2.3. API de promesas (fs/promises)

    El estándar moderno. Permite usar async/await, haciendo que el código asíncrono parezca síncrono (fácil de leer) pero sin bloquear el Event Loop.

    Ejemplo 3: Promesas - Lectura Secuencial con Async/Await 

    import { readFile, writeFile } from 'node:fs/promises';

async function duplicarArchivo() {
  try {
    // 1. Leemos (No bloquea otros procesos)
    const contenido = await readFile('./original.txt', 'utf-8');

    // 2. Procesamos
    const nuevoContenido = contenido.toUpperCase();

    // 3. Escribimos
    await writeFile('./copia_mayus.txt', nuevoContenido);
    console.log('✨ Proceso completado');

  } catch (error) {
    console.error('Algo falló:', error);
  }
}

duplicarArchivo();

    sequenceDiagram

    App->>EventLoop: readFileSync()
    EventLoop->>FS: Leer Disco
    activate FS
    FS-->>EventLoop: Datos
    deactivate FS
    EventLoop-->>App: Retorna Datos
    Note right of App: ¡Todo lo demás esperó!

    Note over App, FS: Escenario Asíncrono (Non-Blocking)
    App->>EventLoop: readFile() (Promesa)
    EventLoop->>FS: Solicitar Lectura
    EventLoop-->>App: Promesa (Pending)

    activate FS
    FS-->>EventLoop: Datos Listos
    deactivate FS
    EventLoop-->>App: Promesa Resuelta
    Característica API Síncrona (Sync) API Promesas (await) API Callbacks
    Bloqueo Event Loop SÍ (Total) NO NO
    Legibilidad Alta Alta Baja (si se anida)
    Manejo Errores try/catch try/catch if (err)
    Caso de Uso Configuración al inicio Rutas de API, Lógica de negocio Librerías de muy bajo nivel

    3. Operaciones Básicas de Lectura y Escritura

    Vamos a trabajar con las operaciones más comunes. A partir de aquí, usaremos preferentemente node:fs/promises.

    3.1. Lectura de archivos (readFile)

    Como vimos, readFile carga todo el archivo en memoria RAM.

    Cuidado con la RAM

    No uses readFile para archivos de vídeo o logs gigantes (GBs). Si lees un archivo de 4GB en un servidor con 2GB de RAM, la aplicación crasheará por Out of Memory. Para eso existen los Streams (punto 7).

    Ejemplo 1: Leyendo un JSON de configuración 

    import { readFile } from 'node:fs/promises';

interface AppConfig {
  port: number;
  dbUrl: string;
}

async function loadConfig(path: string): Promise<AppConfig | null> {
  try {
    // Especificamos utf-8 para recibir un string
    const rawData = await readFile(path, { encoding: 'utf-8' });
    const config: AppConfig = JSON.parse(rawData);
    return config;
  } catch (error) {
    console.error(`No se pudo leer la config en ${path}`);
    return null;
  }
}

    3.2. Escritura de archivos (writeFile)

    Este método escribe datos en un archivo. Si el archivo ya existe, lo reemplaza por completo (lo sobrescribe).

    Flags comunes: * 'w': Escritura (defecto). Crea o trunca. * 'wx': Igual que 'w', pero falla si el archivo ya existe (seguridad para no sobrescribir).

    Ejemplo 2: Guardando datos de usuario 

    import { writeFile } from 'node:fs/promises';

const userData = {
  id: 1,
  username: "DevMaster",
  lastLogin: new Date().toISOString()
};

async function saveUserSession() {
  try {
    // flag 'wx' lanzará error si session.json ya existe
    await writeFile('session.json', JSON.stringify(userData, null, 2), { flag: 'wx' });
    console.log('Sesión guardada.');
  } catch (error: any) {
    if (error.code === 'EEXIST') {
      console.warn('¡El archivo de sesión ya existe! No lo sobrescribí.');
    } else {
      throw error;
    }
  }
}

    3.3. Añadir contenido (appendFile)

    Ideal para logs. Agrega datos al final del archivo sin borrar lo anterior.

    Ejemplo 3: Sistema de Logging simple 

    import { appendFile } from 'node:fs/promises';
import { EOL } from 'node:os'; // End Of Line (salto de línea multiplataforma)

async function logError(message: string) {
  const timestamp = new Date().toISOString();
  const logEntry = `[${timestamp}] ERROR: ${message}${EOL}`;

  try {
    await appendFile('server.log', logEntry, 'utf-8');
  } catch (error) {
    console.error('¡No pude escribir en el log!', error);
  }
}

    Comparativa de Flags

    Flag Significado Comportamiento si existe Comportamiento si NO existe
    'w' Write Lo borra y sobrescribe Lo crea
    'wx' Write Exclusive Error (EEXIST) Lo crea
    'a' Append Escribe al final Lo crea
    'r' Read Lee Error (ENOENT)

    🧠 Ejercicios Reflexivos

    1. ¿Qué pasaría si intentas hacer un writeFile en una carpeta que no existe? (Pista: Error ENOENT).
    2. ¿Por qué es importante usar EOL del módulo os en lugar de simplemente poner \n?
    3. En un sistema de logs concurrente (muchas peticiones a la vez), ¿garantiza appendFile que las líneas se escriban en orden cronológico perfecto?


    4. Gestión de Directorios y Estructuras

    No solo vivimos de archivos planos; necesitamos organizar la casa.

    4.1. Creación (mkdir)

    La opción mágica aquí es recursive: true. Es como decirle al albañil: "Construye la habitación, y si falta la casa o el barrio, constrúyelos también".

    Ejemplo: Crear estructura anidada 

    import { mkdir } from 'node:fs/promises';

async function setupProjectStructure() {
  const path = './uploads/2025/january';

  try {
    // Sin recursive: true, esto fallaría si 'uploads' no existe
    const createdPath = await mkdir(path, { recursive: true });
    console.log(`📁 Directorios creados en: ${createdPath}`);
  } catch (error) {
    console.error('Error creando directorios:', error);
  }
}

    4.2. Listado (readdir)

    Podemos listar solo los nombres (strings) o pedir objetos Dirent para saber qué son.

    Ejemplo: Listar contenido distinguiendo carpetas de archivos 

    import { readdir } from 'node:fs/promises';

async function listContent(path: string) {
  try {
    // withFileTypes devuelve objetos Dirent en lugar de strings
    const entries = await readdir(path, { withFileTypes: true });

    for (const entry of entries) {
      const icon = entry.isDirectory() ? '📁' : '📄';
      console.log(`${icon} ${entry.name}`);
    }
  } catch (error) {
    console.error('Error listando directorio:', error);
  }
}

    4.3. Eliminación de carpetas (rm vs rmdir)

    Históricamente existía rmdir, que solo borraba carpetas vacías. Ahora usamos rm (similar al comando de Unix) que es más potente.

    Ejemplo: Limpieza de temporales 

    import { rm } from 'node:fs/promises';

async function limpiarTemp() {
  try {
    // force: true evita error si no existe. 
    // recursive: true borra carpetas con contenido.
    await rm('./temp', { recursive: true, force: true });
    console.log('🧹 Temporales eliminados');
  } catch (error) {
    console.error('Error al limpiar:', error);
  }
}

    Método Elimina carpeta con contenido Recursivo Nota
    rmdir ❌ No ❌ No Obsoleto para carpetas llenas
    rm ✅ Sí ✅ Sí (con recursive: true) La opción moderna

    5. Manipulación de Archivos Individuales

    A veces necesitamos mover las cosas de sitio o borrarlas definitivamente.

    5.1. Ciclo de Vida de un Archivo

    stateDiagram-v2
    [*] --> Inexistente
    Inexistente --> Existente: writeFile / appendFile
    Existente --> Modificado: writeFile / appendFile
    Existente --> Renombrado: rename
    Existente --> Inexistente: unlink / rm
    Renombrado --> Inexistente: unlink

    5.2. Renombrar y Mover (rename)

    En sistemas POSIX, mover un archivo y renombrarlo es la misma operación. Simplemente cambias su ruta.

    Ejemplo: Mover archivo de "temp" a "procesados" 

    import { rename } from 'node:fs/promises';
import { join } from 'node:path';

async function moveProcessedFile(fileName: string) {
  const oldPath = join('temp', fileName);
  const newPath = join('processed', fileName);

  try {
    await rename(oldPath, newPath);
    console.log('Archivo movido exitosamente');
  } catch (error) {
    console.error('Error al mover archivo:', error);
  }
}

    5.3. Copiar (copyFile)

    A veces necesitamos duplicar sin alterar el original.

    Ejemplo: Backup seguro Usamos constantes (COPYFILE_EXCL) para evitar destruir un backup previo por error.

    import { copyFile, constants } from 'node:fs'; // constants viene del callback API
import { copyFile as copyFileAsync } from 'node:fs/promises';

async function backupDB() {
  try {
    // COPYFILE_EXCL: Falla si destino ya existe
    await copyFileAsync('db.sqlite', 'db.backup.sqlite', constants.COPYFILE_EXCL);
    console.log('Backup realizado.');
  } catch (error) {
    console.error('Error backup:', error);
  }
}

    5.4. Metadatos (stat)

    El inspector de archivos. Nos dice cuándo se creó, cuánto pesa y quién es el dueño.

    Ejemplo: Comprobar tamaño antes de procesar 

    import { stat } from 'node:fs/promises';

async function checkFileSize(filePath: string) {
  try {
    const fileStats = await stat(filePath);

    console.log(`Tamaño: ${fileStats.size} bytes`);
    console.log(`Es archivo: ${fileStats.isFile()}`);
    console.log(`Creado: ${fileStats.birthtime}`);

    if (fileStats.size > 1024 * 1024) {
      console.warn('⚠️ El archivo pesa más de 1MB');
    }
  } catch (error) {
    console.error('No se pudo obtener info del archivo');
  }
}

    5.5. Diferencia stat vs lstat

    Para saber el tamaño, fecha de creación o permisos.

    Tip Profesional: stat vs lstat

    • stat: Si apuntas a un enlace simbólico (acceso directo), te da info del archivo real.
    • lstat: Te da info del enlace simbólico en sí mismo.

    Ejemplo: Inspeccionar archivo 

    import { stat } from 'node:fs/promises';

async function checkSize(archivo: string) {
  const datos = await stat(archivo);

  const sizeMB = datos.size / (1024 * 1024);
  console.log(`Tamaño: ${sizeMB.toFixed(2)} MB`);
  console.log(`Modificado: ${datos.mtime.toLocaleString()}`);
  console.log(`Es archivo?: ${datos.isFile()}`);
}

    Comando Acción Equivalente CLI (Linux)
    unlink Borrar archivo rm archivo
    rename Mover/Renombrar mv origen destino
    copyFile Copiar cp origen destino
    stat Ver info ls -l / stat

    6. Control de Acceso y Permisos

    Seguridad ante todo. No queremos que cualquiera lea nuestros secretos.

    Condición de Carrera (Race Condition)

    NO HAGAS ESTO: if (await access(file)) { await readFile(file) }. Entre el chequeo (access) y la lectura (readFile), otro proceso podría haber borrado el archivo. MEJOR: Intenta leer directamente y maneja el error try/catch.

    6.1. Verificación (access)

    Antes de intentar abrir un archivo, es educado preguntar si tenemos permiso. Usamos constantes para esto.

    Ejemplo: Verificar si puedo escribir 

    import { access, constants } from 'node:fs/promises';

async function checkPermissions(path: string) {
  try {
    // Comprobamos si es legible (R_OK) y escribible (W_OK)
    await access(path, constants.R_OK | constants.W_OK);
    console.log('Tengo permisos de lectura y escritura');
  } catch {
    console.error('⛔ No tengo acceso al archivo');
  }
}

    6.2. Nuevo modelo de permisos (Node.js 22+)

    Node.js históricamente tenía acceso a todo. Inspirado en Deno, las versiones recientes introducen un modelo de seguridad experimental (pero que será estándar).

    Se activa al ejecutar el script, no en el código: 

    node --allow-fs-read="./data/*" --allow-fs-write="./logs/*" server.js
    Esto confina a tu aplicación a leer/escribir SOLO en esas carpetas. Si intenta leer /etc/passwd, fallará.

    6.3. Modificación (chmod)

    Cambiar permisos (Change Mode). Usa el sistema octal de Unix.

    Valor Octal Permiso
    4 Lectura (r)
    2 Escritura (w)
    1 Ejecución (x)

    Ejemplo: chmod 755 -> Dueño (7=4+2+1), Grupo (5=4+1), Otros (5=4+1).

    Ejemplo de código: 

    import { chmod } from 'node:fs/promises';

// Hacer un archivo de solo lectura para todos (444)
await chmod('./config-bloqueada.json', 0o444);

    Ejemplo: Hacer un script privado (Solo lectura/escritura para el dueño) 

    import { chmod } from 'node:fs/promises';

async function protegerClaves() {
  // 0o600: Dueño (rw-), Grupo (---), Otros (---)
  // Usamos notación octal (0o)
  await chmod('./claves_secretas.pem', 0o600);
  console.log('Permisos restringidos.');
}

    7. Operaciones Avanzadas con Streams y Optimización

    Aquí es donde se distingue a un junior de un senior. Cuando los datos son grandes, no los cargamos, los hacemos fluir.

    7.1. El problema de readFile

    Imagina una tubería. readFile es llenar un cubo gigante de agua y luego intentar levantarlo. Stream es conectar una manguera.

    7.2. Streams y Pipeline

    Usamos createReadStream para leer trozo a trozo (chunks) y pipeline para conectar origen con destino gestionando errores automáticamente.

    graph LR
    A["Archivo Gigante 5GB"] -->|"Chunk 1 (64KB)"| B["Stream Lectura"]
    B -->|pipe| C["Transformación/Gzip"]
    C -->|pipe| D["Stream Escritura"]
    D --> E["Nuevo Archivo"]
    style B fill:#f9f,stroke:#333
    style D fill:#f9f,stroke:#333

    Ejemplo: Copia eficiente de archivo gigante con compresión 

    import { createReadStream, createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';
import { createGzip } from 'node:zlib';

async function comprimirArchivo(input: string, output: string) {
  // Estos streams no cargan los 5GB en RAM, solo 64KB a la vez
  const source = createReadStream(input);
  const destination = createWriteStream(output);
  const gzip = createGzip();

  try {
    // Conectamos: Origen -> Compresor -> Destino
    await pipeline(source, gzip, destination);
    console.log('Compresión finalizada sin explotar la RAM 🚀');
  } catch (error) {
    console.error('Error en el pipeline:', error);
  }
}

    7.3. Iterar Streams con async/await

    Una maravilla de Node moderno. Podemos recorrer un archivo gigante línea a línea o chunk a chunk con un bucle for.

    import { createReadStream } from 'node:fs';

async function procesarLogGigante() {
  const stream = createReadStream('./server_big.log', { encoding: 'utf-8' });

  for await (const chunk of stream) {
    // Aquí 'chunk' es un pedazo de texto
    if (chunk.includes('ERROR CRITICO')) {
      console.log('¡Encontré un error en este trozo!');
    }
  }
}

    8. Observabilidad y Monitoreo

    ¿Y si queremos saber cuándo cambia un archivo? Ideal para herramientas de desarrollo (como nodemon o vite). Podemos pedirle a Node.js que nos avise si un archivo cambia.

    8.1. watch vs watchFile

    • watch: Usa eventos nativos del SO. Es eficiente y rápido. (Recomendado).
    • watchFile: Hace polling (pregunta cada X ms: "¿Cambiaste?"). Ineficiente, usa CPU. (Evitar).

    8.2. Caso de uso: Hot Reload

    Imagina reiniciar tu servidor automáticamente cuando cambias la configuración.

    Ejemplo: Vigilar cambios en config 

    import { watch } from 'node:fs/promises';

async function vigilarConfig() {
  const watcher = watch('./config.json');

  console.log('👀 Vigilando config.json...');

  for await (const event of watcher) {
    console.log(`Evento detectado: ${event.eventType}`);
    // Aquí recargaríamos la configuración
    console.log('🔄 Recargando configuración...');
  }
}
// Nota: watch devuelve un AsyncIterator

    Ejemplo 2: Watcher robusto con AbortController Para detener la vigilancia limpiamente. 

    import { watch } from 'node:fs';

const ac = new AbortController();
const { signal } = ac;

const watcher = watch('./temp', { signal }, (eventType, filename) => {
  console.log(`Cambio en ${filename}: ${eventType}`);
});

// Detener después de 10 segundos
setTimeout(() => {
  ac.abort();
  console.log('🛑 Vigilancia detenida.');
}, 10000);

    Tabla Comparativa: Watchers

    Método Rendimiento Exactitud Soporte OS
    fs.watch Alto (Usa eventos nativos del SO) Variable (a veces duplica eventos) Dependiente del SO
    fs.watchFile Bajo (Hace polling, consulta cada X ms) Constante pero lento Universal (menos eficiente)

    Recomendación

    En proyectos reales, usa librerías como Chokidar. Envuelven fs.watch y arreglan todas las inconsistencias entre Windows, Mac y Linux (eventos duplicados, etc).


    9. Integración con Otros Módulos y Buenas Prácticas

    El módulo FS nunca trabaja solo; su mejor amigo es el módulo path.

    9.1. El Módulo Path

    Jamás concatener strings para rutas ('folder/' + file). Eso rompe en Windows (que usa \). Usa path.join.

    import { join, resolve } from 'node:path';

// ✅ Correcto: Funciona en Windows y Linux
const rutaSegura = join('data', 'uploads', 'image.png'); 

// ❌ Incorrecto
const rutaMala = 'data/uploads/image.png';

    9.2. Seguridad: Path Traversal

    Un ataque clásico. Un usuario malicioso intenta acceder a ../../../../etc/passwd.

    Ejemplo de validación: 

    import { normalize, resolve } from 'node:path';

function esRutaSegura(inputPath: string): boolean {
  const rutaBase = resolve('./user_uploads');
  const rutaObjetivo = resolve(rutaBase, inputPath);

  // Verificamos que la ruta objetivo siga empezando por la ruta base
  return rutaObjetivo.startsWith(rutaBase);
}

    9.3. Manejo de Errores Comunes

    No todos los errores son iguales. - ENOENT: Error No Entry (Archivo no encontrado). - EACCES: Error Access (Permiso denegado). - EEXIST: Error Exist (El archivo ya existe y no debía).

    Ejemplo 3: Try-Catch con chequeo de código 

    try {
  await fs.readFile('no-existe.txt');
} catch (error: any) {
  if (error.code === 'ENOENT') {
    console.log('El archivo no está, crearemos uno por defecto.');
  } else if (error.code === 'EACCES') {
    console.error('¡No tengo permisos! Ejecuta como admin/sudo.');
  } else {
    throw error; // Re-lanzar si es algo inesperado
  }
}

    En tests unitarios, nunca escribas en el disco real (es lento y sucio). Usa librerías como memfs o haz mocks de fs.

    10. Conclusión y Recursos

    El módulo FS es como la memoria a largo plazo de vuestras aplicaciones. Mientras que las variables son pensamientos fugaces, los archivos son los libros que escribís para la posteridad.

    Hemos pasado de usar métodos bloqueantes (como escribir a cincel en piedra) a usar Streams y Promesas (como una impresora láser de alta velocidad). Recordad: un buen desarrollador backend trata el disco duro con respeto: lee poco, escribe con seguridad y nunca, nunca bloquea el Event Loop.

    ¡Nos vemos en el siguiente tema, donde conectaremos todo esto a la red con el módulo HTTP! 🚀

    El módulo fs es el puente entre tu lógica de negocio y los datos persistentes físicos.

    1. Promesas por defecto: Usa node:fs/promises para casi todo.
    2. Streams para volumen: Si pesa más de 10-20MB, usa Streams.
    3. Cross-Platform: Usa siempre el módulo path.
    4. No bloquees: Evita *Sync en rutas calientes.

    Ahora que sabes manejar archivos, el siguiente paso lógico es ¿dónde guardar esos archivos si mi servidor escala a 10 máquinas? (Spoiler: Cloud Storage como S3), o ¿cómo estructurar esos datos? (Spoiler: Bases de Datos).
