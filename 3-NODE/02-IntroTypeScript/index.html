    Tema 2: TypeScript

    Introducción

    Imagina que estás construyendo un rascacielos. JavaScript (JS) es como construirlo con materiales flexibles: rápido, dinámico, pero si te equivocas en los cimientos, el edificio se tambalea cuando ya tienes 10 pisos. TypeScript (TS) es como ponerle un andamiaje de acero reforzado y planos de arquitectura milimétricos a ese proceso.

    TypeScript no es un lenguaje nuevo que reemplaza a JavaScript; es JavaScript con superpoderes. Es lo que llamamos un superset: todo código JS válido es código TS válido, pero TS añade una capa de tipado estático que nos permite detectar errores mientras escribimos el código, no cuando el usuario está intentando comprar algo en nuestra web y todo explota.

    En el mundo del desarrollo Backend con Node.js profesional, TypeScript se ha convertido en el estándar de facto. ¿Por qué? Porque cuando tu servidor crece de 5 archivos a 500, necesitas saber exactamente qué datos entran y salen de tus funciones.

    Conceptos Fundamentales

    Definición: TypeScript

    Lenguaje de programación libre y de código abierto desarrollado por Microsoft. Es un superconjunto tipado de JavaScript que se compila (transpila) a JavaScript plano para que pueda ser ejecutado por navegadores o Node.js.

    Definición: Transpilación

    Proceso de traducir código fuente de un lenguaje a otro lenguaje similar (de alto nivel a alto nivel). En nuestro caso, convertimos .ts (TypeScript) a .js (JavaScript) usando el compilador tsc.

    1. Introducción a TypeScript

    ¿Qué es TypeScript y por qué usarlo en Node.js?

    JavaScript fue diseñado en 10 días para dar dinamismo a las webs de los 90. No estaba pensado para grandes arquitecturas de servidor. Su sistema de tipos es dinámico y débil: una variable puede ser un número hoy y un texto mañana. Esto, que parece libertad, es la fuente del 80% de los errores en producción ("undefined is not a function").

    TypeScript resuelve esto añadiendo tipado estático. Tú defines qué es cada cosa. Si dices que una función recibe un número, TS no te dejará pasarle un texto, y te avisará con una línea roja en tu editor antes de que ejecutes nada.

    Ventajas en Node.js:
    1. Detección temprana de errores: Cazas los bugs al escribir, no en tiempo de ejecución (runtime).
    2. Intellisense (Autocompletado): Como el editor sabe qué tipo de dato es cada variable, te sugiere sus métodos. ¡Adiós a mirar la documentación cada 5 segundos!
    3. Refactorización segura: Cambiar el nombre de una función o variable en 100 archivos se hace con un clic sin miedo a romper nada.

    Configuración del proyecto

    Para usar TypeScript, necesitamos instalar el compilador. En un proyecto Node.js, esto suele ser una dependencia de desarrollo (devDependencies), ya que en producción ejecutaremos el JS resultante.

    # Inicializar proyecto node
npm init -y

# Instalar TypeScript como dependencia de desarrollo
npm install typescript --save-dev

# Generar el archivo de configuración tsconfig.json
npx tsc --init

    El archivo tsconfig.json es el cerebro del compilador. Aquí definimos cuán estricto queremos que sea TS y dónde guardar los archivos compilados.

    Ejemplo de tsconfig.json recomendado para Node moderno:

    {
  "compilerOptions": {
    "target": "ES2022",                                  /* Versión de JS a generar */
    "module": "NodeNext",                                /* Sistema de módulos */
    "rootDir": "./src",                                  /* Dónde está mi código TS */
    "outDir": "./dist",                                  /* Dónde guardar el JS compilado */
    "strict": true,                                      /* Modo estricto activado (OBLIGATORIO en clase) */
    "esModuleInterop": true,                             /* Compatibilidad con módulos CommonJS */
    "skipLibCheck": true,                                /* Saltar chequeo de tipos en librerías externas */
    "forceConsistentCasingInFileNames": true             /* Evitar problemas entre Windows/Mac */
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules"]
}

    Diferencias clave con JavaScript

    Característica JavaScript (JS) TypeScript (TS)
    Tipado Dinámico (se conoce al ejecutar) Estático (se conoce al compilar)
    Errores Saltan en tiempo de ejecución (Runtime) Saltan en tiempo de compilación/edición
    Archivos Extensión .js Extensión .ts
    Ejecución Directa en Navegador/Node Requiere compilación previa a JS
    Datos Datos flexibles Contratos de datos estrictos
    let a = 10; a = "hola"; (Válido) let a: number = 10; a = "hola"; (Error)

    Inferencia de Tipos

    TypeScript es inteligente. No siempre necesitas decirle el tipo de todo. Si asignas un valor claro, TS infiere su tipo.

    // TypeScript explícito
const userName: string = 'Alan Turing';

// TypeScript por inferencia (Recomendado cuando es obvio)
const userAge = 42; 
// TS sabe que userAge es 'number'. Si intentas userAge = "cuarenta", fallará.
    Ejemplo comparativo:

    JavaScript (Peligroso): 

    function calcularPrecio(precio, impuesto) {
    return precio + impuesto; // Si impuesto es "10" (string), concatena: "10010"
}
console.log(calcularPrecio(100, "10")); // Resultado: "10010" (Error lógico grave)

    TypeScript (Seguro): 

    function calcularPrecio(precio: number, impuesto: number): number {
    return precio + impuesto;
}
// calcularPrecio(100, "10"); // ERROR: Argument of type 'string' is not assignable to parameter of type 'number'.

    Consejo Profesional

    Usa la inferencia de tipos siempre que sea posible para mantener el código limpio. Solo anota los tipos explícitamente cuando TS no pueda adivinarlos o cuando quieras asegurar un contrato específico (por ejemplo, en parámetros de funciones).

    Diagrama del Proceso de Compilación

    graph LR
    A[Código Fuente .ts] -->|Desarrollador escribe| B(Editor con TS Server)
    B -->|Muestra errores en tiempo real| A
    A -->|Comando 'tsc'| C{Compilador TypeScript}
    C -- Errores --> D[Terminal muestra fallos]
    C -- Éxito --> E[Código Generado .js]
    E -->|Ejecución| F[Node.js Runtime]

    2. Tipos básicos y avanzados

    TypeScript hereda los tipos primitivos de JS y añade una capa de tipos estructurales para poner orden en el caos.

    Tipos primitivos

    Son los bloques de construcción fundamentales, idénticos a los de JavaScript pero con esteroides de validación.

    // String
const fullName: string = 'Grace Hopper';

// Number (enteros, flotantes, hex, binarios...)
const count: number = 10;
const price: number = 99.99;

// Boolean
const isActive: boolean = true;

// Ejemplo de error detectado por TS
// count = "diez"; // Error: Type 'string' is not assignable to type 'number'.

    Arrays, Tuples y Enums

    Arrays: Listas de elementos. Podemos definirlos de dos formas.

    // Forma 1 (más común)
const skills: string[] = ['JS', 'TS', 'Node'];

// Forma 2 (Genéricos - veremos esto más adelante)
const levels: Array<number> = [1, 2, 3];

    Tuples (Tuplas): Arrays de longitud fija y tipos conocidos en posiciones específicas. Muy útiles para coordenadas o devolver múltiples valores simples.

    // Definimos una tupla: [string, number]
let userRecord: [string, number];

userRecord = ['User1', 101]; // Correcto
// userRecord = [101, 'User1']; // Error: El orden importa

    Enums: Una forma de dar nombres amigables a conjuntos de valores numéricos o cadenas. Ojo: Esto sí genera código extra en JS (no desaparece al compilar como las interfaces).

    enum UserRole {
  ADMIN = 'admin',
  EDITOR = 'editor',
  GUEST = 'guest'
}

const currentUserRole: UserRole = UserRole.ADMIN;

if (currentUserRole === UserRole.ADMIN) {
  console.log('Tienes el poder absoluto');
}

    Any, Unknown, Void y Never

    Aquí entramos en terreno peligroso y avanzado.

    Tipo Descripción Uso recomendado
    Any Desactiva el chequeo de tipos. "Confía en mí". EVITAR. Solo para migraciones de JS antiguo.
    Unknown "No sé qué es, pero no te dejaré usarlo hasta que lo compruebes". Alternativa segura a any para datos externos (APIs).
    Void Ausencia de valor. Retorno de funciones que no devuelven nada.
    Never Valores que nunca ocurren. Funciones que lanzan errores siempre o bucles infinitos. 
    // --- ANY vs UNKNOWN ---

let badVariable: any = 10;
badVariable.metodoQueNoExiste(); // TS no se queja, pero explotará en runtime. ¡PELIGRO!

let safeVariable: unknown = 10;
// safeVariable.toFixed(2); // Error: Object is of type 'unknown'. TS te protege.

// Para usar unknown, debemos hacer "Type Narrowing" (estrechar el tipo)
if (typeof safeVariable === 'number') {
  console.log(safeVariable.toFixed(2)); // Ahora sí, TS sabe que es número en este bloque.
}

// --- VOID vs NEVER ---

function logMessage(msg: string): void {
  console.log(msg);
  // Retorna undefined implícitamente
}

function throwError(msg: string): never {
  throw new Error(msg);
  // Nunca llega al final de la función, rompe el flujo
}

    Union Types e Intersection Types

    Union Types (|): "Puede ser esto O aquello". Es el operador lógico OR de los tipos.

    let id: string | number;
id = 101;      // OK
id = 'USER-1'; // OK
// id = true;  // Error

    Intersection Types (&): "Debe tener todo lo de esto Y todo lo de aquello". Combina múltiples tipos en uno nuevo.

    type Draggable = { drag: () => void };
type Resizable = { resize: () => void };

// Un widget UI debe poder arrastrarse Y redimensionarse
type UIWidget = Draggable & Resizable;

const box: UIWidget = {
  drag: () => console.log('Dragging'),
  resize: () => console.log('Resizing')
};

    Type Aliases y Literal Types

    Type Aliases: Crear un nombre personalizado para un tipo. Literal Types: Especificar el valor exacto que puede tener una variable.

    // Type Alias para un ID
type UserID = string | number;

// Literal Types combinados con Union
type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE';

function request(url: string, method: HttpMethod) {
  // ...
}

request('/api/users', 'GET'); // OK
// request('/api/users', 'PATCH'); // Error: "PATCH" no está en la lista permitida

    3. Nulabilidad y manejo de valores opcionales

    Tony Hoare, el inventor de la referencia nula, lo llama su "error de mil millones de dólares". En JS, intentar leer propiedades de null o undefined rompe la aplicación. TS se toma esto muy en serio.

    Strict Null Checks

    En el archivo tsconfig.json, cuando strict es true, TS activa strictNullChecks. Esto significa que null y undefined no son válidos para tipos como string o number a menos que lo digas explícitamente.

    let myName: string = "Ada";
// myName = null; // Error en modo estricto: Type 'null' is not assignable to type 'string'.

let myNullableName: string | null = "Ada";
myNullableName = null; // Ahora sí es válido

    Optional Properties y Parámetros

    Usamos el símbolo ? para indicar que algo puede no existir (es decir, puede ser undefined).

    type Product = {
  id: number;
  name: string;
  description?: string; // Opcional: puede ser string o undefined
};

const mouse: Product = {
  id: 1,
  name: 'Logitech MX'
  // description no es obligatorio
};

    Optional Chaining (?.) y Nullish Coalescing (??)

    Estas dos joyas nos ahorran montones de if (objeto && objeto.propiedad).

    Optional Chaining (?.): Si lo de la izquierda es null o undefined, detiene la evaluación y devuelve undefined, en lugar de lanzar error.

    Nullish Coalescing (??): Proporciona un valor por defecto SOLO si el valor es null o undefined.

    Operador Comportamiento Diferencia clave con ||
    ?. Acceso seguro a propiedades anidadas Evita el error "Cannot read property of undefined"
    ?? Valor por defecto para nulos || considera el 0 y "" como falsos. ?? los respeta. 
    const userResponse = {
  profile: {
    name: 'Alice',
    age: 0 // Ojo, edad 0 es un valor válido
  }
};

// --- Optional Chaining ---
// Si 'settings' no existe, devuelve undefined, no explota
const theme = userResponse.profile?.settings?.theme; 

// --- Nullish Coalescing vs OR ---
// Queremos mostrar la edad o 18 por defecto
const realAge = userResponse.profile.age ?? 18; // Resultado: 0 (Correcto)
const badAge = userResponse.profile.age || 18;  // Resultado: 18 (Incorrecto, 0 es falsy en JS)

console.log(`Edad real: ${realAge}, Edad con OR: ${badAge}`);

    Cuidado con el Operador OR ||

    En JavaScript/TypeScript, el operador || se usa a menudo para valores por defecto. Pero recuerda que 0, "" (string vacío) y false activan el ||. Si esos son valores válidos para tu lógica, usa siempre ??.

    Non-null assertion operator (!)

    Es decirle al compilador: "Cállate, yo sé que esto no es nulo". Úsalo con extrema precaución.

    const input = document.getElementById("email-input"); 
// TS dice que input puede ser HTMLElement | null

// Si estamos 100% seguros de que existe en el HTML:
const value = input!.value; // El ! fuerza a TS a tratarlo como existente

      let street;

    4. Funciones en TypeScript

    Las funciones son ciudadanas de primera clase en JS/TS. En TypeScript, la obsesión es tipar qué entra (parámetros) y qué sale (retorno).

    Tipado de parámetros y retorno

    // Función clásica
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const subtract = (a: number, b: number): number => {
  return a - b;
};

// Inferencia de retorno: TS sabe que number * number = number
const multiply = (a: number, b: number) => a * b;

    Funciones sobrecargadas (Overloads)

    A veces una función puede comportarse diferente según los argumentos. TypeScript permite definir múltiples firmas (signatures) para una sola implementación.

    // Firmas (Overloads) - Lo que ve el usuario/editor
function makeDate(timestamp: number): Date;
function makeDate(m: number, d: number, y: number): Date;

// Implementación (Debe ser compatible con todas las firmas)
function makeDate(mOrTimestamp: number, d?: number, y?: number): Date {
  if (d !== undefined && y !== undefined) {
    return new Date(y, mOrTimestamp - 1, d);
  } else {
    return new Date(mOrTimestamp);
  }
}

const d1 = makeDate(12345678);        // OK
const d2 = makeDate(5, 5, 2025);      // OK
// const d3 = makeDate(5, 5);         // Error: No coincide con ninguna firma

    // 1. Firmas (Lo que ve el exterior)
function getInfo(id: number): string;
function getInfo(email: string): string;

// 2. Implementación (Lo que hace la función, debe cubrir todos los casos)
function getInfo(valor: number | string): string {
    if (typeof valor === "number") {
        return `Buscando usuario por ID: ${valor}`;
    } else {

    Parámetros opcionales, por defecto y Rest

    1. Opcionales (?): Al final de la lista.
    2. Por defecto (= value): Si no se pasa, toma ese valor.
    3. Rest Parameters (...args): Recibir un número indefinido de argumentos como un array.
    // Opcional y Por defecto
function buildName(firstName: string, lastName: string = "Doe", middleName?: string) {
    if (middleName) return `${firstName} ${middleName} ${lastName}`;
    return `${firstName} ${lastName}`;
}

// Rest Parameters
function sumAll(...numbers: number[]): number {
    return numbers.reduce((total, n) => total + n, 0);
}

console.log(sumAll(1, 2, 3, 4, 5)); // 15

    Operadores Rest y Spread (...)

    Como vimos en el tema de JS, funcionan igual, pero ahora tipados.

const team2: string[] = ['Charlie', 'Dave'];

// Spread: combinando arrays

// Spread en objetos (muy usado en backend para DTOs)

const userFull = { ...userBasic, role: 'Admin', active: true };

    6. Clases y Programación Orientada a Objetos

    TypeScript convierte el sistema de prototipos de JS en un sistema de clases clásico robusto, similar a Java o C#.

    Clases: Propiedades, Métodos y Modificadores

    Los modificadores controlan quién puede ver o tocar las propiedades.

    1. Public (defecto): Accesible desde cualquier lugar.
    2. Private: Solo accesible desde DENTRO de la clase.
    3. Protected: Accesible desde la clase y sus hijas (herencia).
    4. Readonly: Solo se puede asignar en la declaración o en el constructor. No se modifica después.
    class CuentaBancaria {
    // Propiedades
    public titular: string;
    private saldo: number; // Nadie puede tocar el saldo directamente desde fuera

    constructor(titular: string, saldoInicial: number) {
        this.titular = titular;
        this.saldo = saldoInicial;
    }

    public depositar(cantidad: number): void {
        this.saldo += cantidad;
        this.auditoria();
    }

    // Método privado, solo para uso interno
    private auditoria(): void {
        console.log(`Saldo actual modificado: ${this.saldo}`);
    }
}

// cuenta.auditoria(); // Error: Property 'auditoria' is private.

    7. Genéricos (Generics)

    Los genéricos son como variables para tipos. Permiten crear componentes reutilizables que funcionan con varios tipos en lugar de uno solo, sin perder la seguridad de tipos (sin usar any).

    Imagina una caja. Si la haces a medida para guardar manzanas, no puedes guardar peras. Si la haces "para cualquier cosa" (any), pierdes el rastro de lo que hay dentro. Con genéricos, le pones una etiqueta a la caja: "Caja de T". Cuando metes manzanas, se convierte en "Caja de Manzanas".

    Genéricos en Funciones

    Usamos <T> (o cualquier letra) para capturar el tipo.

    // Sin genéricos: perdemos información o duplicamos código
function identityNumber(arg: number): number { return arg; }
function identityString(arg: string): string { return arg; }

// Con genéricos
function identity<T>(arg: T): T {
  return arg;
}

// Uso explícito
const n = identity<number>(5); 
// Uso por inferencia (TS detecta que es string)
const s = identity("Hola"); // s es tipo string automáticamente

    Constraints (Restricciones)

    A veces queremos que el genérico sea flexible, pero no tanto. Usamos extends para limitar.

    // Queremos acceder a .length, pero no todo tipo tiene .length
interface Lengthy {
  length: number;
}

function logLength<T extends Lengthy>(arg: T): T {
  console.log(arg.length);
  return arg;
}

logLength("hola"); // OK (string tiene length)
logLength([1, 2]); // OK (array tiene length)
// logLength(100); // Error: number no tiene length

    9. Asincronía en TypeScript

    • Modo Síncrono (Bloqueante): Entra un cliente y pide una tostada. Tú vas a la cocina, pones el pan, esperas 2 minutos mirando fijamente la tostadora sin moverte, sacas la tostada, se la das y solo entonces atiendes al siguiente cliente. Resultado: La cola llega a la calle y los clientes se van furiosos.
    • Modo Asíncrono (No Bloqueante): Entra un cliente, pones el pan en la tostadora y, mientras se hace, atiendes al siguiente. Cuando la tostadora hace "¡Ding!", vuelves a ella.

    En programación, la asincronía nos permite iniciar tareas largas (leer bases de datos, descargar archivos, temporizadores) sin congelar la aplicación.

    Modelo Síncrono

    En el modelo síncrono, las tareas se ejecutan de forma secuencial y se tiene que esperar a terminar la anterior para poder ejecutar la presente.

    Veamos qué pasa si simulamos una tarea lenta en modo síncrono.

    // Imaginad que la siguiente función tarda 5 segundos en la vida real
function tareaPesada() {
    console.log("2. Haciendo tarea pesada...");
    // ...bloqueo mental...
}


console.log("1. Inicio del programa");

tareaPesada();

console.log("3. Fin del programa");

// SALIDA:
// 1. Inicio del programa
// 2. Haciendo tarea pesada...
// (Esperamos...)
// 3. Fin del programa

    En un contexto de una web, si esa tarea pesada es "conectar al servidor", el usuario no podría ni hacer scroll mientras tanto.

    Modelo Asíncrono

    1. La Era Antigua: Callbacks (Llamadas de vuelta)

    Antes de que existieran las Promesas, la única forma de manejar la asincronía en JavaScript/TypeScript era pasando funciones como parámetros. Esto se llama Callback.

    ¿Qué es un Callback?

    Es una función que tú (programador) le pasas a otra función y le dices: "Toma esta función. No la ejecutes ahora. Ejecútala tú cuando hayas terminado tu trabajo".

    Es como dejarle tu número de teléfono al mecánico. No te quedas en el taller esperando; te vas, y él te llama (hace el "callback") cuando el coche está listo.

    Sintaxis Básica: Callbacks

    // Definición de la función que acepta un callback
function nombreFuncion(parametro: tipo, callback: (error?: Error, resultado?: tipo) => void): void {
    // 1. Hacemos la tarea lenta...
    // 2. Si falla: llamamos a callback(error, null)
    // 3. Si funciona: llamamos a callback(null, resultado)
}

// Uso
nombreFuncion(dato, (error, resultado) => {
    if (error) {
        // Manejar error
    } else {
        // Usar resultado
    }
});

    Ejemplo Práctico: Descargar un Archivo (Simulado)

    Vamos a simular la descarga de un archivo. Fíjate en cómo pasamos la función alTerminar.

    // Definimos cómo luce la función callback (acepta un error o un string)
type MiCallback = (error: string | null, archivo?: string) => void;

function descargarArchivo(url: string, alTerminar: MiCallback): void {
    console.log(`📡 Iniciando descarga de: ${url}...`);

    // setTimeout simula el retardo de la red (2 segundos)
    setTimeout(() => {
        // Simulamos que a veces falla (si la URL contiene "error")
        const haFallado = url.includes("error");

        if (haFallado) {
            // LLAMAMOS AL CALLBACK CON UN ERROR
            alTerminar("❌ Error 404: Archivo no encontrado", undefined);
        } else {
            // LLAMAMOS AL CALLBACK CON ÉXITO (null en el error)
            const archivoDescargado = "Datos del archivo: [CONTENIDO BINARIO]";
            alTerminar(null, archivoDescargado);
        }
    }, 2000);
}

// --- EJECUCIÓN ---

// Pasamos una función anónima como segundo parámetro
descargarArchivo("http://google.com/imagen.jpg", (error, archivo) => {
    if (error) {
        console.error("Maldición, algo falló: " + error);
    } else {
        console.log("¡Éxito! " + archivo);
        // ¿Y si ahora quiero procesar el archivo?
        // Tendría que meter OTRO callback aquí dentro...
    }
});

console.log("2. Haciendo otras cosas mientras descarga...");

    El Problema: "Callback Hell" (El Infierno de los Callbacks)

    ¿Qué pasa si tienes que hacer 3 cosas seguidas? 1. Descargar, 2. Descomprimir, 3. Guardar. El código empieza a crecer hacia la derecha en forma de pirámide.

    descargar((err, archivo) => {
    if (err) return manejarError(err);
    descomprimir(archivo, (err, datos) => {
        if (err) return manejarError(err);
        guardar(datos, (err, exito) => {
            if (err) return manejarError(err);
            console.log("¡Todo terminado!");
        });
    });
});
    Esto es ilegible, difícil de depurar y propenso a errores. Necesitábamos algo mejor.


    2. La Era Media: Promesas (Promises)

    Para solucionar el desastre de los callbacks, llegaron las Promesas (ES6 / 2015). Una promesa es un objeto que representa el eventual resultado (o fallo) de una operación asíncrona.

    ¿Qué es una Promesa?

    Imagina que pides una hamburguesa. El cajero te da un Ticket. * Ese ticket es la Promesa. * El ticket está en estado Pendiente (Pending) mientras cocinan. * Si te dan la hamburguesa, el ticket pasa a estado Resuelto (Resolved). * Si se quema la cocina, el ticket pasa a estado Rechazado (Rejected).

    Lo revolucionario es que el Ticket es un objeto que puedes guardar en una variable y pasarlo por ahí.

    Sintaxis Básica: Promesas

    Productor (Crear la promesa): 

    const miPromesa = new Promise<TipoDato>((resolve, reject) => {
    // Código asíncrono
    // Si bien -> resolve(dato);
    // Si mal  -> reject(error);
});

    Consumidor (Usar la promesa): 

    miPromesa
    .then((dato) => {
        // Se ejecuta si resolve()
    })
    .catch((error) => {
        // Se ejecuta si reject()
    })
    .finally(() => {
        // Se ejecuta siempre
    });

    Ejemplo Práctico: Descargar con Promesas

    Vamos a reescribir la función de descarga. Ya no acepta callbacks, ahora devuelve un objeto Promise.

    function descargarPromesa(url: string): Promise<string> {
    // Retornamos inmediatamente el objeto "Ticket" (Promesa)
    return new Promise((resolve, reject) => {
        console.log(`📡 Buscando ${url}...`);

        setTimeout(() => {
            const haFallado = url.includes("error");

            if (haFallado) {
                // Rechazamos el ticket
                reject("❌ Fallo de red");
            } else {
                // Sellamos el ticket como válido
                resolve("Contenido del archivo descargado");
            }
        }, 2000);
    });
}

// --- EJECUCIÓN (Encadenamiento .then) ---

console.log("1. Pidiendo archivo...");

descargarPromesa("http://miweb.com/datos.json")
    .then((contenido) => {
        console.log("2. Descarga completada: " + contenido);
        // Aquí podríamos devolver otra promesa para encadenar
        return "Archivo procesado";
    })
    .then((mensajeProcesado) => {
        console.log("3. " + mensajeProcesado);
    })
    .catch((error) => {
        // Este catch captura errores de CUALQUIERA de los pasos anteriores
        console.error("💥 Error en el proceso: " + error);
    });

console.log("4. Yo sigo a lo mío");

    Mejora: Hemos aplanado la pirámide. El código se lee de arriba a abajo.


    3. La Era Moderna: Async / Await

    Aunque las Promesas son geniales, usar muchos .then() puede ser confuso visualmente. En 2017, JavaScript introdujo Async/Await.

    No es una tecnología nueva. Es "azúcar sintáctico" sobre las Promesas. Por debajo siguen siendo promesas, pero escribimos el código como si fuera síncrono (línea a línea), lo cual es mucho más fácil de leer para nuestro cerebro humano.

    ¿Qué es Async/Await?

    • async: Palabra clave que se pone delante de una función. Convierte la función en una que siempre devuelve una Promesa.
    • await: Palabra clave que solo se usa dentro de funciones async. Le dice al intérprete: "Detente en esta línea. No continúes ejecutando esta función hasta que la promesa de la derecha se resuelva (o falle). Mientras esperas, deja que el resto del programa siga funcionando"

    Sintaxis Básica: Async/Await

    // 1. Declarar la función contenedora como async
async function procesoPrincipal() {
    try {
        // 2. Usar await para esperar el resultado "desempaquetado"
        const resultado = await funcionQueDevuelvePromesa();
        console.log(resultado);

        // 3. Manejo de errores tradicional con try-catch
    } catch (error) {
        console.error(error);
    }
}

    Ejemplo Práctico: El Flujo Completo

    Vamos a usar la misma función descargarPromesa del apartado anterior (recuerda, await consume Promesas), pero la vamos a usar con estilo moderno.

    // Función auxiliar que simula proceso (devuelve Promesa)
function procesarDatos(datos: string): Promise<string> {
    return new Promise(resolve => 
        setTimeout(() => resolve("Procesado: " + datos.toUpperCase()), 1000)
    );
}

// --- EJECUCIÓN CON ASYNC/AWAIT ---

async function ejecutarTareaCompleja() {
    console.log("🟢 Inicio de la tarea asíncrona");

    try {
        // PASO 1: Descargar
        // El código se "pausa" aquí 2 segundos, pero la app no se congela.
        const archivo = await descargarPromesa("http://datos.com");
        console.log("✅ Archivo recibido: " + archivo);

        // PASO 2: Procesar (depende del anterior)
        // El código se "pausa" aquí 1 segundo más.
        const resultadoFinal = await procesarDatos(archivo);
        console.log("🧠 Resultado final: " + resultadoFinal);

    } catch (error) {
        // Si falla la descarga O el proceso, saltamos aquí directamente
        console.error("🔴 Algo salió mal: " + error);
    } finally {
        console.log("🏁 Operación terminada (con éxito o error)");
    }
}

// Llamamos a la función
ejecutarTareaCompleja();
console.log("🟡 Esto se imprime ANTES de que termine la descarga");

    ¿Por qué Async/Await es el rey?

    1. Lectura: Parece código Java o C# síncrono.
    2. Debugging: Es mucho más fácil poner puntos de ruptura (breakpoints) y ver paso a paso qué ocurre.
    3. Errores: Usar try/catch es el estándar para manejar errores en programación, unificando conceptos.

    10. Tipos avanzados útiles en Backend

    Estas herramientas son el "navaja suiza" para manipular tipos, especialmente útil cuando trabajas con Bases de Datos y DTOs (Data Transfer Objects).

    Utility Types

    TypeScript trae tipos que transforman otros tipos.

    1. Partial<T>: Hace todas las propiedades opcionales. (Útil para PATCH updates).
    2. Required<T>: Hace todo obligatorio.
    3. Pick<T, Keys>: Selecciona solo algunas propiedades.
    4. Omit<T, Keys>: Quita propiedades específicas.
    5. Record<Key, Value>: Crea un objeto mapa.
    interface UserDB {
  id: number;
  name: string;
  email: string;
  createdAt: Date;
}

// DTO para crear usuario (no necesitamos ID ni fecha, se generan solos)
type CreateUserDTO = Omit<UserDB, 'id' | 'createdAt'>;

// DTO para actualizar (todo es opcional, solo mando lo que cambio)
type UpdateUserDTO = Partial<CreateUserDTO>;

// Un objeto simple ID -> Nombre
type UserMap = Record<number, string>;

    Tipado de configuraciones (process.env)

    En Node, process.env devuelve string | undefined. Esto es molesto. Podemos extender el tipado.

    // global.d.ts
namespace NodeJS {
  interface ProcessEnv {
    PORT: string;
    DB_URI: string;
    NODE_ENV: 'development' | 'production';
  }
}

// Ahora TS autocompleta
const port = process.env.PORT;

    Operaciones con colecciones

    Las más destacadas son:

    1. forEach: Este método ejecuta una función proporcionada una vez por cada elemento de la colección.
    const numbers = [1, 2, 3, 4, 5];

numbers.forEach((number) => {
  console.log(number);
});
    1. map: Este método crea un nuevo array con los resultados de aplicar una función a cada elemento de la colección.
    const numbers = [1, 2, 3, 4, 5];

const doubledNumbers = numbers.map((number) => {
  return number * 2;
});

console.log(doubledNumbers); // Output: [2, 4, 6, 8, 10]
    1. filter: Este método crea un nuevo array con todos los elementos que pasan una prueba (función) proporcionada.
    const numbers = [1, 2, 3, 4, 5];

const evenNumbers = numbers.filter((number) => {
  return number % 2 === 0;
});

console.log(evenNumbers); // Output: [2, 4]
    1. reduce: Este método aplica una función a un acumulador y a cada elemento de la colección (de izquierda a derecha) para reducirlo a un solo valor.
    const numbers = [1, 2, 3, 4, 5];

const sum = numbers.reduce((accumulator, number) => {
  return accumulator + number;
}, 0);

console.log(sum); // Output: 15
    1. find: Este método devuelve el primer elemento de la colección que cumple con la condición proporcionada.
    const numbers = [1, 2, 3, 4, 5];

const foundNumber = numbers.find((number) => {
  return number > 3;
});

console.log(foundNumber); // Output: 4
    1. some: Este método verifica si al menos un elemento de la colección cumple con la condición proporcionada.
    const numbers = [1, 2, 3, 4, 5];

const hasEvenNumber = numbers.some((number) => {
  return number % 2 === 0;
});

console.log(hasEvenNumber); // Output: true
    1. every: Este método verifica si todos los elementos de la colección cumplen con la condición proporcionada.
    const numbers = [1, 2, 3, 4, 5];

const allPositive = numbers.every((number) => {
  return number > 0;
});

console.log(allPositive); // Output: true
