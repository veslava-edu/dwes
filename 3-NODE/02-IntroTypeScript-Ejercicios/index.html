    Tema 2: Ejercicios TS con Entrada de Datos

    Para realizar estos ejercicios, necesitarás una función auxiliar que permita leer datos desde la consola de forma síncrona (similar a scanf en C o input en Python), ya que readline de Node.js es asíncrono por defecto y puede complicar el aprendizaje inicial.

    Copie el siguiente bloque de código al inicio de cada solución para poder usar la función prompt:

    import * as fs from 'fs';

// Función para leer entrada de usuario de forma síncrona
// `prompt` escribe una pregunta en stdout y lee la respuesta desde stdin
// utilizando operaciones de bajo nivel de `fs`.
// - `fs.writeSync(1, Buffer.from(question, 'utf8'))`: escribe el texto en el file descriptor 1 (stdout).
// - Se crea un `Buffer` de 1024 bytes para recibir la entrada del usuario.
// - `fs.readSync(0, buf, 0, 1024, null)`: lee desde el file descriptor 0 (stdin)
//   y rellena el buffer; devuelve la cantidad de bytes leídos.
// - Finalmente se convierte la porción leída del buffer a string UTF-8,
//   se eliminan espacios alrededor con `trim()` y se devuelve la respuesta.
function prompt(question: string): string {
    fs.writeSync(1, Buffer.from(question, 'utf8'));
    const buf = Buffer.alloc(1024);
    const bytes = fs.readSync(0, buf, 0, 1024, null);
    return buf.toString('utf8', 0, bytes).trim();
}

    Ejercicios de Consolidación

    1) El Analizador Químico (Arrays, Tuples y Enums) | Nivel: Fácil

    Objetivo

    Practicar la definición de tipos estrictos usando Enums para valores limitados, Tuplas para estructuras de datos heterogéneas fijas y Arrays para colecciones.

    Setup Inicial

    Crea un archivo analizador.ts e incluye la función prompt.

    Tarea a realizar

    Estás programando el software para un laboratorio. Necesitas registrar experimentos realizados durante el día. Cada experimento consta del tipo de elemento analizado, su peso exacto y un código de seguridad.
    1. Define un Enum llamado ElementType con los valores: WATER, EARTH, FIRE, AIR.
    2. Define un tipo Tuple llamado ExperimentRecord. Debe contener exactamente:
    * Índice 0: El elemento (ElementType).
    * Índice 1: Cantidad en gramos (number).
    * Índice 2: Si es estable (boolean).
    3. Crea un array vacío tipado para almacenar estos registros.
    4. Pregunta al usuario: "¿Cuántos experimentos vas a registrar?".
    5. Usa un bucle for para pedir los datos de cada uno.
    * Nota: Al leer el elemento (string), deberás convertirlo o asignarlo al Enum.
    6. Al finalizar, recorre el array e imprime un informe de cada experimento.
    7. Usa parseInt( ), parseFloat( ), variable.toLowerCase() si necesario.

    Flujo del Programa:

    Pregunta al usuario cuántos experimentos quiere registrar. 
Usa un bucle para pedir los datos de cada experimento:
Pide el elemento (el usuario escribirá "WATER", "FIRE", etc.). Convierte el string al Enum correspondiente.
Pide la cantidad (número).
Pide si es estable (el usuario escribirá "si" o "no").
Guarda cada tupla en el array.
Al final, recorre el array e imprime un informe: "Experimento [X]: [Elemento] - [Cantidad]g - [Estable/Inestable]".

    Aplicación en el Mundo Real

    Las tuplas son ideales para filas de bases de datos o registros CSV donde la posición del dato indica qué es (Columna 1: Tipo, Columna 2: Valor), ahorrando la sobrecarga de crear un objeto completo con claves si no es necesario.

    Ejercicios de Refuerzo

    2) Registro de Pacientes (Nulabilidad y Opcionales) | Nivel: Medio

    Objetivo

    Manejar correctamente la ausencia de datos utilizando propiedades opcionales (?) y el operador Nullish Coalescing (??).
    Contexto: Estás creando un sistema de admisión para una clínica. No todos los pacientes quieren dar todos sus datos, por lo que el sistema debe ser flexible y robusto ante la falta de información.

    Setup Inicial

    Crea un archivo pacientes.ts e incluye la función prompt.

    Tarea a realizar

    Sistema de admisión de una clínica donde no todos los datos son obligatorios.
    1. Crea una Interface PatientProfile con:
    * id: number (obligatorio).
    * name: string (obligatorio).
    * age: number (opcional).
    * allergies: string (opcional).
    2. Pide los datos al usuario.
    * Para age y allergies, si el usuario pulsa ENTER sin escribir nada, asigna undefined.
    3. Crea el objeto paciente.
    4. Imprime la ficha técnica.
    * Usa ?? para que si la edad no existe, muestre "Desconocida".
    * Usa ?? para que si no hay alergias, muestre "Ninguna".
    * (Opcional) Intenta usar Optional Chaining (?.) si decides meter los datos de contacto en un objeto anidado (ej: contact?.phone).

    Flujo del Programa:

    Solicita el ID y el Nombre (si el usuario lo deja vacío, debes obligarle a escribirlo o lanzar error).
Solicita la Edad (permite que el usuario pulse Enter sin escribir nada).
Solicita Alergias separadas por comas (permite que el usuario pulse Enter si no tiene).
Genera un objeto paciente con esos datos.
Imprime la Ficha del Paciente:
Nombre: (El introducido).
Edad: Si no introdujo nada, debe mostrar "Edad desconocida" o "0" usando ??.
Alergias: Si no introdujo nada, debe mostrar "Sin alergias conocidas".

    Aplicación en el Mundo Real

    En formularios web, el usuario a menudo deja campos vacíos. El backend debe distinguir entre "el usuario escribió 0" (edad válida) y "el usuario no escribió nada" (undefined/null). ?? es vital para no tratar el 0 como falso.

    3) Calculadora de Envíos (Funciones y Rest Params) | Nivel: Medio

    Objetivo

    Implementar funciones con tipado explícito de argumentos y retorno, utilizando Rest Parameters (...args) para listas de longitud variable.

    Setup Inicial

    Crea un archivo logistica.ts e incluye la función prompt.

    Tarea a realizar

    Calculadora de costes logísticos con tarifas extra dinámicas.<br/>
1.  Crea una función `calculateShippingCost`.<br/>
2.  Argumentos:<br/>
    *   `weight` (number).<br/>
    *   `distance` (number).<br/>
    *   `...extras` (number[]).<br/>
3.  Debe devolver `number`. Fórmula: `(peso * distancia * 0.1) + suma_de_extras`.<br/>
4.  En el `main`:<br/>
    *   Pide peso y distancia.<br/>
    *   Pregunta cuántos cargos extra aplicar (Aduanas, Urgencia, Festivo...).<br/>
    *   Lee los cargos en un bucle y guárdalos en un array.<br/>
    *   Llama a la función usando el operador **spread** (`...`) para pasar el array como argumentos individuales, o pásalos según permita tu lógica.<br/>

    Flujo del Programa:

    Pide el peso del paquete (kg).
Pide la distancia (km).
Pregunta: "¿Cuántos cargos extra quieres añadir?".
En base a ese número, pide los cargos uno a uno.
Llama a la función pasando los extras mediante el operador spread (si los guardaste en un array) o directamente si los pasas uno a uno <br/>
(aunque con prompt lo ideal es guardarlos en array y pasarlos con ...).<br/>    
Muestra el coste total formateado (ej: "50.00 €").

    Aplicación en el Mundo Real

    Los Rest Parameters son fundamentales para crear funciones de utilidad (como loggers o calculadoras) que aceptan un número infinito de argumentos sin obligar a crear un array explícito cada vez.

    Ejercicios de Ampliación

    4) Sistema Domótico (POO, Herencia e Interfaces) | Nivel: Alto

    Objetivo

    Estructurar una aplicación usando Programación Orientada a Objetos, Clases Abstractas e Interfaces, interactuando con el usuario mediante un menú.
    Contexto: Vamos a domotizar una casa. Necesitamos modelar diferentes aparatos que comparten características pero funcionan diferente.

    Setup Inicial

    Crea un archivo domotica.ts e incluye la función prompt.

    Tarea a realizar

    1.  Define una **Interface** `Device` con: `name` (string), `turnOn()` y `turnOff()`.<br/>
2.  Crea una **Clase Abstracta** `Appliance` que implemente `Device`.<br/>
    *   Propiedad `protected isOn` (boolean).<br/>
    *   Constructor que reciba el nombre.<br/>
    *   Implementa `turnOn`/`turnOff` cambiando el estado e imprimiendo un mensaje.<br/>
3.  Crea una **Clase Hija** `Television` que herede de `Appliance`.<br/>
    *   Propiedad `volume` (number).<br/>
    *   Método `volumeUp()`: Sube el volumen e imprime el nivel. Solo funciona si la TV está encendida (comprobar `isOn`).<br/>
    *   Sobrescribe `turnOn()` para añadir un mensaje personalizado ("Logo de Samsung...").<br/>
4.  En el `main`:<br/>
    *   Instancia una TV preguntando el nombre.<br/>
    *   Crea un bucle `while(true)` con un menú: 1.Encender, 2.Apagar, 3.Volumen, 4.Salir.<br/>

    Flujo del Programa:

    Pide al usuario el nombre para su nueva Televisión.
Instancia el objeto Television.
Crea un pequeño menú interactivo (bucle while):
"1. Encender" -> Llama a turnOn().
"2. Apagar" -> Llama a turnOff().
"3. Subir Volumen" -> Llama a volumeUp().
"4. Salir".
El programa termina cuando el usuario elige la opción 4.

    Aplicación en el Mundo Real

    Este patrón es la base de frameworks backend como NestJS. Las interfaces definen contratos, las clases abstractas dan funcionalidad base y las clases concretas implementan la lógica de negocio específica.
